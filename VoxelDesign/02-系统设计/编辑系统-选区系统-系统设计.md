## 1. 系统上下文

### 1.1 系统边界

**选区系统负责**：
- 提供玩家定义选区的能力
- 支持多种选区定义方式（单点、几何、笔刷、魔棒）
- 管理当前选区状态（运行时数据）
- 提供布尔运算模式（新选、加选、减选、交集）
- 提供选区后的操作接口（移动、复制、删除、保存模板）

**选区系统不负责**：
- 具体选区工具的实现细节（由工具类实现）
- 选区的UI渲染（由VisualComponent处理）
- 选区后的编辑执行（由BlockWorldSubsystem负责）
- 模板的持久化存储（由模板系统负责）

### 1.2 外部依赖

**依赖的系统**：
- **VoxelBlockWorldSubsystem**：读取体素数据
- **VoxelControllerVisualUIComponent**：显示选区高亮
- **模板系统**：提供"保存为模板"操作

**被依赖的系统**：
- **模板系统**：使用选区数据采集模板
- **编辑执行系统**：使用选区数据进行编辑
- **阵列系统**：基于选区进行阵列操作

### 1.3 输入输出

**输入**：
- 玩家的选择操作（鼠标拖拽、点击等）
- Gizmo交互数据
- 选择参数（形状、类型等）

**输出**：
- 选区数据（`FVoxelSelection`）
  - `TMap<FIntVector, FGameplayTag>` - 位置和原始类型
  - `FAreaCoverageFragment` - 包围盒
  - `FDateTime` - 创建和修改时间
- 选区操作结果（`FVoxelEditModification`、模板资产等）

## 2. 核心概念

### 2.1 基础概念

**选区（Selection）**
- 定义：当前选中的体素位置和原始类型
- 类型：`FVoxelSelection`（运行时数据结构）
- 组成：
  - `TMap<FIntVector, FGameplayTag>` - 选区体素（位置→类型）
  - `FAreaCoverageFragment` - 包围盒
  - `FDateTime` - 创建和修改时间
- 特点：运行时数据，手动清空前持久保存
- 用途：所有编辑操作的基础

**选区工具（SelectionTool）**
- 定义：实现特定选区定义逻辑的工具类
- 类型：`UVoxelSelectionTool` 的派生类
- 分类：
  - 单点工具：点击单体素
  - 几何工具：盒、球、圆柱、多边形
  - 笔刷工具：涂抹轨迹
  - 魔棒工具：连通扩散
- 特点：基于布尔运算修改现有选区

### 2.2 组合概念

**布尔运算模式（BooleanMode）**
- 定义：新选区与旧选区的组合方式
- 类型：新选、加选（并集）、减选（差集）、交集
- 触发：Shift（加选）、Alt（减选）、Ctrl（新选）、Shift+Alt（交集）

**选区构建历史**
- 定义：选区是如何被构建的历史记录
- 组成：多次选区工具操作的序列
- 用途：撤销选区修改、理解选区来源

**操作工具分类**
- 直接操作：不需要预选区，操作后自动生成选区
  - 新增体素、几何体建造、蓝图放置
- 选区操作：需要预选区，对现有选区执行操作
  - 移动、复制/粘贴、删除、替换、填充
- **注意：保存模板不是工具，是按钮触发的操作**
  - 触发路径：UI按钮 → StateComponent → InteractComponent → TemplateManager

### 2.3 行为概念

**框选（BoxSelection）**
- 定义：通过两个点定义的包围盒选择体素
- 输入：起点、终点
- 过程：计算包围盒 → 遍历体素 → 过滤

**魔棒选择（MagicWandSelection）**
- 定义：从点击位置连通扩散，选择相同类型的体素
- 输入：起始体素位置
- 过程：连通性检测 → 类型匹配 → 扩散遍历

**多边形选择（PolygonSelection）**
- 定义：通过多边形顶点定义区域选择体素
- 输入：多个顶点位置
- 过程：构建多边形 → 点在多边形内检测

**反选（InvertSelection）**
- 定义：反转选择状态（选中→未选中，未选中→选中）
- 输入：当前选择集
- 过程：遍历包围盒 → 取补集

### 2.4 概念关系

```
选区数据（FVoxelSelection）
├─ TMap<FIntVector, FGameplayTag> - 选区体素
└─ FAreaCoverageFragment - 包围盒
    ↑ 被修改
    │
选区工具层
├─ 单点工具: 点击单体素
├─ 几何工具: 参数化形状
├─ 笔刷工具: 涂抹轨迹
└─ 魔棒工具: 连通扩散
    │ 操作
    ↓
操作工具层
├─ 直接操作: 新增体素、几何体、蓝图
└─ 选区操作: 移动、复制、删除、替换、填充、模板
```

## 3. 设计原则

### 3.1 架构原则

**三分离架构**
- 选区数据独立：不依附于任何工具
- 选区工具：修改选区的手段
- 操作工具：对选区执行动作
- 清晰的职责边界

**持久化**
- 选区在手动清空前始终保存
- 切换任何工具都不自动清空选区
- 只能通过明确的清空操作删除

**统一抽象**
- 所有选区工具提供相同的交互模式
- 统一的布尔运算语义
- 统一的视觉反馈

### 3.2 接口设计原则

**统一抽象**
- 所有选择工具实现相同的接口
- 返回统一的数据结构（选择集）
- 便于上层系统统一处理

**最小知识**
- 选择工具不关心选择后的用途
- 只返回选中结果，不执行业务逻辑
- 解耦选择和编辑

### 3.3 数据管理原则

**坐标规范**
- 使用世界坐标索引（FIntVector）
- 不转换为世界坐标位置
- 遵循项目编码规范

**数据完整性**
- TMap<FIntVector, FGameplayTag>同时存储位置和原始类型
- 支持编辑操作和统计
- 可直接转换为FVoxelEditModification

**即时计算**
- 选区结果即时计算，不缓存
- 包围盒根据选区动态计算
- 保持数据一致性

**状态无关**
- 选区工具不维护状态
- 每次选区是独立的操作
- 状态由FVoxelSelection对象管理

## 4. 系统约束

### 4.1 技术约束

**坐标系统**
- 必须使用 INDEX（`FIntVector`）
- 不能在工具内部转换为 POSITION
- 遵循编码规范

**数据结构**
- 选区使用 `TMap<FIntVector, FGameplayTag>`（位置→原始类型）
- 自动去重（TMap特性）
- 包围盒使用 `FAreaCoverageFragment`（现有结构）

**继承体系**
- 必须继承 `UVoxelToolBase`
- 必须继承 `UVoxelSelectionTool`
- 遵循工具系统的注册机制

### 4.2 性能约束

**选择范围**
- 单次选择不超过 10,000 个体素
- 遍历性能需要优化（使用区块索引）
- UI 响应时间 < 100ms

**内存占用**
- 选区数据不持久化到磁盘
- 不缓存历史选区结果
- 释放后立即清理

**选区有效性**
- 空选区不允许执行操作
- 必须有明确的边界检测
- 必须支持取消操作

### 4.3 业务约束

**选区有效性**
- 空选区不允许执行操作
- 必须有明确的边界检测
- 必须支持取消操作

**兼容性**
- 必须支持现有编辑流程
- 必须支持撤销/重做
- 必须支持批量编辑
- 必须与模板系统兼容（FVoxelEditModification转换）

## 5. 设计目标

### 5.1 功能目标

**核心功能**
1. 支持四种选区工具（单点、几何、笔刷、魔棒）
2. 支持布尔运算（新选、加选、减选、交集）
3. 提供选区后的基础操作（移动、复制、删除）
4. 支持选区内填充（填充、替换、删除）
5. 支持保存选区为模板

**扩展功能**
1. 支持选区构建历史（查看选区是如何被构建的）
2. 支持选区统计信息（数量、包围盒、材质分布）
3. 支持撤销选区修改
4. 支持选区预览（实时高亮、半透明显示）

### 5.2 质量目标

**可维护性**
- 选择工具逻辑清晰
- 易于新增选择方式
- 接口定义明确

**可测试性**
- 每个工具可独立测试
- 选择结果可验证
- 边界条件清晰

### 5.3 用户体验目标

**易用性**
- 操作直观，符合习惯
- 反馈及时，选择框实时显示
- 错误提示清晰

**一致性**
- 所有选择方式交互一致
- 与编辑系统其他部分风格统一
- 符合UE编辑器操作习惯

## 6. 与其他子系统的关系

### 6.1 与模板系统的关系

```
选区系统
  ↓ StateComponent提供
选区数据（FVoxelSelection）
  ↓ InteractComponent调用
模板系统（TemplateManager）
  ↓ 转换
模板资产（UVoxelBuildingTemplateAsset）
```

**职责划分**：
- 选区系统：提供选区定义功能
- 模板系统：将选区转换为持久化资产
- 触发方式：UI按钮（非工具选择）

**数据流**：
1. 玩家点击"保存为模板"按钮
2. StateComponent 提供选区数据（TMap<FIntVector, FGameplayTag>）
3. InteractComponent 调用 TemplateManager::CreateFromSelection()
4. 模板系统构建调色板（排除 `Voxel.Block.Scaffolding.*` 层级）
5. 转换为相对坐标（底面中心为原点）和调色板索引
6. 自动生成元数据（统计、作者、时间）
7. 保存为 .vxbp 文件到 Saved/VoxelTemplates/ 目录

### 6.2 与预览系统的关系

```
选区系统
  ↓ 提供
选区数据（包围盒 + 体素位置）
  ↓
预览系统
  ↓ 使用
显示选区高亮和包围盒
```

**职责划分**：
- 选区系统：计算选区范围和包围盒
- 预览系统：显示可视化的选区反馈（高亮、边框）

### 6.3 与编辑执行系统的关系

```
选区系统
  ↓ 提供
选区数据（FVoxelSelection）
  ↓
转换为 FVoxelEditModification
  ↓
BlockWorldSubsystem
  ↓ 使用
执行编辑操作
```

**职责划分**：
- 选区系统：提供选区数据
- 编辑执行系统：将选区转换为FVoxelEditModification并执行

**数据转换**：
```cpp
// 选区 → 编辑修改
FVoxelEditModification Modification;
for (const auto& Pair : Selection.SelectedVoxels)
{
    Modification.Add(Pair.Key, Pair.Value);
}
Modification.SetEditMode(EVoxelControllerEditState::Replace);
```
