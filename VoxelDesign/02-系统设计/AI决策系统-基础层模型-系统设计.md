## 1. 定位

基础层 = NPC 的慢变身份数据：**能力（七围）/ 倾向维度（9 维）/ 特质 / 身份轴（种族/职业/性别）**。生成时一次 roll 定 + **常驻慢速回写**（v1.4 定案：全年龄可成长，DF 式极慢——干活/学习/重大经历回写七围；9 维塑变仍归记忆塑变唯一通道，见《AI决策系统-记忆模型-系统设计.md》；职业轨/技能树/熟练度可成长）。

三层关系：基础层（我是谁）→ 需求与状态层（我现在多缺/多糟）→ 统一效应模型（一切效果的唯一形态）。记忆层横跨三者（事件改变数值、写入关联、塑变倾向）。

## 2. 能力：七围（定案）

以 `Config/DefaultGameplayTags.ini:18-24` 为准，Primary 属性为 **7 个**：

| 属性 | Tag |
|------|-----|
| 力量 Strength / 敏捷 Agility / 体质 Constitution | `Creature.Attribute.Primary.*` |
| 智力 Intelligence / 感知 Perception / 魅力 Charisma / 精神 Spirit | 同上 |

- `CoreTags.h:182` 注释已由"基础六围"改口为七围
- 数值流（代码现状，`CreatureGeneratorUtils.cpp`）：生成时每个七围 roll ±2 进 `PersistentBasicValues` → 叠加 Race/Job/Traits 的 AttributeConfigs → `CachedBaseAttributes` → 全局公式表（`UGlobalAttributeFormulas`）→ `FinalAttributes`
- 派生公式消费七围：战斗衍生（Combat.Attack…）、经营衍生（Social.Loading…）、工种熟练度（旧 §11.4：每工种一条 `FDerivedAttributeDef`）
- **成长（v1.4 定案）**：全年龄可成长，常驻慢速回写通道；增速/软上限/年龄曲线/种族 GrowthScale 系数细则随成长模块
- 七围语义细则（尤其 Spirit 与 Intelligence 的分工、Perception 的消费点）：**待议**，随 M2/M5 模块讨论钉死

## 3. 倾向维度：9 维（全部定案）

### 3.1 统一结构（定案）

不设"性格维度"与"价值观"两套系统——所有个体倾向是**同一种数据**：连续双极轴，取值 [-50, +50]，统称倾向维度（`Creature.PersonalityDim.*`）。**每个维度产生的效果形态完全一样：都是对 NPC 各种行为的影响因子**（评分/概率/强度/评价的修饰输入）。维度之间只有消费点不同（哪个修饰器表读它），没有结构不同。

**入队标准（定案）**：每个维度必须能答出"它驱动哪个游戏系统的什么差异"——答不出的不配占维度槽。心理学/社会学概念只作参考，不作入队理由。

生成/存储/管线完全同构：种族与职业分布 + 个体噪声一次 roll 定；与七围同容器（`PersistentBasicValues`）；消费端按命名空间分支（`CreatureGeneratorUtils.cpp:682`）；种族模板 PersonalityModelPresets 通道沿用（三族已配 6 维，3 新维待编辑器补配）。

**铁律**：维度只作行为影响因子（修饰器表输入），**禁止进属性派生公式**（`UGlobalAttributeFormulas` 不得引用 `Creature.PersonalityDim.*`）。

**代码注册现状**：6 维 native 已注册（`CoreTags.cpp:106-112`）；3 新维（Patience/Fastidiousness/Altruism）已于 2026-09-14 同步注册 CoreTags；种族资产的 3 新维预设（PersonalityModelPresets）待在编辑器中补配。

### 3.2 维度清单（9 维，全部定案）

| 维度 | 定义 | 主要影响因子消费点 |
|------|------|------------------|
| Sociality 社交性 | 对陪伴与互动本身的需求强度 | Social 需求衰减、组团倾向、泡店偏好；关系：友情增益率/主动发起率 |
| Conscientiousness 尽责性 | 对职责/承诺/规程的自我要求 | 守时、工作品质、加班意愿、偷懒权重；吸收旧"懒惰/勤劳"特质，并承接落选"服从"轴的守规矩差异 |
| Exploratory 探索性 | 对新奇与未知的趋向 | 新店接受、品类扩展、换工作/搬家倾向 |
| SelfConsistency 自洽性 | **内部评价锚点强度（双极）**：高端=原则稳定（言行一致、记忆锚点衰减慢、抗传染、认同欲低）；低端=易变从众（认同欲外显：社交比较、名声敏感） | 传染/劝说易感性 ∝ (1−SC)、锚点衰减率、社交比较脉冲强度 |
| Competitiveness 竞争性 | 对输赢和相对排序的在意（想赢、记仇） | 讨价还价、仇恨锚点形成、升职/开店野心、被羞辱后的报复意愿；关系：Grudge 衰减常数减小 |
| Greed 贪婪性 | 对金钱得失的敏感度（怕损失） | 价格敏感/砍价、小费吝啬度、工资要价。**储蓄/耐心不归此轴**（归 Patience） |
| Patience 耐心↔急躁 | 及时行乐/等不得 ↔ 延迟满足/等得住 | 排队放弃阈值（排队系统个体差异源）；储蓄 vs 冲动消费；**目标层耐心源**（长期目标的坚持能力，如"攒钱开店"） |
| Fastidiousness 挑剔↔随和 | 好说话/期望带宽 ↔ 难伺候/期望带窄 | **期望带宽度的性格落点**（旧 §6.5"带宽即性格"）；满意度结算与差评率；关系：差评事件产生率。与 Greed 构成"价格×品质"四象限（精英客=低Greed高挑剔，穷凑合=高Greed低挑剔）——"推测客人"玩法的核心两轴 |
| Altruism 利他↔利己 | 只管自己 ↔ 仗义疏财 | 赠礼/帮工/撑腰/替班（职责外付出）、慷慨小费、对求助的响应；关系：正向互动增量加成——社交温度差异源 |

### 3.3 语义边界（定案，配置评审时守）

- 耐心（时间偏好：等不等得/攒不攒得）≠ Greed（金钱得失敏感）——储蓄/投资归耐心，砍价/小费归 Greed
- 挑剔（对**品质/服务**的要求）≠ Greed（对**价格**的敏感）——两轴独立构成消费决策四象限
- 利他（为**他人**付出）≠ Greed（对**自己**得失）——高 Greed 高利他 = 对自己抠对朋友大方
- 利他（对人好）≠ Sociality（要人陪）——高社交低利他 = 爱热闹但自私的派对动物
- 耐心（等得住）≠ Conscientiousness（自我纪律）——守时的好员工排队也可能急躁

### 3.4 落选轴记录（讨论中排除，附去向）

| 落选轴 | 排除理由 | 消费点去向 |
|--------|---------|-----------|
| 服从↔自主 | 用户裁定不收 | 员工守规矩/被管反应差异归 Conscientiousness；不足时以特质补充（如"倔强"） |
| 攻击↔克制 | 用户裁定不收 | 醉酒闹事概率挂 `Buff.Condition.Drunk` 配置（无性格差异）；记仇/报复归 Competitiveness |
| 勇敢↔怯懦 | 用户裁定不收 | 战/逃决策由七围战力评估衍生；战斗章（愿景附录）细化时再议 |
| 个人↔集体 | 消费点被 Sociality + Altruism + SelfConsistency 分完 | — |
| 平等↔等级 | 并入"服从"候选，随之一并落选 | — |
| 传统↔变革 | 与 Exploratory 撞车 | — |
| "崇尚对象"清单（财富/地位/冒险/友谊等） | 与现存维度及 ActivityWillingness 撞车率约 70%，作废 | — |

### 3.5 与特质的分工（定案）

程度问题 = 倾向维度（连续值，影响因子输入）；有无问题 = 特质（规则改写，见《AI决策系统-统一效应模型-系统设计.md》）。

## 4. 特质（归位统一效应模型）

特质 = **命名的永久修改器包 + 获得规则**（生成抽取 / 事件获得、PersonalityRequirements 门槛），不是独立效应通道。结构现状（`UCreatureTraitDefinition`）：AttributeConfigs + DerivedFormulas + DemandConfigs + PersonalityModelPresets + AcquisitionType + SpawnWeight。

**特质亲和（v1.4 定案，都修都补）**：
- 修：恢复 `TraitsRule.RequiredTags` 在生成 roll 里的评估（`CreatureGeneratorUtils.cpp:576-577` 注释掉的死代码），并把 `PersonalityRequirements` 接进候选过滤——得到"能不能出"（种族限定/性格门槛）
- 补：种族模板加 `TraitWeightModifiers: TMap<TraitTag, float>`，roll 点（`CreatureGeneratorUtils.cpp:579`）处 `权重 = SpawnWeight × 种族乘数`——得到"容不容易出"
- 现状普查：负向禁用池（Race/Job 的 ForbiddenTraitsPool + 特质互斥）在运转（`:551-558`）；正向门控与性格门槛是死代码；权重亲和不存在

**特质审计（待议）**：现有注册 5 个（Cautious/Genius/Strong/Weak/Divine）中，Cautious 是程度问题，与 Exploratory 维度撞车；Strong/Weak 需声明为"属性修正型特质"的合法边界。审计结论出来前不新增特质。

## 5. 身份轴（v1.4 定稿）

**基础身份字段：Race（种族/物种）/ Profession（出身职业）/ Gender（性别）/ Faction（阵营）。阵营在名册生成时确定，是与种族、职业同类的人员基础数据；其余身份感继续按下表化约：**

| 旧概念 | 去向 |
|--------|------|
| 阶层（SocialClass） | **化约删除**。购买力=NPC 钱包（待建，经济状态归需求与状态层）；期望中枢=职业基准+9维+噪声；服务门槛=声誉+价格带（编辑系统"阶级限制"同步改道）；"推测客人"线索=外观（财富外显，服装系统玩法出口）+认知档案+砍价行为。代码 `Creature.Identity.Class` 挂空声明（`CoreTags.cpp:94`）删除 |
| 战斗职业（CombatClass） | **删除声明**（`CoreTags.cpp:96`）。战斗职业=Profession 叶子（Guard/Mercenary/Bandit）；战斗能力=七围+装备+特质+熟练度，不看头衔 |
| 阵营（Faction） | **保留基础字段 `FactionTag`**：名册生成时确定，V1 与 Race / Profession 一样用于人员身份与客群统计；不因此启用关系度、派系 Rank / Attitude、阵营关系表或口碑传播。后续关系系统可在该身份之外增加态度与关系数值，不取代此基础字段 |

### 5.1 职业资格轨（定案）

职业的三个目的（用户定）：①加数值；②不同职业不同技能树；③经营证书门控——部分店/业务必须拥有符合职业等级要求的职工才能取得经营证书（双点医院式资质门控：**人才是开店的前置资源**）。

```
NPC 职业资格 = TMap<ProfessionTag, FProfessionState>
FProfessionState { Level: int, 表面Level: int, 技能树进度: 节点集合 }
```

- **兼职 = 多条职业轨**（DND 式）——"一个职业可以兼职"
- **出身** = 生成时 roll 的初始职业轨（配置包照旧应用：属性/需求；性格预设通道挂起未拍，见 §7-5）
- **等级到了 = 认证到位**：无审核流程、无认证机构；**假证 = 表面Level > 实际 Level**（唯一要"额外办"的证，黑暗玩法：资质查询看表面，干活露馅按实际，检查事件曝光风险）
- **经营证书 = 店铺层查询**：Employee 轨里存在 `Profession=X 且 表面Level≥N` 的员工 → 发证
- **当前职业 = 查询**：在哪上班（Employee 轨）就是什么职业；无轨 = 无业。V1 同一 NPC 同一时间最多一条有效雇佣记录；多雇主日程冲突与兼职排他规则归 M2 员工模块
- **三条数值轨边界**：七围=基础能力（能不能干粗活）；工种熟练度=单工种效率（被动累积，"干得好不好"）；职业轨=段位与资格（等级/技能树/认证，"配不配干"）
- 职业模板 PersonalityModelPresets 通道（出身塑性格）：提案挂起，未拍

### 5.2 种族系统定义（定案）

**种族 = 出生注定的超级配置包 + 一个群体标签。** 与特质同构（特质=生成抽取/事件获得的命名修改器包；种族=出生注定、终身不改的命名修改器包），差异仅获得时机与内容体积，无结构差异。

**运行时种族无专属系统，一切差异经四条已有管道涌现**：

| 管道 | 涌现结果 |
|------|---------|
| 统一效应模型 | 数值差异 = 查种族配置包（精灵高精神、矮人高体质） |
| 生命周期配置 | 成长/衰老/死亡节奏——精灵可塑期长、死得晚（接全年龄成长） |
| 关系层群体轨 | 种族 = 可作关系对象的虚拟实体（Attitude 轨，无 Rank）；文化偏见 = 群体八卦传染改写群体轨；遇具体个体时唤起群体轨 = 初始态度。种族小圈子/世仇全是传染涌现 |
| 生成画像 | 职业/钱包 roll 权重引用种族先验——"矮人矿工多"是体质先验 × 矿工门控的统计涌现，不是限制表 |

寿命玩法零机制：锚点不过期（记忆已定案）× 寿命配置，长生种自然攒下百年老锚点。

### 5.3 种族配置规范（定案）

现有 8 项（`UCreatureRaceTemplate`，`CreatureDataDefinitions.h:172-227`）：BodyArchitecture / AdulthoodAge、OldAge、MaxAge / Youth、Stable、OldEventChance / AttributeConfigs / DemandConfigs / PersonalityModelPresets（3 新维待补配）/ ForbiddenTraitsPool + InitialTraitCount / NameConfig / GenderConfig。

**新增 5 项**：

| 新增配置 | 用途 | 备注 |
|---------|------|------|
| `SpawnWeight` | 人口占比/稀有度 | 现状 `GetRandomRaceTag()` 均匀随机（`ConfigDataSubsystem.cpp:570-573`），落地后改轮盘赌 |
| `InitialGroupAttitudes: TMap<RaceTag, float>` | 本族对他族初始态度先验 | 生成时写入个体关系数组的群体轨（DF 世仇先验） |
| `TraitWeightModifiers: TMap<TraitTag, float>` | 特质亲和乘数 | 见 §4 |
| `ProfessionAffinity: TMap<ProfessionTag, float>` | 职业亲和权重 | 生成画像输入 |
| `GrowthScale` | 成长速率系数 | 随成长模块落地，先记名 |

### 5.4 出生与人口（定案）

```
人口 = 剧本关键角色（手配）+ 生成填充（算法 roll）+（后续）生娃/迁入
```

- **剧本关键角色**：每个剧本资产配置——身份/七围/9维/职业/家庭关系/初始关系全手配；**玩家的孩子 = 剧本关键角色之一**（出生事件链留给后续生娃系统）
- **生成填充公式**（阶层删除后的新底）：职业基准 + 9 维 + 个体噪声 + 钱包初始值分布 + 种族权重
- **生娃/迁入**：后续系统，依赖时间系统地基；DF 式迁入波次与生娃事件链挂此
- 流动旅客/客商 Spawn 照旧（旧设计不动）

### 5.5 孩子：首个店员（定案）

Family 轨 + Employee 轨双轨（员工制度的首个真实用户）；可塑培养（成长通道的玩家入口）；认知指引（《关系系统》§7 听闻通道的教程化包装——孩子认识镇民，回家告诉脸盲的玩家"那是谁"）。**家族经营从这里开始。**

## 6. 名声（定案）

名声 = **社会对个体的累计评价标量，有正负**（正 = 敬仰 / 负 = 恶名），挂 NPC 持久化数据，与七围、九维同级存储。

- **写入**：只经统一效应——解读规则输出指向名声键的修改器（谋杀被公开 → 名声 −N；义举被传开 → 名声 +N）。**记录驱动：名声不凭空变，必有来源事件**；无人知晓的事不影响名声（坏事没传开 = 名声不变，只有当事人之间的关系变了）
- **读取**：陌生人对"听说过的人"的预设立场、社交初始态度、服务/门禁优待或拒绝、雇佣与婚恋门槛的输入修饰
- **与关系的分工**：关系是"我对他"（个体对个体，归《AI决策系统-关系系统-系统设计.md》）；名声是"世界对他"（社会标量，本文）。知道某人 ≠ 对他有关系——听闻事件可改变我对他的看法（经条目解读间接影响我的态度），但只有实质交互才建关系 entry
- 数值细则（区间、衰减与否、阈值效果）：数值设计环节
