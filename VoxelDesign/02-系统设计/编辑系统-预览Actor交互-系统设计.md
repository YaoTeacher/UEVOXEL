## 零、组件架构

### 0.1 架构概述

**核心原则**：Manager管理世界状态，Component管理玩家自己的功能

**组件架构**（6个核心组件）：
```
PlayerController（输入路由层）
├── StateComponent（数据存储层）
├── InteractComponent（业务逻辑层 + 输入状态存储）
├── VisualUIComponent（视觉表现层）
├── HistoryComponent（历史记录层）
└── PreviewActor（预览显示）- 独立Actor
```

---

### 0.2 各组件职责

#### AVoxelPlayerController
- **归属**：输入路由层
- **作用**：
  - 接收原始输入（键盘、鼠标、手柄）
  - 分发输入到InteractComponent
  - 相机控制
  - 组件生命周期管理
  - 系统访问（获取WorldSubsystem引用）
  - 输入模式切换

#### StateComponent（VoxelControllerStateComponent）
- **归属**：数据存储层
- **作用**：
  - 存储所有玩家状态数据（包括预览状态HIDDEN/BASE/EDIT）
  - 提供状态访问器和修改器
  - 广播状态变更事件
  - **不做**：业务逻辑、输入检测、视觉更新

#### InteractComponent（VoxelControllerInteractComponent）
- **归属**：业务逻辑层 + 输入状态存储
- **作用**：
  - 接收蓝图传入的体素索引
  - 存储输入状态（FirstPoint、SecondPoint）
  - 业务逻辑处理（包围盒计算、参数调整）
  - 协调其他组件（调用StateComponent、VisualUIComponent、HistoryComponent、WorldSubsystem）
  - 权限检查、成本检查
  - **不做**：输入检测、状态存储、视觉渲染、网格生成

#### VisualUIComponent（VoxelControllerVisualUIComponent）
- **归属**：视觉表现层
- **作用**：
  - 持有PreviewActor
  - 调用PreviewActor的更新方法
  - 管理UI元素（对称模式按钮）
  - **不做**：业务逻辑、输入检测、Gizmo管理（委托给PreviewActor）

#### HistoryComponent（VoxelControllerHistoryComponent）
- **归属**：历史记录层
- **作用**：
  - 管理撤销/重做栈
  - 记录操作日志
  - 统计信息

#### PreviewActor（AVoxelPreviewActor）
- **归属**：预览显示（独立Actor）
- **作用**：
  - 显示预览网格
  - 管理所有Gizmo（12个）
  - 处理Gizmo交互
  - 管理预览状态（HIDDEN/BASE/EDIT）

---

### 0.3 依赖关系

```
PlayerController
├── StateComponent（数据层）
├── InteractComponent（业务层 + 输入状态）
│   → 接收蓝图输入（体素索引）
│   → 管理输入状态（FirstPoint、SecondPoint）
│   → 调用StateMachine（状态转换）
│   → 读写StateComponent（业务数据）
│   → 调用VisualUIComponent（视觉更新）
│   → 调用HistoryComponent（历史记录）
│   → 调用WorldSubsystem（执行编辑）
└── VisualUIComponent（视觉层）
    → 读取StateComponent（包围盒数据）
    → 调用PreviewActor（预览显示）
```

---

### 0.4 输入处理流程

```
原始输入（鼠标/键盘）
    ↓
蓝图（射线检测、体素索引计算）
    ↓
InteractComponent（业务逻辑 + 输入状态）
    ├─ 存储输入状态（FirstPoint、SecondPoint）
    ├─ 状态转换
    ├─ 包围盒计算
    ├─ 参数调整
    └─ 协调其他组件
    ↓
StateComponent（状态更新）
    ├─ 存储新状态
    └─ 广播状态变更事件
    ↓
PreviewActor（视觉更新）
    ├─ 更新预览网格
    └─ 更新Gizmo位置
```

## 一、状态机设计

### 1.1 状态定义

```
EPreviewInteractionState:
    - HIDDEN：隐藏/初始状态（无预览）
    - BASE：拖动定义底面（FirstP + 动态SecondP）
    - EDIT：推拉任意面调整包围盒（FirstP + SecondP + 动态Height/Min/Max）
```

### 1.2 状态转换

```
初始: HIDDEN状态
    ↓
【按下鼠标左键】记录第一个点
    ↓
BASE状态
- FirstP已设置
- 拖动鼠标实时更新SecondP
- 显示2D包围盒预览（无Gizmo）
    ↓
【松开鼠标左键】记录第二个点
    ↓
EDIT状态
- FirstP、SecondP已确定
- Height初始为0
- 显示12个Gizmo
- 显示3D包围盒预览
    ↓
【拖动任意面Gizmo或Actor控件】
    ↓
EDIT状态（持续）
- 动态更新包围盒
- 实时更新预览和Gizmo位置
    ↓
【Enter确认】或【Esc取消】
    ↓
HIDDEN状态
```

### 1.3 状态特性

| 状态 | Gizmo显示 | 预览类型 | 主要操作 |
|------|----------|----------|----------|
| **HIDDEN** | 无 | 无 | 无预览 |
| **BASE** | 无（显示2D包围盒） | 2D包围盒（实时） | 拖动定义底面范围 |
| **EDIT** | 12个Gizmo（Actor控件6+面控件6） | 3D包围盒（实时） | 拖动Gizmo调整尺寸/位置/旋转 |

## 二、取消操作

### 2.1 操作方法

| 操作 | 行为 | 用途 |
|------|------|------|
| **单击右键** | 回退上一步 | 微调、撤销上一步操作 |
| **长按右键 (2秒)** | 清空所有 | 完全取消当前编辑 |
| **ESC键** | 清空所有 | 快速取消（键盘用户） |

### 2.2 视觉反馈

**长按右键2秒的进度反馈**：
- 位置：跟随鼠标光标
- 样式：环形进度条（红色，表示取消）
- 动画：从0%到100%，2秒填满
- 中断：中途松开右键 → 取消退度条，不执行取消

### 2.3 状态回退路径

```
EDIT → BASE → HIDDEN
  ↑      ↑       ↑
  └──────┴───────┘
     每次单击右键回退一步

说明：
- 在EDIT状态单击右键 → 回到BASE状态（保留FirstP，重新拖动SecondP）
- 在BASE状态单击右键 → 回到HIDDEN状态（清空所有）
- 长按右键(2秒)或ESC键 → 从任意状态直接回到HIDDEN
```

## 三、Actor控件组（移动+旋转Gizmo）

### 3.1 Actor控件组组成

```
Actor控件组（共6个Gizmo）：

移动Gizmo（3个）：
    - 红色箭头：沿世界X轴移动
    - 绿色箭头：沿世界Y轴移动
    - 蓝色箭头：沿世界Z轴移动

旋转Gizmo（3个）：
    - 红色圆环：绕世界X轴旋转
    - 绿色圆环：绕世界Y轴旋转
    - 蓝色圆环：绕世界Z轴旋转

作用：操作整个PreviewActor的位置和旋转
无中心点（避免误操作）
```

### 3.2 移动Gizmo特性

```
方向性：
    - 单向箭头（→），指向正方向
    - 拖动时：
        · 向箭头方向拖（向前）→ 正向移动
        · 向箭头反方向拖（向后）→ 负向移动
    - 两个方向都可以，不需要旋转相机

固定轴向：
    - 红色箭头 = 世界X轴（固定不变）
    - 绿色箭头 = 世界Y轴（固定不变）
    - 蓝色箭头 = 世界Z轴（固定不变）
    - 不随相机变化
```

### 3.3 旋转Gizmo特性

```
旋转方式：
    - 圆环Gizmo，沿轴向旋转
    - 拖动圆环时，PreviewActor绕对应轴旋转
    - 旋转角度按固定步长（如45°）吸附

固定轴向：
    - 红色圆环 = 绕世界X轴旋转
    - 绿色圆环 = 绕世界Y轴旋转
    - 蓝色圆环 = 绕世界Z轴旋转
    - 不随相机变化
```

### 3.4 Actor控件样式

```
外观设计：
    移动箭头：
    - 形状：圆柱形箭头（→）
    - 颜色：红/绿/蓝（对应X/Y/Z轴）
    - 大小：适中（容易点击）
    - 位置：从PreviewActor中心出发，沿轴向延伸
    - 材质：半透明

    旋转圆环：
    - 形状：圆环（○）
    - 颜色：红/绿/蓝（对应X/Y/Z轴）
    - 大小：包围PreviewActor
    - 位置：以PreviewActor中心为圆心
    - 材质：半透明

状态反馈：
    未选中：6个控件半透明显示
    悬停：鼠标悬停的控件高亮，UI提示："拖动沿X轴移动" / "绕X轴旋转"
    拖动中：当前控件完全高亮，其他半透明，UI显示移动/旋转数值
```

### 3.5 移动逻辑

```
移动计算：
    1. 计算鼠标在屏幕空间的移动距离
    2. 判断是向前拖还是向后拖
    3. 转换到对应轴的世界坐标增量
    4. 四舍五入到最近的体素单位
    5. 更新PreviewActor位置

体素对齐：
    - 始终吸附到体素网格
    - 移动增量按体素单位计算
    - 最终位置四舍五入到网格

移动约束：
    - 不限制移动范围
    - 可以移出Chunk或世界边界
    - 移动时不检查碰撞
    - 最终确认时才检查位置有效性
```

### 3.6 旋转逻辑

```
旋转计算：
    1. 计算鼠标在屏幕空间的移动距离
    2. 转换为旋转角度增量
    3. 按固定步长吸附（如45°）
    4. 更新PreviewActor旋转

旋转约束：
    - 不限制旋转角度
    - 旋转后包围盒自动更新
    - 旋转后Gizmo位置自动更新
```

### 3.7 操作输入

| 操作 | 行为 |
|------|------|
| **悬停在移动箭头上** | 箭头高亮 |
| **点击并拖动移动箭头** | 沿该轴移动（可正可负） |
| **悬停在旋转圆环上** | 圆环高亮 |
| **点击并拖动旋转圆环** | 绕该轴旋转 |
| **松开鼠标** | 结束操作，保持新位置/旋转 |
| **ESC键** | 取消所有操作 |
| **长按右键 (2秒)** | 取消所有操作（带进度条） |
| **单击右键** | 回退上一步 |

## 四、面Gizmo调整尺寸（推拉面）

### 4.1 面的定义

```
6个面 = 盒体的6个面

        ┌───── 上面(+Z) ─────┐
       /│                    /│
      / │                   / │
     /  │                  /  │
左面(-Y)│      盒体         │ 右面(+Y)
    /   │                 /   │
   /    │                /    │
  /     └───── 下面(-Z) ─┘     │
 前面(-X)                    │
 └───────────────────────────┘
          后面(+X)

面的编号：
    0: 前面(-X) → 控制 Min.X，法向 = (-1, 0, 0)
    1: 后面(+X) → 控制 Max.X，法向 = (+1, 0, 0)
    2: 左面(-Y) → 控制 Min.Y，法向 = (0, -1, 0)
    3: 右面(+Y) → 控制 Max.Y，法向 = (0, +1, 0)
    4: 下面(-Z) → 控制 Min.Z，法向 = (0, 0, -1)
    5: 上面(+Z) → 控制 Max.Z，法向 = (0, 0, +1)
```

### 4.2 面Gizmo样式

```
外观设计：
    - 形状：半透明方形平面
    - 位置：覆盖在盒体的6个面上
    - 大小：与面对应的FBox面大小一致
    - 材质：半透明（可以看到内部预览）

状态反馈：
    默认：不显示（悬停才显示）
    悬停：对应面高亮显示
    拖动中：当前面完全高亮
```

### 4.3 触发逻辑

```
显示时机：
    - EDIT状态下
    - 鼠标悬停在盒体上 → 显示6个面
    - 鼠标移开 → 面消失

点击检测：
    - 只有点击面本身才触发（精确）
    - 点击面旁边的区域不会触发

背面处理：
    - 背向相机的面不能点击
    - 只能点击面向相机的面
```

### 4.4 推拉逻辑

#### 4.4.1 投影平面定义

```
投影平面：
    - 以盒体中心点为原点
    - 平面法向 = 相机视线方向
    - 平面始终面向相机（垂直于相机视线）

示例：
    当前FBox：Min(0,0,0), Max(10,10,10)
    中心点：(5,5,5)
    相机视线方向：V

    投影平面：通过点(5,5,5)，法向=V
```

#### 4.4.2 操作流程

```
步骤：
    1. 点击某个面（比如YMAX面）
       - 射线与投影平面求交点 P1(X, Y, Z)
       - 记录对应轴的坐标（这里记录 Y）

    2. 拖动鼠标
       - 射线与同一个投影平面求交点 P2(B, N, M)
       - 计算偏移量 = N - Y
       - 新的坐标 = 旧坐标 + 偏移量

示例（YMAX面）：
    当前FBox：Min(0,0,0), Max(10,10,10)

    点击时：
        射线交点 P1(5, 10, 5)
        记录 Y = 10

    向右拖动：
        射线交点 P2(5, 15, 5)
        DeltaY = 15 - 10 = 5
        新的MAX.Y = 10 + 5 = 15
        新FBox：Min(0,0,0), Max(10,15,10)

    向左拖动：
        射线交点 P2(5, 7, 5)
        DeltaY = 7 - 10 = -3
        新的MAX.Y = 10 + (-3) = 7
        新FBox：Min(0,0,0), Max(10,7,10)
```

#### 4.4.3 体素对齐

```
体素对齐：
    - 始终吸附到体素网格
    - 移动增量按体素单位计算
    - 最终位置四舍五入到网格

示例：
    DeltaY = 5.3 → 四舍五入到 5
    DeltaY = 5.7 → 四舍五入到 6
```

### 4.5 约束检查

```
严格约束规则：
    对于每个轴：
        Min.X < Max.X
        Min.Y < Max.Y
        Min.Z < Max.Z

    推拉面时：
        实时检查是否会违反约束
        如果违反，阻止该方向的移动
        将坐标钳位到有效范围

示例：
    当前FBox：Min(0,0,0), Max(10,10,10)
    拖动YMAX面向正方向移动

    Max.Y可以增加到任意值
    但不能等于或小于Min.Y（Min.Y < Max.Y）

    如果拖动YMIN面向负方向：
        Min.Y不能等于或大于Max.Y
        Min.Y被限制在 (-∞, Max.Y) 范围内
```

### 4.6 对称拖动

```
UI开关控制：
    屏幕上有3个开关按钮：
        [ X对称 ] [ Y对称 ] [ Z对称 ]

    点击按钮 → 开启/关闭对应轴的对称
    按钮高亮 = 开启，半透明 = 关闭

拖动面时：
    根据开启的对称轴执行对称操作

示例（拖动YMAX面）：
    未开启对称：
        只移动YMAX面
        Min.Y不变，Max.Y改变
        盒体Y中心改变

    开启Y对称：
        YMAX面移动，YMIN面也对称移动
        盒体Y中心不变，向两边扩展

    开启X和Y对称：
        拖动YMAX面时：
        - Y轴对称：YMAX和YMIN同时移动
        - X轴对称：XMAX和XMIN同时移动
        盒体X和Y中心都保持不变
```

### 4.7 推拉面方案的优势

```
相比边界点方案的优势：

1. 复杂度大幅降低
   - 不需要扇形区域判断
   - 不需要计算鼠标角度
   - 不需要判断轴向（每个面只控制一个轴）

2. 更直观
   - 用户看到面，直接推拉
   - 符合直觉（类似Blender、CAD软件）

3. 操作简单
   - 点击面 → 拖动 → 完成
   - 单轴控制，不会误操作

4. 学习成本低
   - 不需要理解复杂的扇形区域概念
   - 直接操作，所见即所得
```

## 五、与其他功能的交互

### 5.1 Gizmo优先级

```
鼠标点击优先级：
    1. 点击Actor移动Gizmo（箭头）→ 移动模式
    2. 点击Actor旋转Gizmo（圆环）→ 旋转模式
    3. 点击面Gizmo → 调整尺寸模式（推拉面）
    4. 点击PreviewActor主体（EDIT状态）→ 无操作（已显示所有Gizmo）

Gizmo优先原则：
    - Actor控件优先于面控件
    - 如果Actor控件和面重叠，优先触发Actor控件
    - 同一时刻只能有一种模式激活
```

### 5.2 数据同步

```
状态一致性：
    - Actor移动：只改变位置，不改变尺寸和旋转
    - Actor旋转：只改变旋转，不改变位置和尺寸
    - 面推拉：只改变尺寸（包围盒），不改变位置和旋转
    - 三种操作可以组合使用

数据流：
    - Actor移动 → 更新PreviewActor位置
    - Actor旋转 → 更新PreviewActor旋转
    - 面推拉 → 更新PreviewActor几何参数（FBox的Min/Max）
```

## 六、视觉反馈设计

### 6.1 颜色编码

| 状态 | Gizmo样式 | 预览颜色 | UI提示 |

## 九、特殊场景处理

### 9.1 箭头指向屏幕内

```
场景：相机从+X轴正向看
    → 红色箭头指向屏幕内
    → 用户很难点击红色箭头

处理方式：
    - 保持箭头长度
    - 不缩短或替换
    - 用户可以继续拖动（向前=正，向后=负）
    - 用户自然旋转相机到更容易点击的角度
```

### 9.2 Gizmo重叠

```
场景：相机斜向看
    → 某两个箭头在屏幕上重叠或接近
    → 难以区分

处理方式：
    - 不特殊处理
    - 用户自己旋转相机
    - 或放大视角（滚轮）
```

### 9.3 面的朝向问题

```
场景：相机从某个角度看，某个面几乎垂直于视线
    → 该面看起来是一条线
    → 难以点击

处理方式：
    - 不特殊处理
    - 用户自然旋转相机到更容易点击的角度
    - 或放大视角（滚轮）
```

## 十、设计原则总结

### 10.1 核心原则

```
1. 职责分离
   - StateComponent：存储所有玩家状态数据（包括预览状态）
   - 蓝图：输入检测并计算体素索引（射线检测、点击判定）
   - InteractComponent：输入状态存储（FirstPoint、SecondPoint）+ 业务逻辑处理（协调其他组件）
   - PreviewActor：管理预览显示和Gizmo（包含HIDDEN/BASE/EDIT状态）

2. 操作优先级
   - 直接编辑优先（EDIT状态自动进入）
   - Actor控件优先于面控件
   - 直接操作（拖动Gizmo）优先于快捷键

3. 体素系统特性
   - 始终吸附到体素网格
   - 单轴操作为主（保证精确）
   - 严格约束（Min < Max）

4. 用户体验
   - 视觉反馈清晰（颜色、高亮、UI提示）
   - 操作方式直观（箭头=移动，圆环=旋转，面=调整尺寸）
   - 容错性好（单击回退、长按取消）
```

### 10.2 待实现功能

```
暂不实现的功能：
    - 边界点Gizmo（已被推拉面方案替代）
    - 厚度可视化编辑（UI）
```

### 10.3 关键设计决策

```
1. 状态机：三状态（HIDDEN/BASE/EDIT）
   - HIDDEN：隐藏/初始状态（无预览）
   - BASE：拖动定义底面（FirstP + 动态SecondP）
   - EDIT：推拉任意面调整包围盒（FirstP + SecondP + 动态Height/Min/Max）

2. 取消操作：单击回退 + 长按清空（2秒）
   - 单击右键：EDIT → BASE → HIDDEN
   - 长按右键(2秒)或ESC：直接回到HIDDEN

3. Actor控件组：6个Gizmo
   - 移动Gizmo（3个箭头）：沿X/Y/Z轴移动
   - 旋转Gizmo（3个圆环）：绕X/Y/Z轴旋转

4. 面控件组：6个半透明平面
   - 推拉方式调整尺寸
   - 使用投影平面进行鼠标射线检测

5. 对称拖动：UI开关控制（X/Y/Z分别控制）

6. 约束检查：严格约束（Min < Max）
```
