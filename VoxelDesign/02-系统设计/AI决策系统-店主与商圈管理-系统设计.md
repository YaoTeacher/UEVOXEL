## 1. 系统边界

**负责**：NPC 店主的管理职责与空窗期、区域业务资金权限、四势力关系与许可的分工规则、商圈内部业务（租务/商圈活动）。

**不负责**：员工排班与工单执行（[员工与工作执行](/VoxelDesign/02-系统设计/AI决策系统-员工与工作执行-系统设计.md)）、势力诉求与情报玩法（§4.4 已挂起）、玩家侧操作清单（[经营操作](/VoxelDesign/02-系统设计/AI决策系统-经营操作-系统设计.md)）、店铺内部经营细节（经营卷）。

## 2. 店主

### 2.1 角色

店主是经营实体的经营人，也可按自己的劳动安排下场工作；承租 / 自营不是工资雇员，只有薪酬制另持有效雇佣记录：

- **个人层**：自己的 Work/Rest/Dine 排班块，亲自承担一部分实际工作（收银/接待/服务），执行工单与员工同一套系统；
- **经营层**：低频决策循环，见 §2.1.1；决策项在原有基础上补 **排班** 与 **工作分配**：
  - 排班：按营业时段 × 关键工作类型 × 员工技能生成，覆盖缺口才调整；
  - 工作分配：按员工职业/技能/性格调整工作优先级表；
- **管理动作**：全部后台数据操作，不建模物理动作（巡店/巡检 V1 不做）。

#### 2.1.1 经营决策循环（性格驱动周期）

```
决策触发 = 周期到点 ∪ 关键事件
  周期长度由基准周期经性格修正决定：
    勤快 / 进取 → 短（每日）
    懒散 / 保守 → 长（每周）
  关键事件（不等周期，立即触发）：
    库存告急 / 资金低于警戒 / 差评激增 / 放弃率连续超阈 / 商圈信号
```

**决策输入 = 滞后指标 + 先行信号**：客流统计、工单积压、库存水位、销量、声誉是滞后指标；等待段放弃事件、投诉事件、队列长度分布聚合为店铺级统计（放弃率／投诉数／平均等待时长）作为先行信号一并接入。店主对「顾客每天默默走掉」这类慢性失血必须有感知渠道，不能只等差评爆发。具体指标集随功能模块细化，此处只定方向。

性格不只影响周期，也影响决策倾向：进取店主敢涨价敢投活动，保守店主求稳。

**决策项**

| 决策项 | 依据 | 输出 |
|---|---|---|
| 营业作息 | 客流时段统计 + 性格 | 改写营业时段 |
| 招聘 / 裁员 | 工单积压 + 放弃率／平均等待 + 资金 | 发起招聘需求 / 解雇 |
| 商品定价 | 销量 + 声誉 + 性格风险偏好 | 逐商品调价（禁止调价系数） |
| 进货 | 库存水位 + 销量 | V1 即时采购 |
| 活动 / 广告 | 知名度 + 放弃率 + 资金 + 性格 | 后续版本，V1 不做 |
| 员工设施 | 员工忠诚／情绪 + 资金 + 性格 | 后续版本，V1 不做休息区 |

**自治边界（仅 NPC 店主；玩家自营店的一切经营决策由玩家随时直接做）**

- 定价 / 作息 / 采购：店主自主执行，玩家看报表与结果；
- 招聘 / 解雇：**永远需玩家同意**，商圈人事权归玩家；
- 关系度解锁商量：关系度低时店主按自己性格独立决策，高时决策前向玩家提案询问；
- 辞退店主：玩家随时可行。

**商圈同类人流的感知渠道**：数据源为商圈统计层（各店客流、同类总量、自身份额）。NPC 店主在经营决策周期（低频）读取本店客流趋势、同类总客流与自身份额变化；玩家侧本店为精确数据，商圈与竞对只给趋势级信息（升／降／平 + 大致幅度），现场观察兜底。

**数据归属**：决策需要的账本／声誉／库存／客流全部读取经营实体的对应模块，决策只读不另存，结果写回模块字段。

### 2.2 候选与邀请

- 后续NPC邀请只面向无有效合同候选，图外合同也算有效；不因邀请自动终止旧合同。已有同业态空铺走邀请 / 同意条款 / 签约接管，不重画区域；模板路径走NPC业态与条款选择 / 预览落位 / 确认，正式Lease生效先于真正租户建筑家具写入，同一连续面板不要求切换多个模式。V1不开放NPC招商 / 任命；
- 月租由商圈管理人按店铺配置，可单独调整；调租立即改配置，下一收租时点按新价收取；**V1 无押金 / 租期**；
- 玩家直接经营的店铺没有 NPC 店主，也没有分店概念（见[员工与工作执行](/VoxelDesign/02-系统设计/AI决策系统-员工与工作执行-系统设计.md)）；V1 沙盒中玩家是店铺承租经营人，不是商圈产权人自营。

### 2.3 空窗与倒闭

```
店主死亡/离开 → 店铺继续运营，经营决策循环挂起
  （无补货/调价/活动决策，员工照常上班，吃老库存）
→ 租金仍按计划直接结算，允许承租经营人的经营账户为负
→ 不因欠租、负余额或资金耗尽自动倒闭 / 收铺
→ 主动退租或产权人按缓冲期收回后才清退员工并空置
```

V1 不生成欠租、坏账或连续失败次数；原“店主死亡→立即空置”和“连续欠租自动倒闭”口径均不进入 V1。

## 3. 区域业务账与资金权限

### 3.1 个人钱包、经营账户与业务归属

V1 每个实际 / 抽象人物创建时都有个人钱包与唯一经营账户，非经营者也有，全部生意共用。商圈 / Shop / 图外生意共享经营实体基础模型并按类型组合模块，唯一注册在 Global `BusinessEntities`；经营实体持经营资产、产权 / 经营关系、`bOpen` / 日程、目录 / 价格 / 订单 / 预留与声誉 / 客流。区域只空间与校验，不能保存业务镜像；实体区域组件关联 `AreaRef={SceneId,AreaId}`，子客房 / 仓库只有空间ID，抽象经营无实际区域且不造假区域。真实库存、FIFO队列和门锁仍归对应实例，区域看板为不入档派生索引。

`BusinessEntityId` 是全局稳定经营 ID（GUID，规则见[总纲 §2.7](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)）；不再使用 `ShopId` 别名。自营 / 承租 Shop 使用经营人的经营账户，薪酬制 Shop / 商圈使用产权人的经营账户，资金责任人由经营实体有效关系解析。店铺产权人在创建与易主时写入实体自身，运行时不上溯；空间包含不吞并租户资产。商圈易主只改变依赖产权人的资金链，承租营收 / 工资不变，合同雇主实体不换。详见[区域店铺与商圈管理 §2 / §9](/VoxelDesign/02-系统设计/AI决策系统-区域店铺与商圈管理-系统设计.md)。

初始顾客钱包按配置提供，不给固定数值。大多数NPC持图外真实工资合同，工资进入个人钱包；图外雇主为抽象账户（`bAbstract=true`，不计余额），支出直接发生、不补资（03A §5.9）。失业且无其他实际收入时没有钱，不兜底发钱。

| 经营方式 | 经营人角色 | 资金与查询权限 |
|----------|------------|----------------|
| 定期交租（承租） | 剩余索取者：交租后利润归己 | 店铺收支使用经营人的唯一经营账户；可查看自己的个人钱包、经营账户和店铺业务流水 |
| 薪酬制（受雇管理） | 拿工资，盈亏归产权人 | 只能执行授权业务，从产权人经营账户结算；可看区域业务流水与经营账户可用资金，不能划转产权人的个人钱包或经营账户，也不能查看其个人流水；薪酬制店主同样持有挂在 Creature 上的劳动安排并下场执行工作，工资只走雇佣记录 |

- 所有业务流水记录 **操作者 + 事由**，为后续审计/挪用玩法预留；
- **中饱私囊 V1 不做**：后续用虚报采购 / 私拿库存 / 假账 + 流水审计实现；
- 本人可在自己的个人钱包与唯一经营账户之间双向注资 / 提取，普通转出须源账户足额；个人之间付款只走双方个人钱包。销售从消费者个人钱包进入店铺资金责任人的唯一经营账户，工资从雇主经营账户进入员工个人钱包，租金在双方经营账户之间划转；贷款、即时采购使用系统单边流水（[经营操作 §3.7](/VoxelDesign/02-系统设计/AI决策系统-经营操作-系统设计.md)）；
- **账目查看在统计页资金段**，按 `SourceBusinessEntityId / TargetBusinessEntityId` 查询源 / 目标业务归属，按可空的 `OccurredAreaRef` 查询发生空间。租金是一笔交易，源归 Shop、目标归 District，不给区域账户，也不按当前父关系回改历史。租约唯一事实在 Global `LeaseRegistry`，经营实体仅持 `LeaseId` 引用；`LessorBusinessEntityId / TenantBusinessEntityId / LeasedAreaRef / TenantCreatureId` 分别表示出租业务、承租业务、租用空间与承租人物，不混用。

### 3.2 利润与工资

- 承租型：销售进入承租经营人的经营账户，租金从该账户划到商圈产权人的经营账户，剩余利润留在经营人的经营账户；
- 薪酬型：销售进入产权人的经营账户，授权经营支出也从该账户结算，经营人工资从该账户进入其个人钱包；
- 玩家直接经营店：V1 沙盒采用承租方式，店铺收支使用玩家唯一经营账户；本人可与个人钱包双向注资 / 提取，普通转出须源账户足额；
- 同一人物的所有生意共享其唯一经营账户；每个人物创建时两类账户均存在，非经营者也有，不做区域分账户或钱包内区域分账。

## 4. 商圈管理人

### 4.1 形态

- **实体 + 后台决策**：有办公室/日程（巡街、面谈），同时挂低频决策循环；
- 可以是产权人本人（自营），也可以是**承租经营人**（向产权人交租金、剩余索取）或**受薪管理者**（工资从产权人经营账户出）；
- 管理人本人可以另有自己的店铺（利益冲突留给事件/声誉系统）；处理下属店铺合同时，若自己就是合同乙方，只能转由产权人办理，不能同时代表双方审批或修改。

### 4.2 内部业务

| 业务 | 规则 |
|------|------|
| 招商（后续版本，V1 不开放） | 后续版本空置店铺可发起招商；候选显示「承租开店 / 应聘经理」意图：承租 NPC 自带业态，薪酬制走商圈员工招聘 + 任命为店铺经营人（商圈卷 §12.7）。V1 只创建玩家标准承租店，不生成 NPC 租户或 NPC 店长 |
| 租务 | V1 月租（每店可配）+ 收租计划 + 调租即时改配（下一收租按新价）；**无租期、无押金、无欠租**；租金按所属商圈计划从承租经营人的经营账户划到商圈产权人经营账户，直接足额划转并允许源经营账户为负；不生成坏账、连续失败、手动补缴或违约收铺；退租 / 清退缓冲期可配，期间继续营业 / 交租 |
| 铺位资产 | 承租户自带的建筑 / 装修 / 家具归租户；后续盘下从产权人经营账户支付，资产归商圈产权方；V1 不做遗留资产处置 |
| 坏账 | V1 不产生坏账；后续违约与资产处置玩法需另行决策 |
| 公共维护 | V1 不设公共维护费，也不启用公共维护工 / 清洁员 / 治安管理员等专属岗位；设施维护统一为员工维修工单，商圈内家具的工单由普通员工认领 |
| 公共设施 | 路灯 / 长椅 / 路面 / 公共厕所等专属设施留后续版本；V1 不做专属公共设施清单与按日维护费，但商圈区域内放置的普通家具仍注册并产生保洁/维修工单 |
| 商圈活动 | V1 不开放广告、促销或其他活动，不生成实例、不扣费；完整版本按业务归属从资金责任人的经营账户支出，集市 / 节庆 / 摊位与节日活动均留后续版本 |

### 4.3 商圈业务账

- 商圈没有独立余额；租金收入、管理人薪酬等按业务归属使用相应经营者的唯一经营账户结算，并通过唯一流水形成商圈业务账；
- 受薪管理人只能执行授权业务，由系统从商圈产权人经营账户扣款；V1 同一产权人的所有区域共享该经营账户，不设分类预算、区域现金池或区域分账户；
- 主线剧情中玩家获得商圈经营业务支出权，不等于获得游商个人钱包或经营账户的任意划转权；
- V1 无欠租收铺或坏账；退租 / 清退只按经营关系与可配置缓冲期处理。

### 4.4 四势力与许可

四势力：**市议会（渡鸦）、教会（白鸥）、市民联合（灰鼠）、帝国残余（太阳）**，各自的据点、人群与相互关系见 [势力设定](/VoxelDesign/00-设定/势力设定/总结.md)。玩家经营的酒店是城市中立的避风港与情报集散地，四势力对它各有需求（[玩法设定](/VoxelDesign/00-设定/玩法设定.md) §4）。

**三条分工，本卷只定分工不定义势力内容**：

| 机制 | 挂谁 | 产出 |
|---|---|---|
| 势力关系值 | 人（玩家与每个 NPC 各一套） | 个人 BUFF |
| 许可 | 经营许可归经营实体；改建许可关联实际空间 | 后续解锁业态、设备、活动、改建，V1不启用 |
| 口碑 / 阵营客群统计 | 经营实体 | V1服务组形成总体声誉，阵营只记客群构成，不作为群体声誉或选店关系修正；完整矩阵后续（[店铺经营](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md) §7） |

**许可校验主体分两类**：改建类（扩建、加盖、后巷用地、征地、公共设施建设）用**所有人**的关系校验；经营类（业态、设备、活动）用**经营人**的关系校验。许可记录保存"用谁的关系获得"。

- 经营许可归经营实体，改建许可关联实际空间；同一所有人开三家店分别申请，区域不镜像经营许可；
- 已获得许可**不因关系下降自动吊销**，只在申请与升级时校验；
- 谁授予哪类许可、各势力的关系等级门槛，属势力设计，不在本卷。

> 许可具体内容由配置表定义：科技树式前置解锁、势力关系门槛、费用、是否可升级、是否年检、有效期、到期重审、持续义务等均逐许可配置；**V1 最小版本暂不实现许可**（详见[区域店铺与商圈管理 §6.9](/VoxelDesign/02-系统设计/AI决策系统-区域店铺与商圈管理-系统设计.md)）。

**不做**（V1）：势力的具体诉求玩法（为帝国残余建密室、情报买卖、势力平衡博弈）。这些是独立玩法模块，接口按"服务目录"预留（服务项 / 提供方 / 费用 / 响应时间），商圈与店铺只做申请方。

## 5. V1 范围

**做**：预置商圈与玩家标准承租店的经营关系 / 资金权限、商圈租务 / 玩家薪酬、同一建造面板创建实体与空间的开店流程、普通员工招聘与劳动安排。NPC店主低频经营循环、NPC招商模板与多商圈运营留后续，不因本次分离扩大V1。

**不做**：自动倒闭 / 欠租收铺、坏账 / 补缴、广告 / 促销活动、势力诉求与情报交易玩法（V1 许可也不实现）、中饱私囊与审计、物理巡店、在营店铺转行、集市 / 节庆 / 摊位、租期 / 续租 / 押金；后续只留必要接口。
