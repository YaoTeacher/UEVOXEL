# 预览系统 状态管理设计

> **文档目的**：定义预览系统的状态管理逻辑，包括状态定义、转换规则和决策表
> **系统定位**：预览系统是独立的渲染辅助系统，**服务于编辑系统**，负责实时显示编辑操作的可视化反馈
> **创建日期**：2026-01-16
> **版本**：v1.1
> **状态**：已确定

**v1.1 更新**：明确预览系统服务于编辑系统的定位

## 一、概述

### 1.1 状态管理的重要性

预览系统涉及多个状态概念，需要明确定义和管理：

- **编辑类型**（业务属性）：用户选择编辑什么类型
- **流程状态**（渲染状态）：编辑流程的当前阶段
- **预览模式**（渲染配置）：如何渲染预览

### 1.2 核心原则

1. **概念分离**：业务属性、渲染状态、渲染配置三者分离
2. **单一数据源**：每个状态只有一个存储位置
3. **层次关系**：编辑类型（高层配置）决定流程行为
4. **双重控制**：Gizmo显示由编辑类型和流程状态共同决定

## 二、状态定义

### 2.1 编辑类型（业务属性）

#### 定义
用户选择的编辑类型，属于业务属性

#### 存储位置
`UVoxelControllerStateComponent`

#### 管理者
`UVoxelControllerInteractComponent`

#### 枚举定义

```cpp
/** 建造模式状态 */
UENUM(BlueprintType)
enum class EVoxelControllerBuildState : uint8
{
    OutBuildMode     = 0 UMETA(DisplayName = "Out Build Mode"),
    EditConstruction = 1 UMETA(DisplayName = "Edit Construction"),  // 单体素编辑
    EditArea         = 2 UMETA(DisplayName = "Edit Area"),           // 几何体编辑
    PlaceFurniture   = 3 UMETA(DisplayName = "Place Furniture"),    // 蓝图编辑
};
```

#### 状态说明

| 编辑类型 | 说明 | 对应的预览模式 |
|---------|------|---------------|
| **OutBuildMode** | 非建造模式 | None |
| **EditConstruction** | 单体素编辑 | SingleVoxel |
| **EditArea** | 几何体编辑 | SimpleGeometry |
| **PlaceFurniture** | 蓝图编辑 | ComplexBlueprint |

#### 切换触发
- 用户选择工具
- 用户切换建造模式
- 用户进入/退出建造模式

---

### 2.2 流程状态（渲染状态）

#### 定义
编辑流程的阶段，只用于控制渲染

#### 存储位置
`AVoxelPreviewActor`

#### 管理者
`UVoxelControllerVisualUIComponent`（通过调用SetPreviewState）

#### 枚举定义

```cpp
/** 预览交互状态 */
UENUM(BlueprintType)
enum class EPreviewInteractionState : uint8
{
    HIDDEN = 0 UMETA(DisplayName = "Hidden"),  // 隐藏/初始状态（无预览）
    BASE   = 1 UMETA(DisplayName = "Base"),    // 拖动定义底面
    EDIT   = 2 UMETA(DisplayName = "Edit"),    // 推拉任意面调整包围盒
};
```

#### 状态说明

| 流程状态 | 说明 | 数据 | Gizmo | 预览 |
|------|------|------|-------|------|
| **HIDDEN** | 初始/隐藏状态 | 无 | 无 | 无 |
| **BASE** | 拖动定义底面 | FirstP + 动态SecondP | 无 | 2D包围盒（实时） |
| **EDIT** | 推拉任意面调整包围盒 | FirstP + SecondP + 动态Height/Min/Max | 12个Gizmo | 3D包围盒（实时） |

#### 切换触发
- 用户点击第一个点：HIDDEN → BASE
- 用户松开鼠标：BASE → EDIT
- 用户拖动Gizmo：EDIT持续
- 用户确认/取消：任意 → HIDDEN

---

### 2.3 预览模式（渲染配置）

#### 定义
渲染方式配置，由编辑类型映射而来

#### 存储
临时存储在`AVoxelPreviewActor`（由VisualUIComponent传递）

#### 枚举定义

```cpp
/** 预览模式 */
UENUM()
enum class EPreviewMode : uint8
{
    None              = 0 UMETA(DisplayName = "None", Hidden),       // 无预览
    SingleVoxel       = 1 UMETA(DisplayName = "Single Voxel"),       // 单体素预览
    SimpleGeometry    = 2 UMETA(DisplayName = "Simple Geometry"),    // 简单几何体预览
    ComplexBlueprint  = 3 UMETA(DisplayName = "Complex Blueprint"),  // 复杂蓝图预览
};
```

#### 映射关系

| 编辑类型 | 预览模式 | 映射逻辑 |
|---------|---------|---------|
| OutBuildMode | None | 无编辑，无预览 |
| EditConstruction | SingleVoxel | 单体素编辑 |
| EditArea | SimpleGeometry | 几何体编辑 |
| PlaceFurniture | ComplexBlueprint | 蓝图编辑 |

## 三、层次关系模型

### 3.1 核心思想

**编辑类型（高层配置）决定流程行为（低层阶段）**

```
编辑类型（配置层）- StateComponent存储
├─ EditConstruction（单体素）
├─ EditArea（几何体）
└─ PlaceFurniture（蓝图）
    ↓
决定流程行为
    ↓
流程状态（运行层）- PreviewActor存储
├─ HIDDEN（无预览）
├─ BASE（定义底面）
└─ EDIT（调整参数）
```

### 3.2 行为差异

#### 单体素编辑

```
特点：跳过BASE状态

流程：
HIDDEN → EDIT（直接）

原因：单体素编辑不需要定义底面
```

#### 几何体/蓝图编辑

```
特点：完整的BASE → EDIT流程

流程：
HIDDEN → BASE → EDIT

原因：需要先定义底面，再调整参数
```

## 四、状态转换

### 4.1 完整转换图

```
初始: HIDDEN状态
    ↓
【用户选择工具 + 点击第一个点】
    ↓
单体素编辑：HIDDEN → EDIT（直接）
几何体编辑：HIDDEN → BASE
    ↓
【BASE状态下：用户拖动定义底面】
    ↓
BASE状态（持续）
- FirstP已设置
- 拖动鼠标实时更新SecondP
- 显示2D包围盒预览
    ↓
【用户松开鼠标】
    ↓
BASE → EDIT
- FirstP、SecondP已确定
- 显示12个Gizmo
- 显示3D包围盒预览
    ↓
【EDIT状态下：用户拖动Gizmo】
    ↓
EDIT状态（持续）
- 动态更新包围盒
- 实时更新预览和Gizmo
    ↓
【Enter确认】或【Esc取消】
    ↓
任意 → HIDDEN
```

### 4.2 转换触发条件

#### HIDDEN → BASE

**触发条件**：
1. 用户选择几何体/蓝图编辑工具
2. 用户点击第一个点

**数据变化**：
- StateComponent：设置FirstP
- PreviewActor：流程状态 → BASE
- PreviewActor：预览模式 → SimpleGeometry

#### HIDDEN → EDIT（单体素）

**触发条件**：
1. 用户选择单体素编辑工具
2. 用户点击放置点

**数据变化**：
- StateComponent：设置编辑位置
- PreviewActor：流程状态 → EDIT（跳过BASE）
- PreviewActor：预览模式 → SingleVoxel

#### BASE → EDIT

**触发条件**：
- 用户松开鼠标（定义完底面）

**数据变化**：
- StateComponent：SecondP已确定
- PreviewActor：流程状态 → EDIT
- PreviewActor：显示Gizmo

#### 任意 → HIDDEN

**触发条件**：
- 用户确认编辑（Enter键）
- 用户取消编辑（Esc键）
- 用户切换工具

**数据变化**：
- StateComponent：清空临时数据
- PreviewActor：流程状态 → HIDDEN
- PreviewActor：隐藏所有组件和Gizmo

## 五、Gizmo显示决策

### 5.1 双重控制矩阵

Gizmo显示由**编辑类型**和**流程状态**共同决定：

| 编辑类型 | 流程状态HIDDEN | 流程状态BASE | 流程状态EDIT |
|---------|---------------|-------------|-------------|
| **EditConstruction** | 隐藏所有 | **（跳过）** | 显示单体素预览<br>无Gizmo |
| **EditArea** | 隐藏所有 | 显示2D包围盒<br>无Gizmo | 显示3D包围盒<br>12个Gizmo |
| **PlaceFurniture** | 隐藏所有 | 显示2D包围盒<br>无Gizmo | 显示蓝图<br>6个Actor Gizmo<br>无面Gizmo |

### 5.2 组件可见性决策表

| 流程状态 | 编辑类型 | WireframeMesh | InnerMesh | BlueprintMesh | ThicknessMesh | Actor Gizmo | Face Gizmo |
|---------|---------|---------------|-----------|---------------|---------------|------------|-----------|
| HIDDEN | 任意 | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| BASE | EditArea | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ |
| BASE | PlaceFurniture | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| EDIT | EditConstruction | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ |
| EDIT | EditArea | ✅ | ✅ | ❌ | ✅ | ✅ | ✅ |
| EDIT | PlaceFurniture | ✅ | ❌ | ✅ | ❌ | ✅ | ❌ |

### 5.3 决策逻辑

```cpp
void AVoxelPreviewActor::UpdateGizmoVisibility()
{
    // 基础规则：HIDDEN状态隐藏所有
    if (PreviewState == EPreviewInteractionState::HIDDEN)
    {
        HideAllGizmos();
        return;
    }

    // 基础规则：BASE状态隐藏所有Gizmo
    if (PreviewState == EPreviewInteractionState::BASE)
    {
        HideAllGizmos();
        return;
    }

    // EDIT状态：根据预览模式决定
    if (PreviewState == EPreviewInteractionState::EDIT)
    {
        switch (CurrentMode)
        {
        case EPreviewMode::SingleVoxel:
            // 单体素编辑：不显示Gizmo
            HideAllGizmos();
            break;

        case EPreviewMode::SimpleGeometry:
            // 几何体编辑：显示所有Gizmo
            ShowActorGizmos();
            ShowFaceGizmos();
            break;

        case EPreviewMode::ComplexBlueprint:
            // 蓝图编辑：只显示Actor控件
            ShowActorGizmos();
            HideFaceGizmos();
            break;
        }
    }
}
```

## 六、数据流设计

### 6.1 工具切换流程

```
用户选择"几何体编辑-盒体"工具
    ↓
蓝图（输入检测）
└─ 调用 → InteractComponent
    ↓
【业务数据处理】
InteractComponent：
├─ 检测工具切换
├─ 清空之前的编辑数据
├─ 更新编辑类型：
│  └─ StateComponent->SetEditMode(EditArea) ← 业务属性
└─ 通知VisualUIComponent
    ↓
【渲染处理】
VisualUIComponent：
├─ 从StateComponent读取：EditArea
├─ 映射为预览模式：EditArea → SimpleGeometry
├─ 调用PreviewActor：
│  ├─ SetPreviewState(HIDDEN)
│  └─ SetPreviewMode(SimpleGeometry)
    ↓
PreviewActor：
├─ 流程状态 = HIDDEN
├─ 预览模式 = SimpleGeometry
└─ 隐藏所有组件和Gizmo
```

### 6.2 编辑流程（几何体）

```
用户点击第一个点
    ↓
蓝图（射线检测，计算体素索引）
└─ 调用 → InteractComponent->UpdateBatchEditPreview(VoxelIndex)
    ↓
InteractComponent：
├─ 存储FirstP（体素索引）
├─ 计算SecondP（初始等于FirstP）
├─ PreviewActor状态转换：HIDDEN → BASE
└─ 通知VisualUIComponent
    ↓
VisualUIComponent：
├─ 从InteractComponent读取：FirstP、SecondP
├─ 调用PreviewActor：
│  ├─ SetPreviewState(BASE)
│  └─ UpdateSimpleGeometryPreview(初始包围盒)
    ↓
PreviewActor：
├─ 流程状态 = BASE
└─ 显示2D包围盒
```

## 七、状态同步

### 7.1 同步规则

1. **编辑类型变更 → 流程状态重置**
   ```
   用户切换工具 → 清空编辑数据 → 流程状态 → HIDDEN
   ```

2. **流程状态变更 → Gizmo显示更新**
   ```
   流程状态变化 → 重新计算Gizmo可见性 → 更新Gizmo
   ```

3. **业务数据变更 → 预览更新**
   ```
   StateComponent数据变化 → VisualUIComponent读取 → 更新PreviewActor
   ```

### 7.2 避免状态不一致

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 编辑类型与预览模式不一致 | 映射错误 | VisualUIComponent统一映射 |
| 流程状态与Gizmo显示不一致 | 未触发更新 | 状态变更时自动触发更新 |
| 业务数据与预览不一致 | 数据未同步 | PreviewActor实时读取StateComponent |

## 九、设计决策

### 决策1：编辑类型是业务属性

**决策**：编辑类型属于业务属性，存储在StateComponent

**理由**：
- 编辑类型是用户选择的工具
- 属于业务逻辑的一部分
- 应该由InteractComponent管理

### 决策2：流程状态是渲染状态

**决策**：流程状态属于渲染状态，存储在PreviewActor

**理由**：
- 流程状态只用于控制渲染
- 不影响业务逻辑
- PreviewActor根据状态自主处理渲染

### 决策3：双重控制Gizmo显示

**决策**：Gizmo显示由编辑类型和流程状态共同决定

**理由**：
- 不同编辑类型需要不同的Gizmo配置
- 不同流程阶段需要不同的Gizmo显示
- 双重控制提供灵活性

### 10.1 状态管理实现

// InteractComponent处理编辑类型
void UVoxelControllerInteractComponent::SwitchTool(EVoxelControllerBuildState NewTool)
{
    // 清空当前编辑
    if (StateComponent->GetBuildState() != EVoxelControllerBuildState::OutBuildMode)
    {
        CancelEdit();
    }

    // 更新编辑类型
    StateComponent->SetBuildState(NewTool);
}

// VisualUIComponent映射预览模式
void UVoxelControllerVisualUIComponent::UpdatePreviewMode()
{
    EVoxelControllerBuildState EditMode = StateComponent->GetBuildState();
    EPreviewMode PreviewMode = MapEditModeToPreviewMode(EditMode);

    PreviewActor->SetPreviewMode(PreviewMode);
}

// PreviewActor处理状态变更
void AVoxelPreviewActor::SetPreviewState(EPreviewInteractionState NewState)
{
    PreviewState = NewState;
    OnPreviewStateChanged(OldState, NewState);
}

## 十二、与编辑系统的关系

### 12.1 服务定位

预览系统是**编辑系统的渲染辅助系统**，具有以下特点：

1. **独立系统**：预览系统有独立的业务边界和职责
   - 职责：渲染显示、状态管理、Gizmo控制
   - 不涉及：编辑逻辑、数据持久化、业务决策

2. **服务于编辑系统**：预览系统为编辑系统提供可视化能力
   - 响应编辑操作：根据编辑类型和状态切换预览模式
   - 实时反馈：显示编辑范围、选中区域、模板预览
   - 交互辅助：显示Gizmo控件辅助参数调整

3. **数据流向**：
   ```
   编辑系统（业务逻辑）
     ↓ 传递编辑请求
   预览系统（渲染反馈）
     ↓ 显示可视化
   玩家（视觉确认）
   ```

### 12.2 接口边界

**编辑系统 → 预览系统**：
- `FVoxelEditRequest`：包含完整的渲染数据
- 编辑类型（BuildState）：决定预览模式
- 几何描述（Geometry）：用于计算渲染位置和形状

**预览系统 → 编辑系统**：
- 可视化反馈：帮助玩家确认编辑操作
- 交互事件：Gizmo拖动等交互返回给编辑系统
