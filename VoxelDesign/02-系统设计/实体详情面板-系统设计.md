# 实体详情面板-系统设计

**最后更新**：2026-11-04

> 范围说明：详情槽支持经营实体、区域、生物（角色）、家具；经营实体与区域不是同一身份。本文定义经营实体及其空间卡的职责与字段映射，角色/家具复用槽位，具体卡后续补充。
>
> 建造组合创建的流程、原子集合与租约先行规则唯一信源见[区域店铺与商圈管理 §6.14](/VoxelDesign/02-系统设计/AI决策系统-区域店铺与商圈管理-系统设计.md)；本文件只负责详情卡展示与入口操作。

## 1. 系统上下文

### 1.1 系统边界

**负责**：

- 「当前选中实体」的状态管理（选中/清除/切换）。
- 右列实体详情槽的展示：随选中实体类型切换详情卡（区域卡先行）。
- 详情卡上的入口操作（编辑业务、装修此区域、父链上钻、子区域下钻、关闭）。

**不负责**：

- 区域业务数据编辑表单本体（「编辑业务」按钮的弹窗内容，另案设计）。
- 经营模拟数据的计算算法；详情只按已实现的实体/账户业务数据及查看权限展示，不从区域生成假值。
- 生物详情卡、家居详情卡的具体设计（后续按同模式补充）。
- 建造态工具参数面板（左列 ToolDetailPanel，已有体系，不属于本系统）。

### 1.2 外部依赖

| 依赖 | 用途 |
|------|------|
| 经营实体业务查询 / Global.BusinessEntities | BusinessEntityId 定位资料及类型组合模块，解析有效产权/经营关系、营业/合同/统计；无空间实体同样可查询 |
| UVoxelAreaWorldSubsystem / AVoxelAreaBaseInstance | AreaRef 定位场景空间；AreaBase只持空间资料、ParentArea/SubAreasIndex及高亮，不承载经营真值 |
| UConfigDataSubsystem | 区域类型 Tag 与业态 Tag 两个分类维度的显示名/图标；区域类型按空间作用分类，业态按经营业务分类，具体取值由配置资产决定 |
| UVoxelCreatureWorldSubsystem | 将业务解析的 CreatureId 转为角色显示名，不从区域复制 Owner/Manager |
| Controller / 业务门面 / ViewModel | 选中与业务入口收口、分别查询实体和空间、订阅事件映射展示（§4） |
| 主 HUD / EntityDetailSlot | 挂接共用详情槽，按经营实体/空间/角色/家具类型展示 |

### 1.3 输入输出

**输入**：

- 世界区域/家具射线点选与经营实体导航；生物仅非建造模式点选。选择状态与工具草稿独立，建造侧栏连续创建不因查看对象卡丢失；展示遵循屏幕分区的工具参数/对象卡切换。
- 详情卡关闭、空间父子导航、普通资料/装修等操作。
- 实体资料/经营关系/营业状态事件，以及空间范围/准入/移除事件；分别刷新相应字段。

**输出**：

- 共用详情槽按对象身份显示/切换卡；有有效 AreaRef 时空间高亮。
- 普通资料编辑传 BusinessEntityId 或子 AreaRef；有空间及有效授权时可进入装修，不把 AreaId 当 ShopId。
- 空间卸载只使其引用/高亮失效，不自动清除仍存在的经营实体详情或注销业务。

## 2. 核心概念

### 2.1 基础概念

**选中实体（SelectedEntity）**

跨模式的全局选中态，表示「玩家当前在看的对象」。经营实体 / 区域 / 生物 / 家具互斥，同一时刻至多一个。经营实体目标用 BusinessEntityId（03 逻辑类型 FBusinessEntityId，底层待定已定，见[总纲 §2.7](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)；不使用 `ShopId` 别名），区域目标用 AreaRef={SceneId,AreaId}；不得用一个整数 Id 混用两种身份。子区域有 AreaId 不是经营实体。与建造态工具 `CurArea`（UVoxelBuildStateComponent、绑定工具生命周期）是不同概念：

| | SelectedEntity（本系统） | CurArea（建造态现有） |
|---|---|---|
| 语义 | 我在看什么 | 区域编辑工具正在编辑谁 |
| 生命周期 | 跨模式，玩家显式清除 | 绑定工具激活期 |
| 驱动方 | 世界点击 / 详情卡导航 | 区域编辑工具射线 |
| 消费方 | 实体详情槽 | 建造预览、M13a 导航等 |

**实体详情槽（EntityDetailSlot）**

主 HUD右列共用详情槽，无选中显示空态，有选中按经营实体/空间/角色/家具身份切换。复用历史原型 v6Detail/v6-dcard槽位，不把原三卡结构当作目标身份限制；建造态按屏幕分区与工具参数切换，连续创建草稿仍由 Controller保留。

### 2.2 组合概念

**区域详情卡（AreaDetailCard）**

区域被选中时详情槽的内容，由四段组成：卡片头、父链面包屑、属性区、子区域列表 + 操作行（详见 §3）。

**父链上钻 / 子区域下钻**

详情卡内的导航行为：点击父链面包屑或子区域条目 = 把选中实体切换为目标区域。纯选中切换，不产生新模式、不改 Camera、不动建造状态。

### 2.3 行为概念

**选中（Select）**：世界点击命中区域 → 写入选中实体 → 广播 → 详情槽刷新 + 区域高亮。

**清除（Clear）**：✕ 按钮 / 点击空处 / Esc / 选中区域被删除 → 清空选中 → 广播 → 详情槽回空态 + 取消高亮。

**导航（Navigate）**：父链/子区域点击 → 等价于对目标区域执行选中。

### 2.4 概念关系

```
SelectedEntity (0..1)
   ├── BusinessEntityId → 经营实体卡（Global.BusinessEntities）
   │                       └─ 可选空间组件 → AreaRef → 空间字段/高亮
   ├── AreaRef → 空间卡（子区域仅关联现有主体，不新建经营实体）
   │              ├─ 空间父链 → Navigate(父 AreaRef)
   │              └─ 子区域列表 → Navigate(子 AreaRef)
   ├── Creature → 生物详情卡（后续设计）
   └── Furniture → 家具详情卡（后续设计，产权来源不由区域包含转移）
```

## 3. 区域详情卡设计

dArea/dSub是历史原型的空间卡划分，目标按经营实体 BusinessEntityId 与空间 AreaRef分别映射来源；空间父链只表达包含/导航，不按 ParentAreaId是否非空判断经营实体身份。子功能区只有空间身份并关联现有主体，经营实体可选关联真实空间。

### 3.1 布局

```text
详情槽（经营实体与空间卡共槽，不混身份）
 ├─ 名称/类型；仅营业实体显示派生营业状态
 ├─ 经营归属与有效产权人/经营人（只读，来自实体关系）
 ├─ 可选空间信息：AreaRef、范围/规格、准入约束
 ├─ 空间父链 / 子区域列表：只空间名称/功能类型，不显示子区域营业灯
 └─ 普通资料编辑 / 有授权且有真实空间时装修 / 关闭
```

纯子区域卡只显示空间资料与关联现有主体，住客入住不改变经营人；图外生意没有空间时不显示范围/定位/装修。

### 3.2 字段映射表

| 面板字段 | 数据来源 | 备注 |
|---------|---------|------|
| 图标 / 类型 | 实体读业态 Tag 配置；区域读区域类型 Tag 配置（按空间作用分类） | 两个分类维度各自独立，区域类型不作为经营身份 |
| 名称 / LOGO | 经营实体资料；子区域读空间名称 | 不从 AreaBase 复制经营资料真值 |
| 状态 | 实体营业模块 bOpen + 纯派生 bOperating | 非营业实体/子区域不显示；默认 bOpen=false，停业/打烊/运营中按 bOpen 与时段判定 |
| 范围 | 可选空间组件 AreaRef 对应区域覆盖 | INDEX 空间，无真实空间不显示 |
| 规格 | 对应空间 Coverage.BoundingBox() 尺寸 | 仅有 AreaRef 时显示 |
| 经营人 | 实体当前有效经营关系解析 CreatureId → 生物显示名 | 只读，不存区域 Manager；住客不是经营人 |
| 产权人 | 实体有效产权/授权关系解析 CreatureId → 生物显示名 | 只读，不存区域 Owner，不因空间父子转移资产 |
| 空间准入 | 区域准入约束 + 有效授权查询 | 公开/战斗约束不授予经营权；门不用客房 Manager 钥匙 |
| 子区域列表 | AreaActor->SubAreasIndex（图标、空间名称/功能标记） | 仅空间导航，子区域无独立营业状态 |
| 空间父链 | AreaActor->ParentArea，导航传 AreaRef | 不等同经营实体 ParentBusinessEntityId |
| 经营归属 | 实体 ParentBusinessEntityId / 有效经营关系 | 不由空间包含或区域父链生成 |

### 3.3 原型字段裁剪说明

原型字段按业务数据是否实现与有效查看权限裁剪，不能以区域字段不存在否定经营实体模型，也不能从空间父链推导经营归属。

| 字段 | 目标来源与显示边界 |
|---------|---------|
| 资金 / 营收 | 人物持有的业务账户与实体经营统计；初始两钱包人物持有，未落地的 UI绑定不展示假值 |
| 满意度 / 客流 / 声誉 | 实体对应组合模块，不镜像到区域；按有效查看权限展示 |
| 所属商圈 | ParentBusinessEntityId / 有效经营关系，不以 ParentAreaId 代替 |
| 自营 / 承租 / 薪酬 | 当前有效经营关系 / Lease / 任命，只读展示 |
| 深入调查 / 抢客策略 | 非本次范围，不作为 V1 新能力 |

未实现字段不做假占位；本文是目标设计，不宣称模型绑定或原型已迁移。

### 3.4 操作按钮

| 按钮 | 行为 | 说明 |
|------|------|------|
| 编辑业务 | 打开既有普通资料表单，经营实体传 BusinessEntityId，子区域传 AreaRef | 只改名称/LOGO或允许的子区域空间类型；不承担创建时补建生意，合同另走专用业务 |
| 装修此区域 | 有 AreaRef 且有效授权时进入建造并定位空间 | 走 Controller 业务门面；无真实空间不提供，租户实物写入须已有有效 Lease |
| 关闭 | 清除选中 | 等价于点击空处 / Esc |

### 3.5 空态

无选中实体时，详情槽显示空态提示（虚线框 + 引导文案，如「点击世界中的区域查看详情」），对应原型 `v6-iempty`。

## 4. 选中链路设计

### 4.1 数据流（单向数据流，铁律合规）

```
世界点击（任何模式；与建造态工具流程并行）
  → 射线检测按「生物 > 家居 > 区域」优先级命中精确目标
    （生物仅非建造模式检测；家居=ECC_GameTraceChannel2，区域=ECC_GameTraceChannel3）
  → Controller选中业务（BusinessEntityId / AreaRef / 对应对象引用分别表达，不混为整数ID）
  → 选中状态组件写入（变化才广播）
  → OnSelectedEntityChanged 广播
  → 订阅方各自刷新：
      ├─ 实体详情槽：重建/刷新区域详情卡
      └─ 世界高亮：UpdateAreaVisual(isSelected)（新选中高亮 + 旧选中恢复）
```

规则：

1. 输入层调用 Controller 选中业务，经营实体目标传 BusinessEntityId，空间目标传 AreaRef；清除走 ClearSelectedEntity，禁止直写选中状态。
2. 空间父链/子区域导航只换选中 AreaRef，不创建或绑定生意；经营主域切换按实体有效关系另走业务。资料/装修/合同操作经 Controller→业务门面→相应存储→事件→UI。
3. 数据查询按源分开：经营资料/Owner/Manager/bOpen等读取实体业务，范围/父子/准入约束读取空间业务，由 ViewModel 映射给 Widget，不从 AreaBase 取经营真值。

### 4.2 选中状态归属

PlayerController上的选中状态与建造 CurArea/草稿解耦。目标区分 BusinessEntityId、AreaRef、Creature/Furniture引用，不使用统一整数经营/空间 ID。变化经 OnSelectedEntityChanged 广播，具体 class/接口划分待架构实施确定。

### 4.3 清除条件

| 触发 | 行为 |
|------|------|
| 关闭 / 世界空处 / Esc | Controller清除选中，事件刷新 |
| 选中空间被删除/卸载 | 清除空间选中与高亮，不注销其关联经营实体 |
| 经营实体的关联空间被删除/卸载 | 实体详情仍可存在，仅空间字段/定位失效；具体删除注销规则待定 |
| 点击另一对象 | 按目标身份切换选中 |

### 4.4 与建造态的关系

- 进入建造不清空选中，空间装修依有效 AreaRef及授权定位；独立 CurArea不写经营选中身份。
- 建造检查器遵循工具参数/对象卡二选一，不在同边角重复挂面板；组合创建草稿保留在 Controller状态，同侧栏可继续完成采集与一次确认，不要求详情补建生意。
- 区域导航与实体注册分开，不能通过空间选中自动绑定业务。

## 5. 设计原则

### 5.1 架构原则

- 严格遵守单向数据流铁律：UI 只调业务方法，刷新只走广播订阅，3D 高亮与 2D 面板互为平级订阅方。
- 选中状态唯一归属，详情槽只订阅不持有。

### 5.2 接口设计原则

- 详情目标按经营实体 BusinessEntityId 或空间 AreaRef 分别传递；不硬定统一 ID 底层类型或具体 class。
- 查询经 ViewModel映射，写入经 Controller/业务门面收口（§4.1）。

### 5.3 数据管理原则

- 不缓存业务真值副本；实体事件刷新经营字段，空间事件刷新覆盖/父子/准入，不从 AreaBase 读经营资料。
- 区域删除/卸载只使空间引用与高亮失效；经营实体详情可继续存在，具体注销规则待定。
- 住客仅限时使用者，不变更客房 Manager；权限及区域门按有效授权查询，不靠空间包含取得资产。
- bOperating=bOpen&&有效时段 纯派生，bOpen仅手动且入档，无自动资格复检；初始两钱包/业务账户人物持有。

### 5.4 扩展原则

- 多类型共槽互斥，经营实体与区域身份独立；角色/家具复用槽位。V1只预置商圈玩家标准租杂货店，NPC空店/模板邀请同一连续面板确认候选同意条款和产权授权，先 Lease再真落位；完整 NPC模板招商/客房后续。
- 换租户沿用同一经营实体、删区域不注销实体（已定）；招图外换工待定，不新增猜测性方案。

## 6. 范围界定

### 在范围内

- 经营实体与空间卡布局、字段来源、普通资料/空间装修入口。
- 选中链路与建造态 CurArea 的区分；组合创建不跳详情补建生意。

### 不在范围内

- 生物/家具具体卡、普通资料表单控件本体、经营模拟算法。
- 深入调查/抢客策略，以及具体 class、蓝图结构或代码实施。
