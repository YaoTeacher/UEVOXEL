## 2. 核心概念

### 2.2 NPC 个体数据模型

**角色是时段属性，不是身份属性**：员工/顾客是同一 NPC 在不同时段扮演的角色，不存在"员工 NPC 类"和"顾客 NPC 类"。

**FTrueCreatureData 扩展**：

| 字段 | 类型 | 说明 |
|------|------|------|
| ActivityWillingness | TMap<需求Tag, float[0,2]> | 品类消费意愿 |
| Expectations | TMap<AspectTag, FExpectationBand{Min,Max}> | 评价尺子（见第 6 章） |
| KnownShopIds | `TSet<BusinessEntityId>` | NPC自己持有，只记录知道这家店铺生意，而非旧Area；重复写入幂等，不保存强度、锚点、最后到访时间，不做遗忘或容量淘汰。完整认知条目留后续扩展 |
| 两类账户引用 | 个人钱包 / 唯一经营账户ID | 每个实际 / 抽象人物创建时两类账户都建立，非经营者也有；所有生意共用经营账户 |
| 收支统计字段 | （占位） | 供职业流动/储蓄统计使用 |

经营资产与业务唯一归 Global `BusinessEntities` 中的经营实体，商圈 / 店铺 / 图外生意共享基础模型并按类型组合模块。经营实体持产权 / 经营关系、营业意图 / 日程、目录 / 定价 / 订单 / 预留、声誉 / 客流；区域只空间与校验，不持业务镜像。身份类型与分工见[总纲 §2.7](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)与[区域店铺与商圈管理 §2 / §9](/VoxelDesign/02-系统设计/AI决策系统-区域店铺与商圈管理-系统设计.md)；空间定位用 `AreaRef={SceneId,AreaId}`。子客房 / 仓库不是经营实体，抽象雇主不造假区域。真实库存、工作点 FIFO 与门锁在对应实例，区域看板为不入档派生索引。

初始顾客钱包取配置，不在本卷设金额。大多数NPC持图外真实工资合同，合同雇主为 `EmployerBusinessEntityId`，工资到个人钱包；图外雇主为抽象账户（`bAbstract=true`，不计余额），支出直接发生、不补资（03A §5.9）。无有效合同且无其他实际收入时真的没钱，不按职业 / 阶层定期补钱。招聘只取无有效合同者，图外合同也有效，不加换工或吞合同政策。

**复用现有字段**：
- PersistentBasicValues（个性）
- TraitTags（爱好）
- 个人记忆条目（FLifeHistoryEntry 扩展，见《AI决策系统-记忆模型-系统设计.md》）+ 关系 entry（见《AI决策系统-关系系统-系统设计.md》）

**HomeAreaRef 语义定为"住所"**：
- 普通居民（V1）→ `HomeAreaRef={SceneId,AreaId}` 直接定位其抽象住所对应的实际SpawnArea进出点；它是主地图空间，不是图外雇主假区域。进图从该点刷出，回住所返回同一点，实际到达并离场后按§2.2结算，不新增住所配置表、抽象住宅区域或二级绑定；
- 住店（后续、V1不生成）→ Home空间由旅店住宿模块的StayRecord更新到 `RoomAreaRef`；客房是子空间，客人不是Manager，不得取旅店经营ID作Home。退房结束住宿授权 / 占用、更新Home空间并产生有清洁工作授权的需求；结算费率与出入隐私策略待住宿专项冻结，定金 / 尾款沿预订规则。
- 定期来客 / 一次性游客（"外来 NPC" 专指此类；完整版本来源，V1 不生成）→ 从城门等 SpawnArea 直接出场，消费/停留后原路离图
- 以上皆无 → 不刷出
- 员工归属**不用** HomeAreaRef，实际工作区域走劳动安排（`FWorkAssignment.WorkAreaRef`），合同与工资关系走雇佣记录（见 §11.2（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)））

**住所分两类（交互深度不同）**：
- **抽象住所**（普通居民）：住所只是一个 Spawn/离场标记点（图外住所直接挂主地图出入口），不挂任何设施、不做实际交互。居家低耗态 = 走回住所点消失回收；V1 NPC **实际到达并离场时**一次补满 6 条需求与 Mood / Health / Hygiene / Comfort，Loyalty 不恢复。V1 不根据图外经过时间补算需求或运行图外日程；起床 / 出门时从该点按名册保存的需求 / 状态与当前日程刷出，住所不出现在商业设施评分候选里。
- **实体住所**（后续版本；旅店客房 + 店主/员工居住区域）：实际设计的区域，摆真实家具设施（床等，能力由家具功能片段声明），睡眠与居家行为走真实流程（ Goto 床 → Advance 自驱回填精力）。V1 不开放这些区域，名册中的普通居民与员工统一走抽象住所。

**生成画像（NPC 生成时一次 roll 定，运行时只读）**：
```
意愿 / 期望 = 职业基准 + 9 维倾向 + 特质修正 + 个体噪声（阶层已化约删除，见《AI决策系统-基础层模型-系统设计.md》§5；生成填充公式见该文 §5.4）
```
噪声必须存在：同职业、同钱包的 NPC 要求也互不相同，这是"推测客人"玩法的信息量来源。

### 2.3 日程系统（三层叠加）

**第 1 层：周节律模板**
- 24 小时 × N 天的时段表，周期长度由时间系统配置（不绑定 7 天/30 天——幻想历法）
- 每格填活动意图：`Sleep` / `Duty`（引用本人劳动安排的 `WorkAreaRef`）/ `Free` / `Anything`
- 由种族/职业模板生成 + 个体扰动
- 是**权重偏好层**不是强制脚本：Duty 提高工作子树权重，Work 块最高；Anything 也允许工作，只是工作权重较低。吃饭 / 使用由需求驱动且优先级高于工作，Dine 只调权重；需求与硬生理极限可压倒模板

**第 2 层：日历覆盖层**
- 一次性代办日程：`FAppointment{触发(时间点或事件Tag), ActionTemplate, Deadline/GracePeriod, RelatedOrderId}`，覆盖当天模板
- **FAppointment 语义是"代办日程"（义务/待办事项），不是社交约会**——日程上挂着的一件待办，有触发条件（到点/事件）和期限。典型：定制订单下定金后休眠 → 订单完成事件唤醒 → 到店验货付尾款
- 逾期未办 = 超宽限期仍未完成（不称"爽约"）
- 节日/事件日整张替换模板（本版只留占位，后续版本实现）

**第 3 层：需求微观填补**
- 时段只决定"在哪、什么角色（RoleContext）"
- 具体行为由需求 + 决策产生

**玩家自主行动复用同一路径**：
- 实际自主条件为 `bAutonomyEnabled && !bManualOverrideActive`；开关默认关闭并随角色存档，直接操控只产生临时接管状态，不改写开关。
- 条件成立时，玩家同样按日程切 RoleContext，由需求、候选过滤、评分和 `FFlowState` 驱动 Duty 工作、Free 生活与 Sleep 睡眠，不另建玩家生活 AI；功能范围仍受当前版本统一限制，不为玩家单独提前开放后续能力。
- 自主消费从玩家个人钱包按普通 NPC 规则自动支付，不逐笔询问；余额、价格、库存等检查相同，不赊账、不透支。
- 直接操控优先于普通自主决策，按统一原子步骤 / 结算边界中断；结束接管后从当前位置和状态重新决策。自主关闭只停止自动决策，不停止需求、硬生理极限、时间与结算。

**出场规则（唯一刷新判据，事件驱动不轮询）**：
```
无激活时段         → 不在图 / 回收对象池（零计算）
有激活 + 不在图    → 按 2.2 出场点分层判据刷出（V1 仅从抽象住所 / 地图边缘 SpawnArea；客房与外来 NPC 留后续），通勤到目标
有激活 + 在图      → 切换 RoleContext，触发重决策
```

**结伴出场**：同住所且高亲密关系、时段重叠的 NPC 概率性作为一个团体一起刷出（"一家人出门 = 一起进图"），团体关系从刷出时即成立（团体的行为语义见 §8.7（[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)））。这是团体的两个来源之一，另一个是场内面对面邀请——不存在远程邀请（被邀者不在图则无响应通道）。

**RoleContext（时段角色上下文）**：

| RoleContext | 决策方式 |
|-------------|---------|
| Duty | 员工决策（优先级表 × Priority 分带两层扫描，见 5.4） |
| Free | 消费者决策（Utility 加法核，见 5.3） |
| Sleep | 居家低耗态（V1 普通居民与员工：回抽象住所点消失回收，实际离场时按 §2.2 一次补满需求与指定生活状态，Loyalty 不恢复；实体住所真实睡眠流程留后续版本） |

**图外抽象雇工**：按真实合同与工资条款抽象结算，`EmployerBusinessEntityId` 指向图外经营实体，实际 `WorkAreaRef` 允许不存在；工作不生成Actor、工单、寻路或设施操作，不开启图外生活模拟。场景未加载与抽象工作不同：有实际工作空间的合同保留原 `WorkAreaRef`，不能因场景未加载改成抽象雇主或虚构区域；V1不新增未加载场景的劳动执行方案。是否在图不决定有没有合同或工资，失业无其他收入仍为0。

**RoleContext 延迟生效**：时段切换只打标记、不强制换脑——变更在当前 Job 自然结束时生效，仅 Critical 需求/外部强制事件可提前引爆重决策。消除"角色已切但还在干旧活"的状态分裂。

**饭点/高峰涌现设计**（不硬编码"几点吃饭"，靠多因子错峰涌现）：
- 起床窗口按种族/职业/个体扰动分散，不做全局对齐
- 饥饿衰减调参（起床后 4-5 小时过阈），起床时刻分散 → 过阈时刻自然分散
- TimeMod 饭点窗口加成只作软引导，不作全局同步信号
- 个体扰动（扰动窗口取宽，避免到峰时刻对齐）
- 设计意图：高峰存在（饭点生意是经营内容），但需求到峰时刻被多因子打散，避免同一时刻全员同一需求造成服务系统共振

### 2.5 行为概念

**决策触发与队列维护模型**
```
事件驱动，无周期轮询：

需求按游戏时间增量变化并跨阈值（Urgent 或 Critical，由 UpdateDynamicAttributes 在固定逻辑 tick 内检测后发射）
当前 Flow 完成 / 失败 / 排队离队 / 资源失效
日程时段切换（RoleContext 变化）
代办日程触发（到点 / 订单完成等事件 Tag）
区域看板新任务通知（Duty 时段）
外部事件（被攻击 / 强制指令）

事件只携带事实，并把相关角色标记为需要裁决，不直接生成 / 更新 / 完成 / 取消目的。
最外层事件及其级联处理结束后，裁决器统一维护目的并整理队列：
  新增或更新目的 → 判断完成 / 取消 / 失效并删除 → 建立执行组合并关系 → 排序
主槽空时直接派发队首；次槽派发相容执行组，不在槽位释放时重新评分整个队列。

不因普通新意图打断当前 Execute 段；它仍可参与待执行队列整理。
无激活时段 → NPC 不在图，零开销。
```

**决策独立性原则**：每次队列裁决的排序只基于当前环境和未执行目的重新评估，不继承上次决策的偏好，不预设任何候选。环境变了（店铺打烊/队列变长/库存变化），下次裁决自然读到新状态，无需专门的"排除上次选择"机制。

**决策递归护栏**（事件驱动不失控的三条规则）：
```
1. 裁决通知只在同一最外层事件事务内按 NPC 去重，事务结束后统一运行裁决器；
   去重通知不合并目的，不限制独立事务在每 Tick 的次数，不在原子结算中途递归维护目的或派发
   （覆盖顺序：硬生理极限 > 外部安全事件 > 玩家指派 > Critical 需求 > 当前执行 > 普通新目的，
   完整序列见 §11.9（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)））
2. 连续失败计数器：任何节点成功完成或需求被回填即清零；达 N 次走兜底链（见 5.5）
3. 级联上限：单次事件事务最多级联 3 次队列整理，之后强制兜底并记录调试信息
```

失败候选不写冷却降权：决策独立，失败时环境已变（打烊/售罄/满员），下次决策按当前环境自然过滤；仅排队主动放弃保留当日候选冷却（防门口反复徘徊，见 5.5）。

**Critical 强制覆盖**

V1 员工在其工作 Shop 区域内不会因自然时间或工作动作继续降低需求，因此不会由上班过程产生新的向下跨阈；入店前已经存在的 Critical 仍按下列规则中断，冻结工作区下降不会清除它。

```
任一需求达到 Critical 阈值时:
- 员工决策: 可压制 Critical 需求优先于一切工单，立即放下手上工作；被撂下的顾客由等待段机制接管（见下）。容忍窗内可"做完当前原子步骤再走"（§11.7，[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)）
- 消费决策: 硬过滤的价格上限放宽（饿极了贵的也吃）；后续版本的负面记忆修饰下限才可放宽（恨意打折但不忘），V1 无个人记忆输入
- 强制打断只发生在原语段边界（节点骨架见 §8.2（[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)））：自驱段按节点合同结算允许的效果；V1 商品 `CheckoutSale` 任一步失败都整笔不支付、不扣货、不入包，服务驱等待段直接离开并走放弃分支
- 员工被打断时手上工单按 bPausable 处理（§11.7，[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)）：可暂停 → 进度留存；不可暂停 → 未完成原子段进度按规则清零、工单认领释放、工单回池
- 硬生理双阈值（精力等生理硬限，完整优先级序列见 §11.9（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)））:
  Critical 线（低于下限）→ 仍可行动：触发紧急睡眠 Job（最高优先级，时段无关），
    实体住所 NPC 通勤回床（后续版本）/ V1 普通居民与员工回抽象住所点消失抽象睡眠；可被玩家指派压制（"面露难色"，后果玩家承担）
  清空线（归零）→ 断片昏厥：已丧失行动能力，不可寻路、不可压制——原地昏厥 + 定时苏醒 + 负面记忆 + 外化；
    通勤途中耗尽 → 半路昏厥（合法模拟结果，街上躺人是"压榨员工"的可见后果）
  寻路故障只报错，不转化为任何玩法行为（bug 不伪装成涌现）
```

**Execute 阶段重评估规则**
```
不重评估:
- 同一需求的其他候选（不换餐厅）
- Urgent 级别新需求（等当前节点完成）

强制打断:
- Critical 新需求（吃饭中途上厕所）
- 外部强制事件（被攻击/着火）

打断处理（不同中断带来不同后果，先归因再走对应路径）:
  ① 归因四类: 自身原因（自己的其他需求跨 Critical，如吃饭中途上厕所）/ 店铺原因（服务失败、等待段破底）/ 环境原因（灾害等；门外未进店者打烊白跑另按服务组例外上报一次负满意度）/ 社交中断（被他人打断互动）
  ② 结算后果（四类通用）: 按实际进度应用当前节点效果；支付、取货和所有权按各业务节点已完成事务结算，不由通用中断逻辑擅自按比例扣款；释放当前预留资源
  ③ 评价后果: 一般店铺原因产生负面服务样本，自身与环境原因不追责；打烊门外未进店白跑是例外，一次负满意度样本只写服务组、不计来访成交客群。社交中断后续按互动规则产生双方事件；V1不启用个人记忆链
  ④ 流程类 Job 记录断点（节点 i + 原语段 j + 子进度 k，骨架见 §8.2（[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)）），可休眠持久化
  ⑤ 触发紧急决策
```

**执行槽位结构（主槽 + 次槽 + 子动作）**
```
裁决器输出的是已排序的待执行目的与执行组，执行层按槽位派发：

意图队列: 保存尚未执行的目的，不设固定数量上限；事件只携带事实并触发裁决器。
           裁决器统一新增 / 更新 / 完成 / 取消 / 删除目的，并排序、建立执行组合并关系。
           合并只关联 PrimaryIntentId / CoveredIntentIds，不删除各目的完成条件。
           玩家指派按覆盖规则插入；队列容量与主 / 次槽执行资源分开。
主槽:     直接推进主行为链，执行项同时保存主目的、覆盖目的、FlowState 和资源占用。
           主槽空时取队首执行组，校验前置条件并绑定 Flow，不再做一次裁决。
次槽:     派发与主行为相容的次行为链，也保存对应目的和 FlowState——
           边吃边聊、排队看表演、工单执行中被顾客搭话；各行为独立结算效果。
           每个交互声明位置 / 座位 / 手部 / 注意力等级与相容标签，
           资源不冲突才可入槽；主行为变化导致冲突时按次行为自身规则退出。
子动作层: 主交互内部的轻量加权随机（反应、闲聊、小动作），
           不占槽、不过决策层，是"生活感"的直接来源

被打断: 按归因产生后果（见上）并上报结果事件，由裁决器判断未满足目的的更新、保留或回队，再按队列与覆盖规则处理
```

主槽 Flow 完成不等于所有关联目的完成。成交后由消费者购买行为方法根据其需求、性格、特性与购买上下文结算 Shopping、Mood 等体验，之后使用食物的基础作用才满足 Hunger；次槽聊天产生的 Social 效果同样交由裁决器判定 Social 目的是否完成。单次 Flow 失败只结束本次尝试并上报结果，由裁决器决定未满足目的保留、更新或回队，不随主行为一起被误判为完成或永久失败。

购买清单还受私人背包的实际可放置结果约束：V1 使用固定槽位，每槽只引用一个 ITEM 堆实例，其实例 `Quantity` 不得超过静态 `MaxStackCount`；不同品质不共堆，同种兼容物品允许存在多个未满槽且空槽随时可用。Browse 只形成能整单放入的 1～3 件清单，收银时按实际源堆状态重新生成计划并原子入包；这只是候选清单的可行性与履约条件，不改变目的裁决和主次槽规则。详见[库存与保质期 §2.2](/VoxelDesign/02-系统设计/AI决策系统-库存与保质期-系统设计.md)。

**服务等待段（统一等待模型，并入期望带）**
```
任何节点进入"阻塞等待外部服务"状态（排队前进 / 等工单履约）即开启等待段
（QueueAt 只是它在排队场景的标准实例，节点骨架见 §8.2（[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)））:

  ① 等待体验值随时长衰减，减缓因子按场景配到节点:
     站排=等待区节点静态 Comfort 配置（QP.Comfort，非 Creature.State.Comfort）；坐等上菜=用餐区 Luxury/Environment；引导员在岗减速（§9.7，[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)）
  ② 跌破预警线（Expectations[Service].Min + 预警边距，节点可配）:
     → 触发投诉事件（突发状况口子，《AI决策系统-事件系统-系统设计.md》§10）+ 外化演出（敲桌/看表/招手，16.2）
     → 关联工单 Priority 提升到紧急带（顾客催单自然插队，复用分带扫描）
     → 玩家/店主可介入安抚，消掉本次负面记录
  ③ 跌破 Expectations[Service].Min → 按承诺程度三分支放弃:
     未承诺（未下单未付钱）→ 离队/离店 + 轻负面记录（§7.6，[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)）
     已承诺未支付 → 起身离店 + 差评；V1 商品在 CheckoutSale 原子成功前没有已履约交付，故不支付、不扣货、不入包并释放预留；后续可分次履约服务才可按自己的节点合同 PartialSettle
       + 作废关联工单（顾客离场 = 发起方取消，§11.7（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)）回池原则的例外；后续服务的半成品记库存损耗，V1 杂货商品链不产生半成品）；等买单阶段破底 = 跑单
     已支付（预付/定金）→ 离店 + 自动退款 + 差评（权重更高，店违约在先）
  ④ 放弃后写当日候选冷却（仅限排队主动放弃，防门口反复徘徊入队；决策本身独立，不因失败历史降权，见 2.5）→ 触发重决策
  ⑤ 一次消费多段等待：Service 维度按时长加权平均上报 FExperienceReport；
     任何一段破底 → 本次消费 Service 单独记负面（服务失败主导评价）

估算等待统一入口（评分与等待中重估调同一函数）:
  估算等待由队列长度、单次使用时长与服务点并发推算
  防蜂拥: 评分读队列长度用信息快照（低频刷新）+ 个体估算抖动
```

**角色统一性**
```
店员和顾客是同一 NPC 在不同时段的 RoleContext:
  Duty 时段: 员工决策（优先级表 × Priority 分带），统一雇佣记录决定 Shop 或商圈雇主，排班与工作优先级读 Creature 上的劳动安排
  Free 时段: 消费者决策（Utility 加法核评分）
  Sleep 时段: 居家低耗态
  Critical 个人需求: 任意时段都优先

无身份切换逻辑，时段切换即角色切换
```

**兜底行为链**
```
无高分消费候选 → 闲逛（自驱游走：不依赖任何设施，向可达随机点移动，天然不会失败；
                Leisure 需求的合法满足途径，正常行为非异常）
连续 N 次候选失败 → 回家（居民）/ 离场（游客经 SpawnArea 离图）——防"鬼打墙"的总出口
全需求满足     → 回家（V1 普通居民与员工回抽象住所点消失；后续实体住所 NPC 回居家流程，可被对象池回收）

无"空闲超时"字段——兜底语义由 闲逛 → 回家/离场 链自然接管
```

## 5. 决策架构（三段式）

RoleContext 把 NPC 的决策分流为三段：Duty → 员工决策（5.4），Free → 消费者决策（5.3），Sleep → 居家低耗态。消费决策在评分前先过硬过滤漏斗（5.1）。

### 5.1 硬过滤漏斗（绝对约束，不进评分）

**认知边界（NPC 信息可得性规则）**：
- 远程可知：店铺类型 / 价位档（当前已上架商品相对物品基础价 `Value` 的平均 `PremiumRate`，即时派生的模糊消费水平，V1 不依赖个人记忆推算）/ 营业状态 / 队列长度（QueueFactor 预估依据）
- 到店才知：具体商品目录 / 实时库存 / 精确价格（在 Browse 节点揭示，见 §8.6（[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)））

```
① 营业状态: 读取经营实体纯派生 bOperating（= bOpen && 当前有效营业时段）；不复检设施、不入档，人工开业保留业态必需设施校验，运行期缺设施不系统关店
   （设施可用状态管店内具体功能点——占用/维护槽/库存派生，不管整店）
        ↓
② 认知: KnownShopIds 命中（NPC 不知道这家店就不会去）
        ↓
③ 价位档: 店铺平均 PremiumRate ≤ Expectations[Aspect.Price].Max
   （按 NPC 对该店的模糊认知判定；Critical 需求时上限放宽；
     期望带方向倒置时此处过滤下限，见 6.1 Direction）
        ↓
④ 时段预算: 估算往返通勤时长 > 当前时段剩余 → 候选出局
   （纯赶路什么都消费不了，属绝对约束；通勤估算复用 IsPathReachable 预估。
     "来得及但会迟到/熬夜"不在此过滤，走 5.3 的时段紧迫柔性衰减——保留涌现）
        ↓
【占位】节日/信仰/禁忌: 未来按其语义逐个定性为过滤或因子后接入，本版不实现
```

### 5.2 认知增长机制

**V1 的 `KnownShopIds` 只有三个写入来源：**

1. **开局老店预设**：世界生成时把老牌店铺写入附近居民认知。玩家在开局后新建的店铺不追溯套用这一步。
2. **简化路过发现**：NPC 实际路过店铺时，按店铺既有发现范围与招牌配置做业务距离判定，命中则写入店铺 ID。该路径不接完整感知、目击解读、图外流量池或记忆系统，也不由声誉动态生成知名度半径。
3. **交易完成**：`Shop.CheckoutCompleted` 把成交店铺写入买家认知；即使该次交易来自测试或特殊指令，也只写认知集合，不创建个人记忆。

V1 不通过广告触达、口碑记忆或 NPC 间传播写入认知。路过发现是普通认知来源，**不是首客保护**：不做开业全量写入、公共目录替代、强制首客或额外客流保护，不保证新店一定被发现或成交。

**V1 认知结构就是NPC所有的 `TSet<BusinessEntityId>`：**集合命中即知道这家店铺生意，重复写入幂等。空间改挂不改变经营ID或重写集合；路过距离判定与消费导航另经经营实体区域组件取得实际 `AreaRef`，不把AreaId当认知键。V1不保存强度、锚点、最后到访时间，不做遗忘、概率移除或每品类槽位淘汰，不添加占位字段，存档直接保存集合。

完整版本可在后续把集合扩展为带强度与时间的认知条目，并接回广告触达、记忆传播、图外感知和衰减规则；这些不是 V1 的运行或验收内容。

**V1 读档恢复**：名册按 CreatureID 恢复需求／状态、生活日程、位置、KnownShopIds、固定槽位背包和决策断点；背包槽位只解析物品子系统已恢复的稳定 ItemInstanceId。目的、执行组和 Flow 使用稳定 ID 重连；候选冷却保存下一游戏日界绝对 `GameTimeSec` 并随游戏时刻原值恢复，连续失败计数直接恢复；移动阶段业务计时按游戏秒保存并随游戏时刻恢复，不用现实秒或新进程时钟重算。读档不重放需求、进店或成交事件，不重写认知。完整顺序见 [AI 决策系统架构 §7 存档](/VoxelDesign/03-架构设计/AI决策系统-架构设计.md)。

### 5.3 消费决策（Utility 加法核评分）

Sims needs-based AI 结构，随机效用理论背书。评分分三层（具体公式与参数属数值设计，本大纲只定逻辑结构）：

**候选收集的三个来源**（收集后统一过硬过滤漏斗 5.1、统一评分，互不特殊）：
1. **触发需求品类过滤**：触发需求决定候选品类（性能优化，不独占评分）
2. **Remedy 诉求**（《AI决策系统-需求与状态层-系统设计.md》§4）：身上带着有 Remedy 的 BuffTag/记忆锚点 → 能提供该 Remedy 的店铺/服务者纳入候选（买药/求医/洗浴/找侦探皆此通道）
3. **代办日程注入**（§8.4，[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)）：到点/事件触发的 FAppointment 注入候选，含**委托准备**（出城委托 → 注入"备齐装备/补给"候选——目标前的准备行为走此通道）

1. **加法核**：需求强度、店铺质量、品类意愿、次要回填四个分量加权求和合成基础分——加法结构，分量间可互相补偿（便宜补远、急需补次）；评分是全动机的，触发需求只决定候选品类过滤（§3.2，[总纲](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)）
2. **全局衰减器**：距离与排队压力两个乘性衰减——对基础分整体打折但永不为零；**不参与加法核补偿**（需求强度不能完全抵消距离与排队压力，调参时不得按"可补偿"理解这两维）
3. **修饰器**：性格/角色/时段/天气/记忆/客群/情绪/社交驱动一组独立乘性修正，中性值不产生影响，可上调也可下调

**加法核分量**（可互相补偿——便宜能补远，急需能补次）：

| 分量 | 输入 | 说明 |
|------|------|------|
| NeedScore | 需求当前值 + 阈值 | 沿用需求衰减曲线差值（非线性衰减，越低越急） |
| QualityScore | 功能品质与店铺有效声誉 | V1 读服务组五项总体声誉（贝叶斯收缩）；纯店铺层统计，不掺个体记忆。完整版本的个体偏差入口 MemoryMod 在 V1 固定为中性值 1 |
| WillingnessScore | 品类意愿与价格在期望带内的位置 | 价格位置读 Expectations[Price] 带 |
| SecondaryFillScore | FunctionFragment 声明的次要需求回填 | 候选对触发需求之外的需求回填量，低权重奖励项——餐厅 = Hunger 主 + Social/Leisure 次，让"边吃饭边社交"在一次决策里完成，行为链不再单目标碎片化 |

**全局衰减器（乘性，只减不增，永不为零）**：

| 因子 | 输入 | 说明 |
|------|------|------|
| ProximityAtten | 路径距离 | 距离柔性衰减——"远"是"不太愿意"而非"绝不"；不可达在硬过滤/候选收集阶段已剔除 |
| QueueFactor | 估算等待 vs Expectations[Service] 底线 | 预估排队压力；估算等待由队列长度、单次使用时长与服务点并发推算（与等待段实判同一入口，见 2.5）；读信息快照（低频刷新）+ 个体估算抖动，防蜂拥 |
| TimeBudgetAtten | 估算总耗时（通勤+排队+消费，均复用现有估算入口）vs 时段剩余 | 时段紧迫柔性衰减——剩余时间越不够，分数越低；"为吃顿好的晚睡/迟到"的涌现保留。纯赶路超时已在硬过滤④出局，此处只管"来得及但会超时段" |

**修饰器（乘性，中性值不产生影响，可上调可下调）**：

| 因子 | 输入 | 说明 |
|------|------|------|
| PersonalityMod | 9 维倾向 + 特质（《AI决策系统-基础层模型-系统设计.md》§3） | 挑剔→品质分量权重上调、Greed→价格敏感（价格位置权重）、探索→陌生店偏好（好奇）、耐心→时段紧迫衰减放缓 等 |
| DutyMod | 当前 RoleContext | Duty 时段的消费候选打折扣（配置） |
| TimeMod | 当前游戏时间 + ActionTag | 深夜睡眠加成 / 饭点餐饮加成 |
| WeatherMod | 全局天气状态 | 接口预留（见 §17.5（[商圈卷](/VoxelDesign/02-系统设计/AI决策系统-商圈生态-系统设计.md)）），本版恒不产生影响 |
| MemoryMod | **V1 固定中性值 1，不生成个人记忆输入** | 完整版本才读取记忆锚点 / 条目修改器快照，在唤起时按快照重放并聚合（有上下限），不现场重算规则 |
| ClienteleMod | 完整版本的店铺客群派系统计与派系态度；**V1 不启用，固定中性值 1** | 后续才读取关系层群体轨 Rank/Attitude；V1 的 `FactionTag` 只作人员基础身份与客群统计，不产生选店关系修正 |
| MoodMod | **V1 固定中性值 1，不驱动行为** | V1 的 Mood 只计算数值、展示并接收购买体验等结算结果；后续版本才用低落／高涨修饰安慰型消费、探索型消费与店铺偏好 |
| SocialDrive | Social 需求过阈激活（`Buff.Urgency.Lonely`） | 社交修饰 = Sociality ×（店铺氛围值 − 中性点）：外向者泡热闹店、内向者偏好安静店；店铺氛围值 = 客流滚动统计派生（[店铺经营 §1](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)）。熟人锚点与关系加成留后续版本，V1 不读取 |

**选择器**：
```
1. 过滤总分为零的候选
2. 排序降序
3. 最高分低于行动阈值 → 兜底闲逛
4. Top-3 按分数加权随机（避免挤同店）
5. 输出选中候选 → 生成 FIntent（Source=Self，State=Bound，统一模型见《意图与流程统一模型》）
```

### 5.4 工作决策（员工，优先级表 × 任务分带两层扫描）

RimWorld 式两层模型：员工侧工作优先级表（意愿）× 任务侧 Priority 分带（紧急度），**不走评分公式**：

**员工工作优先级表**（`FWorkAssignment.WorkPriorities`）：
```
TMap<AI.Work.* Tag, uint8>，取值 0-4:
  0 = 禁止（绝不干，如怕火的员工禁灭火）
  1-3 = 普通偏好梯度
  4 = 灭火级（有活就抢着干）
"岗位"概念由优先级表吸收：招聘时按岗位给预设模板，玩家之后可逐格调整
```

**扫描流程**：
```
① 已有 Critical 个人需求优先：V1 离店 / 回抽象住所处理；工作 Shop 内不产生新的需求下降，不转别店消费
② 按员工优先级从高到低遍历工种（优先级 0 的工种跳过）
③ 该工种看板有可领工单 → 进入（工种内按任务侧 Priority 分带: 紧急 → 常规 → 低优）
④ 同带 tie-break: 就近 + 先到先得
⑤ 全表扫完无工单 → V1 仅工作区待机；后续版本才接待机/偷懒分流（§11.6，[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)）
```

交接约束（详见 §11.7（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)），含工单可暂停/不可暂停分带）：
- 下班只允许按容忍窗完成当前原子段，不要求整个工单做完；可暂停业务进度留在对应业务域，下一劳动者续做，不随不入档看板或认领保存
- 临近下班只认领"预估工期 ≤ 剩余班次时间"的不可暂停工单（班次末尾"只接小活"是自然涌现）
- 无人接的工单留在看板

### 5.5 兜底行为链

```
无高分消费候选 → 闲逛（自驱游走：不依赖任何设施，向可达随机点移动，天然不会失败；
                Leisure 需求的合法满足途径，正常行为非异常）
                ↓
连续 N 次候选失败 / 闲逛需求已回填 → 回家（居民）/ 离场（游客）——防"鬼打墙"的总出口（连续失败计数器重置条件见 2.5 递归护栏③）
                ↓
全需求满足     → 回家（V1 普通居民与员工回抽象住所点消失；后续实体住所 NPC 回居家流程，可被对象池回收）
```

无"空闲超时"字段，兜底语义由该链自然接管。排队主动放弃写持续至下一游戏日界的候选冷却，只防"门口反复徘徊入队"这一退化行为；决策本身独立，不因失败历史对候选降权（2.5）。跨日抑制复购由完整版本的个体记忆承担；V1 不生成该记忆，也不做额外跨日复购抑制。

## 6. 评价体系：期望带模型（SERVQUAL 期望差）

**需求驱动行为、期望评判体验——两套字段彻底分离。** 需求是会衰减的驱动值（Dynamics，不动）；期望是不衰减的评价基准线（Expectations，评价尺子）。

### 6.1 期望带

`FExpectationBand{Min, Max, Direction}`：每个评价维度一个满意带。

- Direction: `HigherBetter`（默认，体验值越高越好）/ `LowerBetter`（如常人对价格：越便宜越好）
- 方向与带值由生成画像时特质修正写入，运行时决策代码零分支。例："势利"特质把 Price 翻成 HigherBetter + 高 Min（太便宜 = 破底线，硬过滤③随之变为价格下限）；"异食癖"把 Environment 翻转（越脏体验越高）
- 特殊服务需求同理：特质可向 NPC 的 Expectations 增加非常规 AspectTag 维度，店铺侧能产出该维度体验值即闭环

AspectTag 维度集：`Service / Quality / Luxury / Environment / Price`。加维度 = 配置加行，零代码。

### 6.2 体验报告

`FExperienceReport{Aspects: TMap<AspectTag, 体验值[0,1]>, 归因(自身/店铺/环境/社交)}`：由消费流程节点产出；中断场景同样产出，归因决定评价后果去向（2.5 打断处理 / §7.7（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)））。

| 节点 | 上报维度 |
|------|---------|
| QueueAt | 服务速度（Service） |
| Consume | 品质（Quality） |
| （店铺装修/卫生/拥挤注入） | Luxury、Environment |
| Pay | 实际价格（Price） |

### 6.3 单维度满意度

满意度是从负到正的有向分数（负 = 不满，正 = 满意，正向有封顶）：

```
HigherBetter 维度（越高越好，如服务速度）:
  体验值跌破底线 → 负分（破底线）
  底线与上限之间 → 越高越满意
  体验值超过上限 → 封顶正分（过满分线不再加分）

LowerBetter 维度（越低越好，如常人对价格）:
  方向倒置——体验值超出上限 → 负分；低于底线 → 封顶正分
```

### 6.4 综合满意度

综合满意度 = 各维度满意度按在意度加权平均。

在意度 = 底线值：HigherBetter 维度取底线（底线高 = 在意）；LowerBetter 维度取上限的反向位置（价格上限压越低 = 对价格越敏感）。天然加权，免配权重表。

### 6.5 带宽即性格

- 挑剔贵客 = 高底线 + 窄带（难伺候）
- 随和顾客 = 低底线 + 宽带（好打发）

带宽与底线 = 职业基准 + Fastidiousness（挑剔↔随和）+ 特质修正 + 个体噪声（生成画像，2.2）——挑剔↔随和正是期望带宽度的性格落点（《AI决策系统-基础层模型-系统设计.md》§3.2），无需单独的性格→忍耐映射。

### 6.6 关键一致性

选店硬过滤的店铺价位档与结账价格好感共用同一 `PremiumRate = (Price - Value) / Value`：远程店铺价位档是当前已上架商品的平均溢价率，个人 `Expectations[Price].Max` 决定可接受上限；成交后 `PriceFavorDelta = -PremiumRate`，高于基本价按比例降低价格好感，低于基本价按比例提高。精确货币价格仍到 Browse 才揭示，V1 不做动态市场价或供需波动。

### 6.7 等待忍耐并入（服务等待段）

- 所有"阻塞等待外部服务"统一走等待段模型（定义见 2.5，节点骨架见 §8.2（[空间卷](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)））：等待体验值随时长下降，减缓因子按场景（等待区设施/用餐环境/引导员）
- 预警档：跌破预警线 → 投诉事件 + 外化 + 关联工单提带，玩家/店主可安抚消负面
- 跌破 Expectations[Service].Min → 按承诺程度三分支放弃（2.5）
- 选店时 QueueFactor 用"估算等待 vs Service 底线"预估——预估与实判同一把尺

### 6.8 漂移接口预留

期望带 Min/Max 可向体验值缓移（期望被现实驯化/由奢入俭难），首版关闭，但漂移字段（方向/速率/边界）首版即定死进 FExpectationBand 数据结构，第二阶段启用——避免届时改存档结构。

## 16. 行为外化与情报记录

### 16.1 两层信息分离（脸盲约束）

脸盲限制的是"这是谁"，不限制"他在干什么"——素体也做动作，行为正是脸盲玩法的观察通道：

| 层 | 内容 | 门槛 |
|---|------|------|
| **身份层** | 脸/名字/属性面板 | 关系度达标才显示；否则统一半透明素体 |
| **行为层** | 动作/反应/情绪演出 | 永远可见（素体也演） |

### 16.2 外化模型（订阅制）

**外化不造事件**——外化层没有平行事件通道，只订阅已有数据源、翻译成演出指令（FExternalizeEvent 降级为外化层发给动画系统的内部演出指令）：

| 订阅源 | 驱动内容 |
|--------|---------|
| 状态层档位变化（《AI决策系统-需求与状态层-系统设计.md》） | 姿势/表情基调（疲惫驼背、醉态） |
| 当前行为 Tag（FFlowState 执行节点） | 行为动画集（擦桌/收银/闲逛） |
| 事件解读产生的强情绪修改器（统一效应单入口，带来源事件 ID） | 情绪反应演出（愤怒/恐惧/狂喜的表情与气泡） |
| 事件系统广播中的显著事件（差评/离队/冲突等） | 即时反应（嫌贵皱眉、离队指店、被好评点头） |

外化内容分三类（全配置化，Tag 驱动）：

| 类别 | 例子 | 玩法作用 |
|------|------|---------|
| 情绪反应 | 嫌贵皱眉、吃到差评摇头、被服务好评点头 | 玩家观察 → 推测该店问题所在 |
| 行为线索 | 看别家队伍、排队中途离队指店、橱窗张望 | 玩家观察 → 推测客流流失原因 |
| 工作状态 | 员工忙碌/偷懒/打盹的演出 | 接 §11.6（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)）偷懒的可见性 |

**密度控制**：订阅 ≠ 全演——显著性过滤（强度阈值）+ LOD 档位（§18：LOD1 只演关键外化）控制演出密度。

### 16.3 系统挂接

- 外化层是显示层订阅方（只订阅、不反写）；不产生事件、不进记忆
- 演出层走动画系统（蒙太奇/表情）；AI 侧只暴露数据与演出指令，不管怎么演
- 玩家记事本可记录观察到的外化（脸盲玩法的线索沉淀）

### 16.4 玩家侧 NPC 档案（情报记录口子）

玩家对 NPC 的观察/认知数据（关系度、记事本备注、观察到的外化演出）统一存在**玩家侧 NPC 档案**，作为未来情报玩法（万事屋/侦探所等店铺核心玩法）的数据底座。本版不设计传播/交易/情报价值机制。

### 16.5 关系系统

> 本章已移至《AI决策系统-关系系统-系统设计.md》v2.0（账本与余额分离 / 制度型与情感型 / 派系 / 玩家侧认知档案），本处只留锚点。

> 16.6 闲聊话题与叙事传播 → [商圈卷](/VoxelDesign/02-系统设计/AI决策系统-商圈生态-系统设计.md)；16.7 店铺日志 → [经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)

### 16.8 玩家行为级接口

玩家与 NPC 的互动是**具体行为而非抽象数值按钮**——每次互动都是一个事件，走同一事件管线：

- 行为示例：搭话、请客/赠礼、安抚（投诉/情绪低）、训诫、帮工等
- 行为后果（统一管线）：影响目标情绪与双方关系度（FSocialMemory，双向）→ 产生外化演出（16.2）→ 可能产生话题（§16.6，[商圈卷](/VoxelDesign/02-系统设计/AI决策系统-商圈生态-系统设计.md)）→ 写入双方记忆
- 行为集配置化可扩展（Tag 驱动）：未来玩法（情报/委托等）加行为不改框架
- 与管理指令的边界：管理指令（指派工单/驱赶，§11.9（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)））是玩家以"老板身份"对店铺/员工的动作；行为级互动是以"个人身份"对 NPC 的动作——两条线入口分开，后果可叠加（训诫既是管理动作也是社交事件，两条后果都生效）

## 18. 决策 LOD（演出与执行分级）

事件驱动模型下不存在"休眠档"：不在图零开销（2.3），图内每个 NPC 都有事做，没有可供再降档的持续决策运算。决策本身是事件时刻的稀有操作（一次加法核算术），**计算不值得降档**——LOD 管的是**演出与执行成本**：饭点全员在场时，把表现算力集中在玩家看得见的地方。

### 18.1 图内两档 LOD

| 档位 | 判定 | 降档内容 |
|------|------|---------|
| **LOD 0 全量** | 玩家店铺内 / 玩家附近 / 高关系度目标 | 全动画与外化演出、完整寻路 |
| **LOD 1 简化** | 图内但远离玩家 | 只演关键外化、动画降频、简化寻路 |

不在图的 NPC 不保留激活 Actor，但 V1 名册及其需求 / 状态等业务数据仍按存档清单入档。实际回家并离场时按 §2.2 一次补满指定数值；其他不在图期间不做图外时间补算，进图时按名册保存状态与当前日程刷出。图内全员都是名册上的完整个体（§17.4，[商圈卷](/VoxelDesign/02-系统设计/AI决策系统-商圈生态-系统设计.md)），不存在“背景人”装饰层。

### 18.2 重要度优先定档

```
重要度 = 玩家店铺员工/顾客(+高)
       + 玩家高关系度 NPC(+高)
       + 当前被玩家注视/交互(+高)
       + 距离衰减(−)

基础档位由重要度定，再按距离微调
```

**玩家店铺始终全量**：玩家经营的店，其员工与在场顾客锁定 LOD 0/1（玩家观察的核心）。

### 18.3 升降档与连续性

- 档位可升降：玩家走近 → 升档；走远 → 降档。升降时补一次决策避免行为断层
- **LOD 只降演出与执行，决策与数据层全档位同精度、永不降档**：决策评分（含 Top-3 加权随机）、感知判定（《AI决策系统-事件系统-系统设计.md》§4.4）、记忆解读与传播接收、需求衰减、租约续约、看板状态流转、体验结算、账本、声誉滚动统计、店主经营循环，全部照常推进——玩家远离时世界照常运转，回来账本声誉对得上

## 20. 战斗模式（愿景附录）

> 定位：战斗为探索模式的**回合制 3D 战棋（非网格）**。可复用的是评分器框架与连续空间距离因子（ProximityAtten 映射为距离/AP 消耗，与日常连续寻路同源）；**回合时序执行层另设**，不属于本系统交付范围。本章仅为方向性参考，不构成实现承诺。

### 20.1 同框架不同配置

战斗不新建独立系统，通过 `BehaviorContext` 切换：

| 维度 | Daily 配置 | Combat 配置 |
|------|----------|-----------|
| 决策触发 | 需求阈值 / 日程时段 / Job 完成 | 回合开始 / 被攻击 |
| 候选来源 | 店铺设施实例状态 + 商品目录 / 看板工单 | 技能 + 格子 + 道具 |
| NeedScore 输入 | 需求值 | 血量 / AP / 友军血量 |
| QualityScore | 功能品质与有效声誉 | 伤害值与命中率 |
| ProximityAtten | 距离衰减 | 移动范围 + 攻击范围 |
| 执行模式 | 流程节点 + 连续寻路 + 动画 | 回合制 3D 战棋（非网格）+ AP 消耗；回合时序执行层另设 |
| 玩家控制 | 无 | 挚友完全受控 / 陌生盟友 AI 评分 |

**一级能力同源**：战斗数值与工作熟练度读同一份 `Creature.Attribute.Primary` 基础七围（见 §11.4（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)））——培养员工的工作能力同时投资战斗能力（"全员皆兵"设定）。

### 20.2 玩家控制

- **挚友**（完全控制）：候选只有玩家指令，分数固定最高
- **陌生盟友**（AI 控制）：正常 Combat 配置评分
- **同一框架**：只是候选来源不同，评分器本身不变

## 24. 关键场景走查

### 24.2 吃饭中途上厕所

```
Consume 节点（餐厅流程）吃饭进行到一半
进食累积消化计数过阈 → 触发 Buff.Urgency.NatureCall 便意（如厕是吃喝下游结果，非独立需求条——《AI决策系统-需求与状态层-系统设计.md》）
  → 强制打断当前节点（归因=自身原因：自己的 BuffTag 触发，不追责店铺，2.5/§7.7（[经营卷](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)））
  → PartialSettle: Hunger 按进度比例部分回填
  → 支付同比例, 体验分按进度打折（不产生店铺负面记录）
  → 释放吧台座位, 流程记录断点
  → 紧急决策

空间优先级扫描 Layer 1: 当前餐厅
  → 餐厅内有洗手间 → 生成候选, 停止扩展
  → （无洗手间 → 尴尬事件：失禁 BuffTag 爆发, Mood 冲击 + 外化 + 店内 Environment 污染）

去洗手间 → 便意清除 → Hunger 仍低
  → 重决策 → 可从断点恢复餐厅流程继续吃
```

### 24.5 记忆影响评分与个体偏差

```
NPC 甲评分餐厅 A:
  店铺有效声誉尚可，但个体记忆负面（"上次在 A 吃坏肚子"）
  记忆修饰大幅下调（有下限保护）→ 品质分项与修饰双低
  → 几乎不会选餐厅 A

NPC 乙评分餐厅 A:
  无相关记忆 → 记忆修饰不产生影响
  → 按店铺有效声誉正常评分 → 可能选中

同一家店, 不同人不同的分（个体偏差）
```

### 24.9 组团消费

```
NPC 甲 Hunger 急 + 社交意愿高:
  → 甲与乙结伴出场（同住所+高亲密+时段重叠，2.3），刷出时已成团
    （若未成结伴：甲在街上遇到乙 → 面对面邀请，即时数据请求当帧响应）
  → 乙: Hunger 也低 + Free 时段 + 与甲亲密度高 → 接受入团
    （丙不在图 → 无远程邀请通道，根本不会成为候选）
  → 甲跑评分选餐厅 X → 乙对 X 的评分高于否决线 → 同行
  → 到店排队/占座按人头（2 个队列位/座位资源）；等待与去留统一按甲（发起人）的容忍度
    （乙若可压制 Critical → 发催促外化，修正甲的判定；乙若硬极限 → 无条件脱离，团规模 -1）
  → 同店消费 → 聊天互动回填 Social 需求
  → 两人各自写记忆 + 店铺声誉样本 +2
```
