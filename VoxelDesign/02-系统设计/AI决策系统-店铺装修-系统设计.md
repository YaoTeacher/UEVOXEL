**本分册职责**: 装修的数值携带、区域环境聚合、经营实体资产归属与退租边界

> 修改日志：2026-11-04 装修资产归属用 BusinessEntityId 与 LeaseId，退租不拆除、不回滚、不重分资产；区域环境只作派生输入。
>

> 装修不设施工期，确认即完成。装修 = 体素建造（墙/地/门窗结构）+ 家具摆放，不新建独立系统；新增的只有区域环境聚合与体素实例状态。

## 1. 系统边界

**负责**：
- 定义装修相关的数值携带（家具 Stats、体素实例状态、风格标签、灯光）
- 区域环境分项聚合与重算时机
- 装修资产归属记录与退租不拆除、不回滚、不重新分配的边界

**不负责**：
- 施工期/工期/噪音灰尘（V1 不做）
- 家具自身的使用逻辑（家具系统）
- 区域权属与权限规则（区域系统）
- 顾客评价公式（评价体系在经营卷）

## 2. 数值携带

### 2.1 家具

- 静态：物品行 `Stats`（`Stat.Beauty` / `Stat.ComfortFactor` / `Stat.Quality`）
- 动态：三状态读取（Cleanliness / Integrity〔HP 派生〕/ 库存）
- 风格：物品行 `StyleTags`

### 2.2 体素（地板/墙/天花板）

体素有实例状态，按格稀疏存储：

```
FVoxelCellState（仅存偏离默认值的格）
├─ HitPoints    当前物理耐久；正常格默认 MaxHitPoints
└─ Cleanliness  清洁度，默认 1
```

- `MaxHitPoints` 来自方块行的静态基础配置，所有 ITEM／体素都有 float HP；`Integrity = HitPoints / MaxHitPoints` 仅供结构判断与环境展示，不作为第二份状态保存；
- 正常格不占额外内存；只有 HP 偏离 `MaxHitPoints` 或真脏的格进入稀疏表；
- 方块类型行携带 `Stats`（材质美观等）与 `StyleTags`。
- 损坏度由战斗 / 灾害 / 事件及使用磨损写 `HitPoints`，派生 `Integrity` 影响环境美观与结构判定；V1 接入维修工单。设施低于维护阈值时降低使用效果，HP0 可使用但无功能效果，不直接因损坏停用。
- 清洁度可打扫：清洁工单按"区域 + 污渍簇"生成，相邻脏格合并成一个工单，一次动作清理整簇。

### 2.3 灯光

灯具家具挂 `FLightFuncFragment { GlowRadius, Intensity, Color }` + Stats；光照分项按区域采样点的覆盖比例算，昼夜与开关只影响这一项。

## 3. 区域环境聚合

### 3.1 数据来源

| 来源 | 进入方式 | 更新时机 |
|------|----------|----------|
| 家具 | 放置完成 → footprint 查最小包含区域 → 区域设施索引 | 放置/移除/品质变化/维护槽跨阈值 → 标脏 |
| 体素 | 区域创建/边界修改时向体素系统请求盒内统计；体素编辑落点 ∈ 区域盒时增量更新材质直方图与状态聚合 | 编辑 → 标脏 |
| 灯光 | 重算时按光源覆盖计算 | 随环境重算 |

体素**不做采样、不逐格注册**：区域维护"暴露面材质直方图 + 状态聚合"，材质统计只计暴露面（相邻有空气的方块），避免厚墙内部重复计分；编辑时检查 6 邻域更新暴露状态。

### 3.2 环境分项

```
FAreaEnvironment
├─ Beauty        地板/墙面材质美观（面积加权）+ 家具美观密度（Σ美观×三槽 / 面积）
├─ Comfort       顾客可达坐席的 ComfortFactor 均值（无坐席按站位降档）
├─ Tidiness      家具清洁度均值 + 暴露面体素清洁度均值
├─ Light         采样点光照覆盖率 × 灯具品质
└─ Spaciousness  可用面积 / 常驻人数
```

- **不存单一总分**，分项是从空间、体素和家具状态派生的查询缓存，不作为经营资产 / 业务事实入档；顾客体验按 `Aspect.Environment.*` 期望带逐项比较。
- 家具美观做密度化（除以面积），防止堆家具无限加分。
- 子功能区（厨房/员工区/卫生间）不参与顾客环境；顾客环境只算主店铺区域。
- 更新：脏标记 + 惰性重算（顾客进店/结算时），无 Tick。

### 3.3 风格分布（数据层，不做分项）

```
物品/方块行：StyleTags（单主风格，Style.Rustic / Style.Modern…）
区域聚合：TMap<FGameplayTag, float> 风格占比，按美观值加权归一化
NPC 侧：风格偏好（性格/背景/记忆产出）
结算：偏好风格占比 × 偏好强度 → 修饰器；混搭不扣分，偏好风格被稀释自然降分
```

### 3.4 结算分工（防双重计分）

- **接触体验**读单件家具：坐下/睡觉/吃饭时按那件家具的舒适系数、品质、清洁度结算；
- **氛围体验**只读区域环境分项，家具美观只作为聚合输入，不再单件结算。

**五个分项的归口**：区域环境仅为空间派生输入，氛围体验结果写经营实体服务组的**环境氛围**维度（[店铺经营](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md) §7）。V1四类群体只记客群构成，不交叉写群体声誉；分项本身不进口碑、不复制一份业务分数。

| 分项 | 影响什么 |
|---|---|
| Beauty | 环境氛围评分（按顾客审美偏好加权） |
| Comfort | 接触体验的座位/床位结算 |
| Tidiness | 环境氛围评分 + 触发清洁工单（[员工卷](/VoxelDesign/02-系统设计/AI决策系统-员工与工作执行-系统设计.md) §4.1） |
| Light | 环境氛围评分 |
| Spaciousness | 环境氛围评分（拥挤时显著压低） |

风格偏好（§3.3）作为环境氛围评分的个体修饰，不单独记账。

## 4. 装修归属与退租

### 4.1 权限

- 硬装（体素墙 / 地 / 门窗）：从经营实体产权 / 经营关系解析权限，再对实际 `AreaRef` 执行空间编辑校验，不从区域Owner镜像读权限；
- 软装（家具 / 门窗实例）：有权经营人按合同编辑自己的或经授权的资产；店铺承租经营人不等于客房住客，客人不设为客房Manager；
- NPC商业街（后续）可通过空间编辑约束限制硬装，合同与经营权限仍属经营实体；
- 玩家商圈编辑仍受经营权限、租户资产归属及空间校验约束，不凭管理身份吞并租户资产。

### 4.2 归属记录

经营资产与业务唯一归 Global `BusinessEntities` 中的经营实体，商圈 / Shop / 图外生意共享基础模型并按类型组合模块。实体持产权 / 经营关系、`bOpen` / 日程、目录 / 定价 / 订单 / 预留与声誉 / 客流；区域只空间与校验，不持业务或资产镜像。店铺产权通过经营隶属继承商圈产权人，不凭空间包含吞并租户资产。实体区域组件关联 `AreaRef={SceneId,AreaId}`，子客房 / 仓库不是经营实体，抽象生意无实际区域且不造假区域。真实库存、工作点FIFO与门锁归对应实例，区域看板为不入档派生索引。

`BusinessEntityId` 是全局稳定经营 ID（GUID，规则见[总纲 §2.7](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)）；不再使用 `ShopId` 别名，也不用 `Shop->GetAreaId()` 表达经营 ID；Home / Work 仍空间。租约唯一事实存 Global `LeaseRegistry`，实体仅持 `LeaseId`，出租 / 承租业务、租用空间和租户人物分别为 `LessorBusinessEntityId / TenantBusinessEntityId / LeasedAreaRef / TenantCreatureId`。

| 类型 | 记录方式 |
|------|----------|
| 软装（家具 / 门窗） | 实例记录所属经营实体 `BusinessEntityId` 与 `PlacedByLeaseId`；HP / 清洁度等仍归实例 |
| 硬装（体素） | 归属日志 `{格坐标, 原方块, 新方块, BusinessEntityId, LeaseId}`，只记录实际编辑与历史归属，不用作退租自动恢复 |

- 租户建造 / 装修前必须已有生效Lease；建造面板圈地 / 填信息 / 确认业务一次创建经营实体、区域与必要关系合同，正式Lease生效后才真正写入租户建筑家具，同一连续面板不要求跳多个模式。创建默认 `bOpen=false`，不是开业。
- 每次新承租关系使用新 `LeaseId`，实体经营ID仍独立于空间；历史归属不随退租、重签回写到新租户。
- 签约前已有结构仍归原经营产权方，之后租户自建 / 改造记在对应租户经营实体的资产归属中；空间包含不转移资产。详见[区域店铺与商圈管理 §2 / §6.14 / §9](/VoxelDesign/02-系统设计/AI决策系统-区域店铺与商圈管理-系统设计.md)。

不做全区域快照（存储随店铺数线性增长）；改动日志量级 = 实际改动格数。

### 4.3 退租结算

```
退租 / 清退缓冲期届满
  → 终止租约与该店相关雇佣，按在职时长结清工资
  → 保留租户资产归属与历史LeaseId
  → 不拆建筑、不收回家具、不逆序回滚装修、不自动折价或重分配资产
```

- 退租不是批量体素恢复或自动入包操作，不按拆除返还率结算材料；V1建造 / 装修免费。
- 后续产权方需要取得租户资产时，只能通过盘下协商收购，不凭空间包含、失联或死亡充公。
- 普通授权编辑中，家具 / 门窗从OBJECT收起为ITEM仍保留HP、清洁度等实例状态；ITEM中不推进清洁度，重新放置继续计算。堆叠与入包按实例兼容规则执行，但这些不是退租自动动作。

### 4.4 无主充公

- V1 不做无主充公；确认死亡或跑路时，租户自带资产仍归租户所有；
- 产权人或父级管理人只能通过盘下与租户协商收购其自带建筑 / 装修 / 家具（后续版本）；
- 不存在押金抵欠租、欠租没收或按欠租期数充公。

## 5. V1 范围

**做**：家具 / 体素 / 风格 / 灯光数值携带；区域空间五项环境 + 风格分布；设施推送与体素直方图；普通家具清洁 / 维修工单；按经营实体和LeaseId记录装修资产归属。V1建造 / 装修免费，退租不拆毁、不回滚、不重分资产，不产生装修欠费与没收。

**不做**：施工期、风格一致性惩罚、公共专属设施与长椅维护费、地面以外的环境介质（温度 / 湿度 / 气味）。
