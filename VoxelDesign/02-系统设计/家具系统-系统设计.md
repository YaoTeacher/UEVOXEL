## 1. 系统上下文

### 1.1 系统边界

**家具系统负责**：
- 家具能力的功能片段定义（坐/睡/吃/储/收银/产/娱/通行/采光/维护）
- 家具实例的功能模块与状态
- 槽位系统（socket 声明、解析、回退推导）
- 设施注册（家具↔区域绑定）、设施发现与占用
- 三状态槽（清洁度/完善度/库存）与维护工单
- 组合家具（桌↔椅）的运行时配对
- 门/窗的通行与采光语义
- 需要排队的工作点声明与队列配置（收银台、门等）

**不负责**：
- 区域权属、权限、营业状态（区域系统）
- NPC 决策与流程编排（AI 决策系统）
- 价格/账本/商品目录（经营系统）
- 网格占用与 Actor 生成（VoxelItemWorldSubsystem）
- 工作点 FIFO 队列的消费流程编排（空间卷 §9）

### 1.2 依赖

- **ConfigDataSubsystem / 物品数据模型**：家具行配置、Profile 缓存
- **VoxelItemWorldSubsystem**：footprint 占用与实例 Actor
- **VoxelAreaWorldSubsystem**：区域查询、设施索引挂载
- **AI 决策系统**：设施发现与占用的调用方

## 2. 核心概念

**家具行（配置）**：一行配置 = 一种家具型别，声明功能片段集合、Stats、放置数据。

**家具实例**：场景中的一个具体家具，持有功能模块状态（占用/清洁/完善/锁）。

**设施（Facility）**：带功能片段的家具实例在区域中的角色称谓——区域设施索引登记的是它，NPC 找的也是它。纯装饰家具不产生设施记录。

**工作点（WorkPoint）**：提供收银、通行等服务的运行对象；需要排队时持有自己的 FIFO 逻辑队列，家具配置负责声明“需要排队”与站位方式。

**槽位（Slot）**：交互点位。由网格 socket 声明或按规则推导，分角色（路线/消费/员工/台面/出入口）。

**功能模块（Module）**：片段在实例上的运行形态，装该功能的状态。

## 3. 家具配置

### 3.1 家具功能片段

| 片段 | 结构参数 | 效果 | 说明 |
|------|----------|------|------|
| FSeatFuncFragment | — | Effect(舒适) | 能力与容量全由槽位声明，片段本身无参数 |
| FDineFuncFragment | SurfaceCells 台面餐盘数 | Effect(舒适) | 餐位容量 = 邻接配对的椅子数 |
| FSleepFuncFragment | bMedical 医疗床标记 | Effect(精力) | 双人床 = 两个 sleep 槽位 |
| FToiletFuncFragment | — | Effect(如厕) | 便意是进食消化后的 BuffTag，不设需求条 |
| FStorageFuncFragment | MaxCell / AllowItemTags / bForSale / PreserveFactor（后续保质，V1 不生效） | — | 货架（可售）与储物柜（不可售）同片段不同参数；地窖/冰窖类后续使用 PreserveFactor |
| FCashierFuncFragment | QueueConfig（见 §3.3） | — | 收银台家具的能力标记，声明需要排队的工作点；运行期提醒按此能力计数，员工工作位置由家具自身 `slot_staff_cashier` 提供，不另作检查项 |
| FProduceFuncFragment | RecipeRefs 配方引用 / JobTag 工种 | — | 灶台/工作台；产出定义在配方行 |
| FJoyFuncFragment | Mode：Socket 点位 \| 区域几何（距离范围+宽度+b同房间） | Effect(娱乐) | 电视/舞台用区域几何，棋桌用点位 |
| FPassageFuncFragment | Flow 双向/单向 / bHidden 暗门 / bDefaultLocked / QueueConfig（需要排队时） | — | 门；需要排队时按 §3.3 声明工作点队列 |
| FSightFuncFragment | — | — | 窗，标记即 LOS 透明 |
| FLightFuncFragment | GlowRadius / Intensity / Color | — | 灯具，光照环境分项来源 |
| （物品行基础字段） | MaxHitPoints: float | — | 所有 ITEM 都有 HP；不再以可选片段决定有无耐久 |
| FMaintainCleanFuncFragment | — | — | 标记 = 放置 OBJECT 会产生清洁劣化，速率/阈值走全局配置；ITEM 形态不推进 |
| FMaintainRepairFuncFragment | — | — | 标记 = 会产生使用磨损并触发维修；读写实例核心 `HitPoints`，不另存 `Integrity` |

数值归属：片段只装结构参数；品质/美观/舒适系数进 `Stats`；效果增量进片段内 `Effect`；阈值与劣化速率走全局配置。

### 3.2 家具行的典型组合

| 家具 | FunctionSet | Stats |
|------|-------------|-------|
| 四人长桌 | FDineFunc + FMaintainClean + FMaintainRepair | 品质/舒适系数/美观 |
| 餐椅 | FSeatFunc | 品质/舒适系数 |
| 货架 | FStorageFunc{可售} + FMaintainRepair | 品质 |
| 收银台 | FCashierFunc{QueueConfig} + 员工槽位声明 | 品质 |
| 双人床 | FSleepFunc + FMaintainClean + FMaintainRepair | 品质/舒适系数 |
| 灶台 | FProduceFunc{Cook} + FMaintainClean + FMaintainRepair | 品质 |
| 门 | FPassageFunc（需要排队时附 QueueConfig） | — |
| 橱窗 | FSightFunc | 美观 |

### 3.3 工作点队列配置

收银台、门等需要排队的工作点声明以下配置；不要求玩家放置独立的“排队区”资产：

```
FWorkPointQueueConfig
├─ bRequiresQueue = true
├─ QueueMode           Line | WaitingArea
├─ QueueLine           可编辑排队点串（QueueMode=Line）
└─ WaitingAreaRef      已有关联区域 / 子区域（QueueMode=WaitingArea）
```

- 工作点持有自己的 FIFO 逻辑队列，容量统一为 8；`QueueMode` 只决定站哪里，不决定排队顺序。
- `Line` 未配置 `QueueLine` 时，按工作点朝向与周围可站立、可达格子自动生成默认队列线；生成失败则禁用该工作点并向玩家告警。
- `WaitingArea` 让顾客在关联等待区内等待，轮到自己时走到工作点；等待区不另存队列顺序。
- 队列满、打烊与离队的消费流程规则见[空间卷 §9](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)。

## 4. 实例与功能模块

```
FVoxelItemInstanceBase
├─ 核心字段（HandleId / ItemTag / Quantity / float HitPoints / Direction / ParentArea）
└─ FunctionModules
     FSlotModule           { TMap<int32, FVoxelSlotUse{OccupantType, OccupantId, State, Expiry}> }
     FStorageModule        { TArray<FVoxelInstanceContainerFragment> }  // 槽位引用 ITEM 实例
     FMaintainCleanModule  { float Cleanliness = 1 }                    // 仅 OBJECT 推进
     FPassageModule        { bool bLocked }
```

- 所有 ITEM 的 `MaxHitPoints` 都来自静态基础配置，`HitPoints` 都位于实例核心；`Integrity = HitPoints / MaxHitPoints` 仅派生，不进入模块或存档；
- 普通 ITEM 的 HP 归零时保留实例，但不可使用、可以维修；家具维修读写同一核心 HP，不另存完善度；
- 家具作为 OBJECT 放置时，使用、环境和清洁行为修改 `Cleanliness`；收起为 ITEM 后只保存该值，不在背包／货架中继续推进，重新放置时恢复并继续计算；
- 槽位状态**只存一份**，坐/睡/吃等交互共用；Free / Reserved / Occupied 三态，预约带到期时刻，超时回收。工作点 FIFO 队列及队列线 / 等待区站位不写入这些功能槽位。
- `FCashierFuncFragment` 是能力与工作点队列配置标记，V1 不新增 `FCashierModule`：员工位占用仍由 `FSlotModule` 保存，顾客顺序由工作点持有的 FIFO 逻辑队列保存，认领与服务进度归 Cashier 工单，不重复落家具状态。
- 椅↔桌配对结果**不入存档**：运行时缓存，区域编辑事件驱动重算。
- 可选功能状态读取走语义化 getter；HP 不再是可选状态，所有 ITEM 均按核心 HP 计算 `Integrity`。

## 5. 槽位系统

### 5.1 声明方式

**主路线：网格 socket**。放置在 StaticMesh 上，命名规范：

```
slot_route_NN                     路线点（寻路终点，snap 前停靠）
slot_consumer_<sit|stand>_NN      消费者功能位（坐/站）
slot_staff_<sit|stand>_<工种>_NN  员工工位
slot_surface_NN                   台面放置位（餐盘/商品）
slot_entry / slot_exit            出入口（门）
```

加载时解析为类型化 `FSlotTable`，按 HandleId 缓存，全类型实例共享。

槽位角色决定允许的占用者：`consumer/staff = Creature`，`surface = Item`，`route/entry/exit = None`（只做寻路/通行）。队列线站位由工作点的 `QueueLine` 配置或默认生成提供，不属于功能槽位。

**回退模式**：`bUseSocketSlots` 关闭，或开启但 socket 缺失 → 按 footprint + 朝向 + 间距常量推导（站 1.0m / 坐 0.6m），并输出警告。回退保证旧资产可用，但精度降级。

**娱乐设施的区域几何模式**：FJoyFuncFragment.Mode = 区域几何时，不解析点位，改用"朝向距离范围 × 宽度 + 同房间"描述观看区（电视模式），观看者站位由导航自行选择，坐具只加舒适。

### 5.2 两阶段交互

```
FindFacility 选中设施
  → 预约目标功能槽位（State=Reserved，写 OccupantType/OccupantId/Expiry）
  → 寻路到 slot_route（路线点）
  → snap 进功能位（坐/站/躺）
  → 执行 → 结算 → 释放（清预约/占用）
```

route 与功能位分离：寻路只认路线点，避免直接寻路进家具内部；snap 由交互层完成。footprint（占用格）与 slot（交互点）互不推导——0.2m 格是建筑分辨率，不是人体占位单位。

### 5.3 组合家具

主家具（桌）声明台面与消费者槽位；配套件（椅凳）声明自己的座位槽位。配对在运行时按**邻接 ∧ 朝向**自动完成：

- 主家具的餐位容量 = 邻接且朝向它的椅子数；
- 没有椅子 → 降级为站位使用，体验系数降档（不禁止使用）；
- 配对结果缓存于实例侧运行期数据，家具移动/旋转/区域编辑时重算；
- 不做静态绑定，不在配置里填"椅子属于哪张桌"。

## 6. 设施注册与发现

### 6.1 注册（放置时）

```
家具放置完成
  → 用 footprint 查询重叠区域，取最小包含区域
  → 建立 家具↔区域 双向绑定（实例.ParentArea + 区域设施索引）
  → 区域设施索引挂在区域 Actor 上（公共设施区没有 FunctionAreaComponent，索引不能挂组件）
  → 索引条目记录：家具实例引用 + 功能掩码（来自 Profile）
```

跨区域/无区域放置：0 个区域 → 放置告警；跨多个区域 → 取最小包含者，其余区域不登记（门除外，见 §8）。

### 6.2 发现与占用（NPC/员工）

```
FindFacility(区域, 需求, 角色)
  → 区域设施索引按功能掩码筛（HasFunc<T>）
  → 过滤：占用/预约冲突、权限（ALLOW/员工身份）、营业时段、库存等功能硬条件
  → 清洁度 / HP 不作维护不可用硬过滤：低于阈值进入使用效果结算，清洁度 0 另降低使用欲望
  → 排序：品质 × 距离 × 性格偏好
  → 预约槽位 → 占用 → 结算 → 释放
  → 无可用位：需要排队的工作点进入其容量 8 的 FIFO 队列；队列满则转其他可用同类工作点，无可用则离店；其他设施按流程等待或离开
```

员工另有两条通道：工种匹配岗位（`slot_staff_<工种>`）+ 班次租约；看板工单（清洁/维修/补货/收银/上菜）。

## 7. 三状态槽与维护

| 槽 | 变化来源 | 后果 | 工单 |
|----|----------|------|------|
| 清洁度 Cleanliness | 每次使用扣减；脏环境加速 | 低于维护阈值降低使用效果；为 0 时降低使用欲望，但不硬停用 | AI.Work.Clean |
| 完善度 Integrity（HP 派生） | 使用磨损 + 事件（打斗/故障）读写 `HitPoints` | 低于维护阈值降低使用效果；HP 为 0 时可使用但无功能效果 | AI.Work.Repair |
| 库存（FStorageModule） | 售出/取用扣减 | 无货 → 设施不可用 | AI.Work.Restock |

- **不配置维护工种字段**：工种由劣化的槽推导——清洁度低 → 清洁工单，完善度低 → 维修工单，库存低 → 补货工单。
- **维护阈值来自家具配置行**（`FFacilityConfigRow`：`CleanThreshold` / `RepairThreshold` / `DecayPerUse`），按家具类型一行；实例只缓存，不在实例上硬编码，也不放业态配置（不同家具阈值不同，收银台比货架更怕脏）。
- 过阈值时只更新家具自身业务状态并发布 `Facility.StateThresholdCrossed`；工单索引器订阅后维护所属**经营实体**的派生看板，家具不直写看板，也不需要 NPC 主动检查家具。
- 物理耐久只保存 `HitPoints`；维修读取 `Integrity = HitPoints / MaxHitPoints`，不另写完善度字段。清洁度、腐败与品质均不作为 HP 的子状态。
- 恢复：维修完成将 `HitPoints` 恢复至 `MaxHitPoints`，清洁完成将 `Cleanliness` 恢复至 1（或配置上限），随后恢复正常使用效果；清洁度 0 的使用欲望惩罚也随之解除。
- 地面/墙面的清洁度由体素实例状态维护（稀疏存格），清洁工单按"区域+污渍簇"生成，见[装修卷](/VoxelDesign/02-系统设计/AI决策系统-店铺装修-系统设计.md)；家具清洁度只管家具自身。

## 8. 门与窗

### 8.1 门（FPassageFuncFragment）

- 锁：双向强制拒绝，Owner/Manager Override（身份即钥匙）；实体钥匙 v1 不做。
- 流向：双向 / 单向（闸机类）。
- 隐藏侧：暗门 = 可见性控制，不是权限。
- **两侧区域判定**：footprint 外圈全格查最小包含区域并分组（泛化支持旋转门、宽门、跨 3+ 区域）；0 区域=放置告警；1 区域=内外门；同一区域=内门，不触发进出事件。
- 通行判定：`X→Y = IsEntityAllowed(Y,X) ∧ !bLocked ∧ (bHidden ⇒ 已发现)`。
- 门是**进出事件触发点**与 Spawn 精确点位；无门开口靠位置查询兜底。
- 门作为需要排队的工作点时，按 §3.3 声明 `QueueConfig`；FIFO 逻辑队列归工作点，`FPassageModule` 只保存通行状态，不保存顾客顺序。

### 8.2 窗（FSightFuncFragment）

- 标记即 LOS 透明：感知管线穿过窗判定视线；不参与通行与占用。
- 两侧区域用于橱窗效应/展示判定。
- v1 无维护。

## 9. 业务链路示例

**就餐（需求驱动的 UseItem）**：

```
需求触发 UseItem → 选物品（背包已有物品优先）
→ 有限搜索半径内优先 FindFacility(店内餐桌 / 座位)，筛 FDineFunc / FSeatFunc
→ 读 SurfaceCells + SlotTable，查槽位占用与配对椅
→ 有可用位：预约 → 寻路 route → snap 就位
→ 无可用位：原地使用，并记一次“无餐桌”负面体验
→ 等待物品配置的使用时长 → 触发物品配置定义的使用效果
→ 扣减数量 / 生成剩余物 → 释放座位等资源
→ 若使用家具，使用后扣减其 Cleanliness；过阈值的状态变化由工单索引器生成清洁工单
```

**生产**：

```
员工按 FProduceFunc.JobTag 匹配工种 → 认领工单
→ 读 RecipeRefs → 检查 FStorageModule 原料 → slot_staff 操作 → 产出
→ 库存低于阈值 → 状态变化由工单索引器生成补货工单
```

**消费（道具）**：需求回填、状态效果、消耗数量与剩余物均由物品配置定义，`UseItem` 只执行通用流程，不为具体食物另写效果分支。餐桌 / 座位提供就位条件与体验修正，不取代物品自身效果；数量归零时销毁堆实例并清空容器引用。

**维护**：三槽过阈值 → 工单索引器根据状态变化维护工单 → 工种匹配 → 员工认领 → 恢复。

## 10. 与其他系统的关系

| 系统 | 关系 |
|------|------|
| 物品数据模型 | 家具是 NormalItemBase 行；片段/模块/Profile 遵循统一规范 |
| 区域系统 | 设施注册取最小包含区域；所有权/Manager/ALLOW 决定设施可用性。**注意**：设施按最小包含区域注册，所以按店铺聚合时必须沿 `ParentAreaId` 链覆盖主区域及其全部子区域（口径见[库存与保质期 §2](/VoxelDesign/02-系统设计/AI决策系统-库存与保质期-系统设计.md)） |
| AI 决策系统 | FindFacility 的调用方；设施状态驱动候选过滤与消费/工作流程 |
| 空间卷 | 工作点队列：家具声明“需要排队”与 `QueueConfig`，工作点持有 FIFO 逻辑队列；队列线 / 等待区站位与消费流程规则见空间卷 §9 |
| 经营系统 | 货架商品目录与 bForSale 联动；业务状态变化由工单索引器转换为区域派生工单索引 |
| VoxelItemWorldSubsystem | footprint 占用、实例 Actor 生命周期 |
