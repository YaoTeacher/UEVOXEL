**本分册职责**: 客房预订的发起、定金、保留、取消与入住衔接（后续版本；V1 不开放酒店与预订业务）

---

## 1. 系统边界

**版本边界**：V1 不创建客房、预订记录或住宿交易，本页全部流程留后续版本。后续预订范围仅旅店客房、仅当面预约。

**与现货预留的边界**：本页 `FReservation` 只表示后续版本的客房预订，不表示 V1 杂货现货的库存预留。现货选品、缩篮子与 `CanReserveBasket` 唯一守卫统一见[店铺空间与消费流程 §8.6](/VoxelDesign/02-系统设计/AI决策系统-店铺空间与消费流程-系统设计.md)，不在客房预订链路另设入口。

**不负责**：现货库存预留、餐厅桌位保留、包场、外卖、远程/信使预约、超售（后续版本）。

## 2. 预订记录

```
FReservation                  归旅店经营实体的住宿模块
├─ ReservationId
├─ BusinessEntityId            旅店经营实体，全局稳定经营ID
├─ RoomAreaRef                 {SceneId,AreaId}，客房空间定位
├─ GuestId                     预订人，人物ID
├─ CheckInDay / CheckOutDay
├─ DepositAmount               定金
├─ State                       Active / CheckedIn / Cancelled / NoShow
├─ StayRecordId                入住后关联住宿记录
└─ CreatedAt
```

房间在预订期内**硬锁定**：其他顾客不可入住、不可再订；不做超售。这是旅店住宿模块的业务占用，不是区域资产或客房Manager权属，也不自行定义门锁 / 隐私策略。

旅店是 Global `BusinessEntities` 中的经营实体，与商圈 / Shop / 图外生意共享基础模型、按类型组合模块，持经营资产及产权 / 经营关系、`bOpen` / 日程、目录 / 定价 / 订单 / 预留、声誉 / 客流；客房业务归旅店住宿模块。区域只空间与校验，不存业务镜像，实体区域组件关联 `AreaRef={SceneId,AreaId}`；子客房 / 仓库只有空间ID、不是经营实体，抽象生意无实际区域且不造假区域。真实库存、工作点FIFO与门锁仍归对应实例，区域看板为不入档派生索引。

`BusinessEntityId` 是全局稳定经营 ID（GUID，规则见[总纲 §2.7](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)）；不再使用 `ShopId` 别名。`RoomAreaRef` 只定位空间，`GuestId` 只定位人物；Home / Work 仍是空间。详见[区域店铺与商圈管理 §2 / §9](/VoxelDesign/02-系统设计/AI决策系统-区域店铺与商圈管理-系统设计.md)。

## 3. 发起方式

只能**当面预约**：NPC 在旅店前台办理，玩家同样在前台操作。不存在远程预订通道（与"不在图无响应通道"的既有设定一致）。

NPC 预订条件：

```
熟客（与旅店/店主有关系度）
  且 有确定的住宿需求（固定行程/商务/节日等）
→ 到店发起预订
其余游客一律 walk-in
```

预订成功后生成一条代办日程（到日入住），当天注入候选池；逾期未到按 no-show 处理。

## 4. 定金与取消

| 规则 | 内容 |
|------|------|
| 定金 | 比例由店主配置 0–100%；入住时付尾款 |
| 取消窗口 | 由店主配置；窗口内取消退定金，超出不退 |
| no-show | 到入住截止时刻仍未到店 → 没收定金、房间释放、记顾客一次负面记录 |
| 店主取消 | 房间不可用时（损坏/被占）由店主取消，退还定金并记店铺差评 |

定金与尾款沿现行预订规则走账本支付节点（经营卷§10.3），不新增账目类型。每个实际 / 抽象人物创建时已有个人钱包与唯一经营账户，非经营者也有；住宿付款从住客个人钱包进入旅店资金责任人的经营账户（自营 / 承租为经营人，薪酬制为产权人），不向客房区域账户支付。退款反向冲销对应原交易；唯一流水保留 `SourceBusinessEntityId / TargetBusinessEntityId` 及可空 `OccurredAreaRef`，历史不随当前父关系回改。定金或尾款支付均不自行授予客房Manager。

## 5. 与入住链路衔接

```
预订（前台，当面）→ 记录 Active，房间锁定
→ 到日：代办日程触发 → 到店
→ 前台CheckIn：付尾款 → 旅店住宿模块建StayRecord、费用 / 住宿授权与占用 → 更新Home空间为RoomAreaRef
→ 退房：CheckOut → 结束授权、释放占用、更新Home空间 → 触发旅店有清洁工作授权的工单（不授予住客Manager）
→ 未到：NoShow 结算 → 房间释放
```

入住由旅店经营实体的住宿模块创建 `StayRecord{StayRecordId, BusinessEntityId, RoomAreaRef, GuestId, 入住 / 退房时间, 费用与授权}`，建立入住占用及有效住宿授权，并将住客Home空间更新到 `RoomAreaRef`。客人不是客房Manager，不获得经营权或区域资产。

退房结束住宿授权、释放业务占用并更新Home空间，触发清洁需求；清洁工作授权来自旅店业务与劳动权限，明确允许对应工作，不把住客或清洁工设为客房Manager。工作点FIFO与实际门锁仍由实例管理，住宿授权不是门锁状态副本。

**尚未冻结边界**：入住结算方式、计费粒度 / 费率、费用授权的具体条款与字段、退房后Home空间的具体目标，以及出入 / 隐私 / 清洁访问策略仍待住宿专项确认；本卷不自定日结 / 月结 / 全款政策。定金比例、取消窗口、no-show与入住付尾款继续按§4现行规则，不因经营实体分离改动。

## 6. 后续版本范围

**做**：客房当面预订、定金、取消窗口、no-show、房间锁定、与入住/退房/清洁衔接。

**不做**：远程预约、餐厅桌位、包场、外卖、超售、预订排队。
