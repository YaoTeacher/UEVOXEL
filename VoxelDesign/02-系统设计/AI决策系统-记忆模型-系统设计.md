## 1. 定位：主观解读层

事件系统回答"发生了什么、谁知道、怎么传"（客观，全图一份账）；记忆系统回答"**这件事对我意味着什么**"（主观，每人一份解读）。分工一句话：

- **事件系统**：事实库、感知判定、传播管线——只记录，不评价。
- **记忆系统**：个人条目、解读规则、效果快照——只解读，不记内容（内容靠引用事实库）。

记忆条目**不复制事件内容**，只存"事件ID + 我怎么经历的 + 它对我造成了什么"。同一件事（如一场谋杀），凶手、死者家属、围观群众、道听途说者各持一条条目，解读出完全不同的效果——这是 Sims 2 记忆极性、DF 创伤系统的落地形态。

## 2. 个人记忆条目（FLifeHistoryEntry 扩展）

```
FLifeHistoryEntry（每个感知者一份，挂 NPC 侧）
├─ 事件ID          // 引用全局事实库（事件系统 §3.1），内容不复制
├─ 来源            // 亲历（我是主动者/接收者）| 目击（在场）| 听闻（传播到达）
├─ 角色位          // 主动者 | 接收者 | 在场者
├─ 确信度          // 亲历=满；听闻按渠道可信度折算（事件系统 §5.3）
├─ 封口标记        // 被封口后不参与传播（影响见事件系统 §7）
├─ 锚点标记        // 重大恩情/过节/创伤：唤起不打折、不参与 GC
├─ 快照            // 解读产出的【已求值修改器组 + 强度标量】（见 §4 第④步）
├─ 传播计数        // 我向外传播了几次（簿记归事件系统 §6）
└─ 时间
```

**快照语义（v2.0 核心）**：条目建成时，解读输出被**当场求值并整体快照**——修改器组的键、操作、值都是结算后的最终形态。**唤起 = 按快照直接重放**（普通记忆按曲线打折，锚点不打折），**不回头查规则、不回头查配置**。两条理由：规则集日后会改，旧记忆不应随之变化（防策划改表）；性格日后会漂移，写入时的调制结果必须保真（v1.2 已确立的强度快照原则，v2.0 扩展为整组快照）。

**锚点**：沿用 v1.2 口径——锚点 = 唤起不打折的记忆条目，且永不进 GC。结构事实永久，证据类印象有时效。

## 3. 解读规则集（UEventInterpretationSet 资产）

解读的业务逻辑全部在数据资产里，ConfigDataSubsystem 加载，改数据不改代码：

```
UEventInterpretationSet          // 数据资产
  事件类型Tag                     // 挂点；Tag 层级继承（挂在 Event.Death 的规则对 Event.Death.Murder 生效）
  规则列表:
FInterpretationRule
  ├─ 命中: 来源(亲历|目击|听闻|任意) / 角色位(主动者|接收者|在场)
  │        / 关系条件(我对[主动者|接收者]的关系轨条件, FTriggerCondition, 可空)
  ├─ 条件: 我的状态条件(FTriggerCondition, 可空)
  ├─ 输出: [{目标角色, 修改器组}]   // 目标角色: 我自己|主动者们|接收者们
  │        // 修改器 = {键, 操作, 值, 条件}（统一效应概念结构，不寻址）
  │        // 值四形态: 常量 | 事件值参数键 | 我的属性 | 共享公式资产
  ├─ 快照: {基准键, 调制维度[]}     // 强度 = 基准键效果值 × 调制维度
  └─ 种子: {目标Tag, 性格过滤}      // 可空；目标层唯一入口（目标层 §3.1）
```

- **多规则命中全部生效**，聚合归统一效应（Σ加 Π乘，覆盖最后；子类型规则后应用）
- **关系增量只是普通修改器**：键 = 关系 Map、子键 = 当事人 ID，不做特殊分类
- **塑变（性格永久漂移）只是普通修改器**：键 = 九维，与 Buff、属性共用一条管线
- **加载期校验**：类型 Tag、键命名空间、值参数枚举键全可校验；事件实例缺规则引用的值参数键 → 按 0 处理 + 开发期警告
- 事件类型 Tag **统一使用域前缀**（`Shop.*` / `Need.*` / `Time.*` / `Death.*` 等，见事件系统 §2），不设独立 `Event.*` 根。代价是事件 Tag 与其他业务 Tag 共享根命名空间，因此**必须靠事件目录做登记校验**：未登记的 Tag 不得当事件发布，避免与行为／交互 Tag 混用。解读规则仍按 `UEventInterpretationSet` 挂在事件类型 Tag 上并按层级继承。

## 4. 解读管线（每条目建成时走一遍）

```
条目建成（感知或传播到达）
  ① 收集: 按事件类型 Tag 层级收集所有挂接的规则集
  ② 过滤: 按来源 / 角色位 / 我对当事人的关系 / 我的状态 逐规则筛
  ③ 发放: 输出修改器组 → 目标角色解析成实体/子键 → 值求值
          → ApplyMods（统一效应单入口，带来源事件ID，可溯源）
  ④ 快照: 已求值修改器组 + 强度标量 写回条目（§2）
  ⑤ 结果: 结果段追加（事件系统 §3.3，反查日志）
  ⑥ 种子: 种子段性格过滤通过 → 种到目标层
```

## 5. 传播入口（记忆侧只管接收）

传播管线（闲聊/公告板/广告/通缉令、传播计数、掩盖与发现）归事件系统 §6-§7。记忆侧只有两条规则：

- **听闻条目照常解读**：传播到达 = 建一条来源=听闻的条目，走 §4 同一管线——"听说某人被羞辱"对听者产生的效果由规则集的"来源=听闻"分支决定
- **闲聊双重解读**：闲聊行为本身是一条普通社交事件（双方各建条目，照常解读）；闲聊携带的"话题=被传播事件ID"是通用间接机制，零配置
- **认知 = 知识型条目**：广告触达等信息源写入的不是事件条目，是知识型条目（`TMap<对象ID, 强度>`，可衰减可锚定，统一效应 §5）——店铺认知、门路、传闻地点同此结构

## 6. 唤起、消亡与规模控制

- **唤起（Recall）**：刺激出现（见到某人/到某地/同类事件）→ 按条目检索匹配 → 按快照重放（普通记忆按曲线打折，锚点不打折）。DF 式回响：不会每次全量重燃，但次次都疼。遇具体个体时唤起其所属群体的关联条目 = 初始态度（种族/派系偏见的涌现通道）
- **传染与八卦**：不再是记忆系统内部机制，统一走事件系统传播管线（接收侧见 §5）
- **两级弱痕迹**：共现/目击只写短期弱痕迹条目（几天衰减光），不创建关系 entry、不进长期——关系/认知的创建门槛是实质交互（关系系统 §6）。保证 300 NPC 的记忆流不被垃圾事件淹没
- **消亡**：条目按各自规则消亡（弱痕迹到期、非锚点条目被 GC）；**事实在最后一条引用它的条目消亡时打消亡标记**（不删存储，留审查，事件系统 §8）
- **口碑是查询，不是存储**：店铺口碑 = 店铺侧统计（[店铺经营 §1](/VoxelDesign/02-系统设计/AI决策系统-店铺经营-系统设计.md)），聚合值只作性能缓存（统一效应 §4）。**Mood 不在此列**——Mood 的存储与变动归《AI决策系统-需求与状态层-系统设计.md》§3（Dynamics + 事件脉冲即时修改 + 基线回归），记忆对 Mood 的影响只经解读输出修改器施加，不存在第二份情绪账。关系程度已存储化，不在此列（关系系统 v2.0）

## 8. 未决议题

1. 堆叠规则：同类型 + 同主关联方的重复条目——开新条 / 原条计数+刷新（RimWorld 式 stack 上限）
2. 唤起折扣曲线与锚点判定阈值
3. 条目 GC 策略细则（人口规模决定；锚点条目永不回收）
4. 伪事件（主动撒谎/伪造）与传闻失真：标记后做，最小版本不做（事件系统 §10）
5. 违逆检查（被指令违背强目标/强关系时的判定）归位：待定，候选 = 解读规则的条件段或目标层受挫通道
