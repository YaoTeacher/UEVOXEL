## 1. 系统上下文

### 1.1 系统边界

**模板系统负责**：
- 将选区中的体素结构保存为可复用的模板
- 模板资产的管理和组织（通过ConfigDataSubsystem）
- 模板的序列化分享（通过VXBP格式）
- 模板预览网格的生成和缓存
- 模板与阵列系统的集成

**模板系统不负责**：
- 选区定义（由选区系统负责）
- 体素世界修改（由BlockWorldSubsystem负责）
- 阵列定位点计算（由阵列系统负责）
- 撤销/重做（由HistoryComponent负责）
- MOD/DLC管理（预留TODO）

### 1.2 外部依赖

**依赖的系统**：
- **选区系统**：提供选区数据作为模板数据来源
- **ConfigDataSubsystem**：统一的模板资产管理
- **VoxelBlockWorldSubsystem**：读取体素数据进行模板采集
- **预览系统**：显示模板预览
- **VoxelControllerHistoryComponent**：记录模板操作

**被依赖的系统**：
- **UI系统**：模板创建、浏览、导入界面
- **阵列系统**：使用模板进行阵列放置
- **NPC系统**：预留TODO，NPC选择模板入驻

### 1.3 输入输出

**输入**：
- 选区数据（来自选区系统）
- 模板ID（用于加载）
- 分享代码字符串（用于导入）

**输出**：
- 模板资产（`UVoxelBuildingTemplateAsset`）
- 分享代码字符串（VXBP格式）
- 体素修改请求（`FVoxelEditModification`，用于建造）

## 2. 核心概念

### 2.1 基础概念

**体素模板资产（VoxelBuildingTemplateAsset）**
- 定义：体素结构的可复用数据资产
- 存储格式：.vxbp 自定义二进制文件
- 特征：稀疏存储（只存实体方块）
- 坐标：相对坐标（底面中心为原点）
- 优化：调色板索引存储（Palette + VoxelData索引）
- 数据：`TMap<FIntVector, int32>` VoxelData（存储调色板索引）
- 元数据：名称、描述、标签、作者、时间、统计
- 支持：运行时创建、打包后保存

**锚点（Anchor）**
- 定义：模板放置时的参考点
- 位置：固定为底面中心（模板内部原点）
- 计算：`((Size.X-1)/2, (Size.Y-1)/2, 0)`
- 用途：鼠标对齐、阵列定位
- 旋转：围绕锚点进行6向旋转

**相对坐标**
- 定义：相对于底面中心的坐标
- 范围：`(-AnchorOffset.X, -AnchorOffset.Y, 0)` 到 `(Size.X-1-AnchorOffset.X, Size.Y-1-AnchorOffset.Y, Size.Z-1)`
- 优点：放置时无需额外偏移，直接对齐鼠标位置

### 2.2 组合概念

**模板文件格式（.vxbp）**
- 文件头：Magic + Version + ThumbnailSize + PayloadSize
- 缩略图：PNG/JPG 格式（可选，用于快速预览）
- 核心数据：Zlib 压缩的序列化数据（FBlueprintCoreData）
- 优势：支持运行时创建、统一格式、快速扫描

**模板目录结构**
- 官方模板：`Content/VoxelTemplates/`（只读，打包后）
- 玩家模板：`Saved/VoxelTemplates/`（可读写，运行时创建）
- 统一管理：ConfigDataSubsystem 扫描两个目录

**分享代码（ShareCode）**
- 定义：模板的序列化字符串表示
- 格式：`"VXBP:" + Base64(Zlib(Serialize(Template)))`
- 用途：玩家间通过剪贴板分享
- 特点：极致压缩（调色板 + Zlib）、不含缩略图
- Tag处理：序列化为Tag名称，导入时验证并替换无效Tag

**文件分享（.vxbp）**
- 定义：模板的二进制文件表示
- 格式：.vxbp 文件（含缩略图 + 核心数据）
- 用途：玩家间通过文件拖拽分享
- 特点：支持缩略图预览、无需解压即可浏览元数据

### 2.3 行为概念

**模板采集（Capture）**
- 定义：将选区或Sub-Level场景转换为模板资产

**模式1：选区创建**
- 输入：选区（FVoxelSelection）
- 触发：UI按钮 → StateComponent → InteractComponent → TemplateManager
- 过程：
  1. 计算包围盒和锚点偏移（底面中心）
  2. 构建调色板（去重的Tag列表，排除脚手架）
  3. 遍历选区体素，转换为相对坐标（底面中心为原点）+ 调色板索引
  4. 自动生成元数据（作者、时间、统计）
  5. 填写手动元数据（名称、描述、标签）
  6. 检测MOD/DLC依赖
  7. 保存为 .vxbp 文件到 `Saved/VoxelTemplates/`
- 输出：`UVoxelBuildingTemplateAsset`（包含文件路径）

**模式2：Sub-Level创建**
- 输入：Sub-Level名称
- 触发：UI按钮 → StateComponent → InteractComponent → TemplateManager
- 过程：
  1. 加载Sub-Level场景
  2. 使用脚手架方块（`Voxel.Block.Scaffolding.*`）生成地基
  3. 扫描地基范围，读取所有体素
  4. 排除脚手架方块（按Tag层级）
  5. 同模式1的步骤2-7
- 输出：`UVoxelBuildingTemplateAsset`（包含文件路径）

**模板放置（Placement）**
- 定义：将模板数据写入体素世界
- 接口：`InteractComponent::ApplyTemplate()`
- 转换：`ConvertTemplateToEditRequests()` → BatchEditTool
- 输入：模板、锚点位置（底面中心对齐）、旋转（EActorDirection）、阵列配置
- 过程：
  1. 遍历模板中的每个方块（相对坐标）
  2. 应用6向旋转变换（围绕底面中心）
  3. 计算世界坐标（AnchorPosition + 旋转后的相对坐标）
  4. 生成EditRequest集合
  5. 批量提交到BatchEditTool执行
- 输出：`FVoxelEditModification`

**模板序列化（Serialization）**
- 定义：模板数据与字符串/文件的相互转换

**模式1：文件分享（.vxbp）**
- 导出：模板 → FBlueprintCoreData → Zlib压缩 → 文件头（+缩略图） → .vxbp 文件
- 导入：.vxbp 文件 → 解析文件头 → 提取缩略图 → Zlib解压 → FBlueprintCoreData → 模板
- 用途：文件拖拽分享、支持缩略图预览

**模式2：字符串分享（VXBP代码）**
- 导出：模板 → FBlueprintCoreData → Zlib压缩 → Base64 → VXBP代码
- 导入：VXBP代码 → Base64解码 → Zlib解压 → FBlueprintCoreData → 模板
- Tag替换流程：
  1. 验证所有Tag是否存在
  2. 存在无效Tag时显示替换UI
  3. 玩家选择替换目标（支持批量）
  4. 执行替换并保存 .vxbp 文件

### 2.4 概念关系

```
选区系统
  ↓ 提供
选区数据（FVoxelSelection）
  ↓
模板系统（采集）
  ↓
模板资产（UVoxelBuildingTemplateAsset）
  ↓
ConfigDataSubsystem（管理）
  ↓
预览系统（生成网格 + 缓存）
  ↓
阵列系统（阵列放置）
  ↓
编辑执行系统（写入世界）
```

## 3. 设计原则

### 3.1 架构原则

**统一数据管理**
- 模板文件由ConfigDataSubsystem统一扫描和管理
- 官方模板（Content/VoxelTemplates/）和玩家模板（Saved/VoxelTemplates/）使用同一套系统
- 支持运行时扫描和动态加载
- 支持 .vxbp 文件拖拽导入

**调色板优化**
- 使用调色板索引存储，减少冗余
- 存储int32索引而非FGameplayTag
- Zlib压缩效果更佳

**依赖声明**
- 明确声明MOD/DLC依赖（全部必需）
- 导入时验证依赖完整性
- 缺失依赖时提示玩家

### 3.2 接口设计原则

**最小知识**
- 模板数据对外部系统透明
- 不关心具体放置方式（单体/阵列）
- 不关心网格生成细节

**统一接口**
- 统一的加载/保存接口
- 统一的序列化接口
- 统一的验证接口

### 3.3 数据管理原则

**稀疏存储**
- 只存储实体方块
- 不存储空气方块
- 使用TMap自动去重

**调色板管理**
- Tag去重存储在Palette数组
- VoxelData存储int32索引
- 支持Compact操作清理未使用项

**相对坐标**
- 模板内部使用相对坐标
- 放置时转换为世界坐标
- 锚点固定为底面中心

**版本兼容**
- Tag序列化为名称，支持跨版本
- 导入时验证Tag有效性
- 无效Tag允许手动替换

### 3.4 性能原则

**按需生成**
- 不预生成所有预览网格
- 选择时才生成预览
- 使用UVoxelTemplatePreviewCache缓存

**缓存策略**
- 运行时内存缓存（LRU淘汰）
- 默认缓存50个模板的预览
- 缓存命中直接返回

**批量操作**
- 阵列放置使用批量提交
- 减少BlockWorld调用次数
- 单次历史记录

## 4. 系统约束

### 4.1 技术约束

**文件系统**
- 文件格式：.vxbp 自定义二进制格式
- 文件头：Magic + Version + ThumbnailSize + PayloadSize
- 目录结构：Content/VoxelTemplates/（官方）、Saved/VoxelTemplates/（玩家）
- 通过ConfigDataSubsystem扫描和管理

**数据结构**
- 核心数据：TArray<FGameplayTag> Palette
- 体素数据：TMap<FIntVector, int32> VoxelData（索引）
- 核心序列化结构：FBlueprintCoreData

**序列化**
- 文件模式：.vxbp 文件（含缩略图 + Payload）
- 字符串模式：VXBP代码（Base64 + Payload）
- 压缩使用Zlib，编码使用Base64
- 支持快速扫描（只读文件头和缩略图）

**Tag处理**
- 序列化为Tag名称（字符串）
- 导入时验证Tag是否存在
- 无效Tag需手动替换

### 4.2 性能约束

**模板大小**
- 单个模板不超过 10,000 方块
- 预览网格生成 < 200ms
- 加载时间 < 500ms

**内存占用**
- 预览缓存动态管理（基于历史活跃度）
- 缓存上限：50次历史记录未使用的模板
- 模板文件 < 1 MB（复杂模板，含缩略图）

### 4.3 业务约束

**撤销/重做**
- 单体放置：每个模板实例 = 1次历史记录
- 阵列放置：整列 = 1次历史记录（不论实例数量）
- 预览阶段参数调整：所有有影响的参数变化都记录历史
- 与现有历史系统兼容

**分享功能**
- 文件模式：.vxbp 文件拖拽分享（含缩略图）
- 字符串模式：VXBP代码粘贴分享（不含缩略图）
- 支持Tag缺失检测和手动替换
- 提供Tag替换UI（显示使用次数、支持批量替换）
- 支持依赖信息展示

**依赖管理**
- 所有MOD/DLC依赖都是必需的
- 缺失依赖时禁止导入或提示替换
- 预留TODO：MOD/DLC管理系统

## 5. 设计目标

### 5.1 功能目标

**核心功能**
1. 从选区采集模板
2. 模板资产的保存和加载（通过ConfigDataSubsystem）
3. 模板的元数据管理（名称、描述、标签）
4. 模板的单体放置
5. 模板的阵列放置（集成现有阵列系统）
6. 模板的序列化分享（VXBP格式）

**扩展功能**
1. 模板预览网格生成和缓存
2. 模板导入（支持Tag替换）
3. 模板库UI（浏览、搜索、标签筛选）
4. 模板导出为资产文件
5. 依赖检测和展示

### 5.2 质量目标

**可维护性**
- 数据结构清晰
- 易于扩展新功能
- 易于调试

**可测试性**
- 数据序列化可验证
- 模板采集可测试
- 分享功能可测试

### 5.3 用户体验目标

**易用性**
- 采集操作简单直观
- 分享代码易于复制粘贴
- 错误提示清晰

**可靠性**
- 分享代码校验
- 版本兼容性检查
- 数据损坏恢复

## 6. 与其他子系统的关系

### 6.1 与选区系统的关系

```
选区系统
  ↓ 提供
选区数据（FVoxelSelection）
  ↓
模板系统
  ↓ 使用
创建模板
```

**接口**：
- 选区数据提供位置和原始类型
- 模板系统计算相对坐标和调色板
- 自动生成统计信息

### 6.2 与ConfigDataSubsystem的关系

```
模板系统
  ↓ 创建/注册
模板资产
  ↓
ConfigDataSubsystem
  ↓ 统一管理
模板库（官方 + 玩家）
  ↓
UI/NPC系统
  ↓ 查询/使用
获取模板
```

**职责**：
- 模板系统：创建和保存模板资产
- ConfigDataSubsystem：统一加载和管理
- 动态注册玩家创建的模板

### 6.3 与阵列系统的关系

```
模板系统
  ↓ 提供
模板资产
  ↓
阵列系统
  ↓ 使用
计算阵列放置
```

**职责**：
- 模板系统：提供模板数据和锚点信息
- 阵列系统：计算多个实例的定位点
- 集成方式：扩展现有阵列配置，添加Template字段

**关键点**：
- 使用底面中心作为锚点
- 复用现有朝向模式（FollowCurve、FixedDirection、LookAtCenter）
- 批量提交优化

### 6.4 与预览系统的关系

```
模板系统
  ↓ 提供
模板资产
  ↓
UVoxelTemplatePreviewCache
  ↓ 检查缓存
缓存命中？
  ├─ 是 → 返回预览Mesh
  └─ 否 → UVoxelTemplateMeshGenerator生成
         ↓ 缓存结果
         返回预览
```

**接口**：
- `UVoxelTemplatePreviewCache::GetOrGeneratePreview(TemplateId)`
- LRU缓存策略，默认缓存50个
- 大型阵列（>100模板）显示边界框预览
