## 1. 核心命题：账本与余额分离

**关系程度是存储，不是查询。**

```
NPC 侧关系数据 = TMap<对方ID, FRelationshipEntry>
FRelationshipEntry = TMap<关系类型Tag, 程度值>
```

- **事件管线一扇出二**：事件发生 → (a) 写入记忆事件原子（**账**：何时、何地、何事、还有谁）；(b) 按解读规则集输出的增量改程度值（《AI决策系统-记忆模型-系统设计.md》§3）（**余额**）。两个汇、同一源，不存在双权威
- **记忆不参与程度计算**，只负责回溯：话题、闪回、玩家查岗、侦探取证的叙事材料
- **值域按类型配置**：bool 轨（制度有无）/ int 轨（派系 Rank）/ float 轨（情感程度）——一个 entry 容器，类型配置声明值域，新关系类型（师徒/牌搭子）只加配置不动代码

## 2. 关系类型：两类行为

| 类别 | 类型 | 程度语义 | 衰减 |
|------|------|---------|------|
| **制度型**（解除才消失） | Employer / Employee / Spouse / Family | 该关系的状况（雇佣满意度、婚姻质量），事件驱动 | 不自动衰减 |
| **情感型**（可生可灭） | Friendship（[-100,100]，负值区=交恶）/ Romance / Grudge（独立仇恨轨） | 深浅 | 长期不见则衰减，归零删轨 |

- **阶段 = Friendship 轨的阈值视图**（沿用旧 §16.5 意图）：陌生→面熟→熟络→亲密；负向：不快→交恶。阶段门控交互，交互配置以 Tag 声明阶段条件
- **双轨制兑现**：SIM4 的友情条/爱情条 = Friendship/Romance 两条存储轨；Grudge 与 Friendship 独立并存 = 爱恨交织（挚友+死仇可同时挂在同一人身上）
- **锚点 = 衰减下限**：重大事件（大恩/死仇/共同出生入死）把某轨的衰减地板钉住——"被锚定的关系不掉回锚点阶段以下"的旧语义兑现
- **sentiment 不做独立结构**：总量=程度值，具体=单条未衰减记忆的回溯。"麻吉但揣着记恨"= Friendship 高 + 一条记恨记忆，见面时由记忆唤起触发心情/话题
- **嫉妒/黑暗动机**：目击伴侣调情 → Romance 大负增量 + Grudge 正增量 + 记忆锚点

## 3. 关系对象不局限于人

关系目标须区分对象类别：人物用 `CreatureId`；店铺生意用全局稳定 `BusinessEntityId`，不能借 `AreaId` 或 `CreatureId` 代替；派系 / 群体仍按各自类型引用。三个全局业务身份统一为 GUID，规则见[总纲 §2.7](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)；不再使用 `ShopId` 别名。经营业务唯一归 Global `BusinessEntities`，区域只空间校验，路过 / 导航另取 `AreaRef={SceneId,AreaId}`。**人员基础阵营归属另读名册生成时确定的 `FactionTag`；本节后续Rank / Attitude不取代基础阵营，也不进入V1评分。**

- **对店：常客轨（后续）**——以BusinessEntityId标识生意，表达我与这家店的关系程度。V1只保存NPC所有的 `KnownShopIds:TSet<BusinessEntityId>`，只记知道生意，不存强度、不衰减、不锚定，也不运行常客轨；普通路过 / 交易写集合不增加首客保护，完整关系与认知扩展留后续。
- **对派系：`{Rank: int[0..4], Attitude: float[-5,+5]}`**
  - Rank：0=非成员 / 1=成员 / 2=高级 / 3=骨干 / 4=领袖。Rank=0 即"非成员"，无独立布尔；领袖唯一性=派系配置声明各级坑位数
  - Attitude：个体对派系的态度（憎恶↔忠诚）。**非成员钳制 ≤ +2**：可憎恶（受害者）、可仰慕（同情者），忠诚必须有成员身份
  - **资格与态度分离**：成员+负态度是正常组合——触发叛逃判定 / 可被收买（贿赂找高 Rank 低 Attitude）/ 派系任务怠工 / 被清洗。细则归黑暗玩法模块
  - 阵营矩阵 `DT_FactionRelations`（派系↔派系）保留为派系实体属性；个体态度可背叛阵营立场（腐败卫兵给帮派通风报信）
  - 稀疏性：Rank=0 且 Attitude=0 → entry 不存在；entry 只对实际打过交道的派系创建
- **对种族等群体：Attitude 轨（无 Rank）**——种族=可作关系对象的虚拟实体。文化偏见=群体八卦传染改写群体轨；遇到具体个体时唤起群体轨 = 初始态度。种族小圈子、世仇全是传染涌现，无种族专属系统

## 4. 组织成员统一形状

**制度轨（成员事实）+ 等级/岗位属性 + 态度轨**：

- 派系：Rank + Attitude（§3）
- 雇佣唯一事实在Global统一雇佣登记：`EmploymentId / CreatureID / EmployerBusinessEntityId / 薪酬条款`，雇主是经营实体，不直接人员雇佣人员；经营实体与NPC只引用同一记录，图外合同同样有效。V1招聘只取无有效合同者，不因关系轨吞并旧合同。Employee制度轨如在后续展示，只投影有效合同、不另存雇佣事实；对老板个人的Friendship仍是人物关系，不能代替业务雇主、名册或工资合同。
- 玩家的店：孩子 = 首个店员（Family 轨 + Employee 轨双轨，见 §9）

## 5. 增长、衰减、传染与 GC

- **增长**：事件增量（解读规则集输出，记忆模型 §3）× 九维修饰器——Sociality→友情增益率/主动发起率；Altruism→正向互动加成；Competitiveness→Grudge 衰减常数减小（记仇）；Fastidiousness→差评事件产生率；SelfConsistency→传染打折（∝ 1−SC）
- **衰减**：情感轨按各自衰减常数；制度轨不衰减；锚点轨有下限
- **传染/八卦 = 同一条管线打折**：听闻事件 → 打折写入记忆 + 打折改程度。去意传染、排队怨气、话题传播无特例
- **GC**：情感轨归零删轨；entry 无轨且无制度链接删 entry；锚点轨不删

## 6. 两级数据控制（防数据爆炸）

- **弱痕迹层**：共现/目击只写短期记忆（几天衰减光），**不创建任何 entry**——O(n²) 消除
- **entry 创建门槛**：实质交互（对话/交易/服务/冲突/共同探索/主动观察）才创建
- **陌生人变朋友的通道**：同店共现按概率**采样触发闲聊事件**（DF 酒馆式配对）——闲聊是实质交互，创建 entry；店铺是闲聊触发器 = 全镇社交枢纽；每 NPC 每日主动社交次数上限 → 增速硬顶
- **面熟阶段重定位**：entry 已建但程度低的阈值区间（第一次交易后即面熟），不是共现攒出来的

## 7. 玩家侧认知档案（脸盲玩法）

玩家没有记忆流与 AI 管线——"玩家认清 NPC"需要玩家侧独立存储：

```
TMap<NPCID, FPlayerKnowledgeEntry>
FPlayerKnowledgeEntry { 认知度: float, 已知信息: 逐条解锁集合, 玩家备注: FString }
```

- **认知度来源 = 所有形式的接触**：聊天/服务/共同探索/主动观察，与 NPC 侧共享同一事件管线（一个玩家参与的事件扇出三汇：NPC 记忆、NPC 对玩家程度、玩家认知档案）
- **信息解锁三通道**：
  - 阈值通道（v4.2 意图保留）：低=素体剪影 / 中=真名+职业 / 高=完整面板
  - 观察通道（SIM4 learned-traits 式）：目击维度表征行为 → 点亮"此人疑似 X"——九维的玩家侧出口，了解人靠观察不靠面板全知
  - 听闻通道：第三方传授（孩子回家说"那是肉铺老张"）= 八卦传染的玩家侧版本
- **认知度衰减**：已点亮信息不熄灭，但认知度跌回阈值下时显示退化（"那个谁来着"——名字模糊、面板回锁）；重新交互快速回升（熟人是重新熟悉）
- **不对称是设计意图**：NPC 对玩家的 Friendship 与玩家对 NPC 的认知度是两条独立轨——"他把你当挚友，你不记得他"是涌现叙事

## 8. 结伴出行（串门化约）

**串门不是特殊交互，是结伴出行行为的目的地分支**：

- 触发：关系程度够（熟络以上）的 NPC 发起结伴
- 目的地三档模拟粒度：实体住所 → 真实进入、屋内活动播出；抽象住所 → 进入-停留-出来（不模拟内部）；店铺/酒馆/餐馆 → 正常消费行为，结伴进行（拼桌/同行）
- 关系增益 = 结伴期间的标准交互事件，走统一管线，无特例
- 与旧分册"组团逛街/拼桌"概念统一

## 9. 家族、婚姻与孩子

- Family / Spouse 制度轨收录，**存在、暂不细化**（类型可数据驱动扩展）
- **孩子 = 首个细化实例**：剧本关键角色（出生系统后续）+ Family 轨 + Employee 轨（首个店员）+ 可塑培养（成长通道见基础层 §2）+ 认知指引（§7 听闻通道的教程化包装）。"家族经营"从这里开始
