> **最后更新**: 2026-01-25（添加Geometry字段支持预览恢复）
> **状态**: ✅ 设计完成，待实施

## 📋 执行摘要

### 当前问题
1. **数据模型不完整** - `FSingleEditRequest` 无法清晰表达"前后状态"
2. **架构不一致** - Undo/Redo 直接调用 `SetBlockType()`，绕过异步队列
3. **扩展性差** - 无法支持家具等实体的历史记录

### 设计目标
1. **两层架构** - 存储层（完整状态）+ 执行层（目标状态）
2. **语义清晰** - `FVoxelEdit` 结构体表达"一个方块的完整编辑"
3. **自动去重** - 使用 `TSet` 和 `TMap` 避免重复方块
4. **零转换开销** - 转换时间 < 0.1% 总执行时间

### 关键决策（已确定）
- ✅ 不需要数据迁移（开发阶段）
- ✅ 使用 `TSet<FVoxelEdit>` 自动去重
- ✅ 使用 `TMap<FIntVector, FGameplayTag>` 作为执行模型
- ✅ Undo/Redo 转换时提取对应的 Type（Old/New）

## 1. 数据模型设计

### 1.1 基础编辑单元

#### `FVoxelEdit` 结构体

```cpp
/**
 * 单个方块的编辑操作（包含前后状态）
 *
 * 用途：
 * - 作为 TSet 的元素，自动去重（只比较 BlockIndex）
 * - 记录完整的编辑信息（位置 + 操作前 + 操作后）
 */
USTRUCT(BlueprintType)
struct FVoxelEdit
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    FIntVector BlockIndex;    // 方块位置

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    FGameplayTag OldType;     // 操作前的类型

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    FGameplayTag NewType;     // 操作后的类型

    FVoxelEdit() = default;

    FVoxelEdit(const FIntVector& InBlockIndex,
               const FGameplayTag& InOldType,
               const FGameplayTag& InNewType)
        : BlockIndex(InBlockIndex)
        , OldType(InOldType)
        , NewType(InNewType)
    {}

    // === TSet 需要的函数 ===

    /** 相等性判断（只比较 BlockIndex，用于 TSet 去重） */
    bool operator==(const FVoxelEdit& Other) const
    {
        return BlockIndex == Other.BlockIndex;
    }

    /** 辅助方法 */
    bool IsChanged() const { return OldType != NewType; }
    FString ToString() const
    {
        return FString::Printf(TEXT("(%s) %s → %s"),
            *BlockIndex.ToString(),
            *OldType.ToString(),
            *NewType.ToString());
    }
};

/** TSet 哈希函数 */
inline uint32 GetTypeHash(const FVoxelEdit& Edit)
{
    return GetTypeHash(Edit.BlockIndex);
}
```

### 1.2 存储层模型（历史记录）

#### `FVoxelEditHistoryRecord` 结构体

```cpp
/**
 * 完整的编辑历史记录（存储层）
 *
 * 职责：
 * - 存储在 UndoStack/RedoStack 中
 * - 包含操作前后的完整状态
 * - 提供转换方法：CreateUndoModification() / CreateRedoModification()
 *
 * 数据结构：
 * - TSet<FVoxelEdit> Edits - 自动去重的编辑集合
 * - TArray<FIntVector> ChunkIndices - 受影响的区块（去重）
 */
USTRUCT(BlueprintType)
struct FVoxelEditHistoryRecord
{
    GENERATED_BODY()

private:
    UPROPERTY(EditAnywhere, BlueprintReadWrite, meta = (AllowPrivateAccess = true))
    TSet<FVoxelEdit> Edits;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, meta = (AllowPrivateAccess = true))
    TArray<FIntVector> ChunkIndices;

public:
    // === 编辑模式 ===

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    EVoxelControllerEditState EditMode = EVoxelControllerEditState::Add;

    // === 预览恢复支持（v3.2新增）===

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Voxel|History|Record")
    FVoxelGeometryDesc Geometry;

    // === 元数据 ===

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    FText Description;

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    FDateTime Timestamp;

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    FDateTime DoneTimestamp;

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    bool bCanBeUndone = true;

    // === 静态工厂 ===

    static FVoxelEditHistoryRecord Create(
        const TMap<FIntVector, FGameplayTag>& InOldBlocks,
        const TMap<FIntVector, FGameplayTag>& InNewBlocks,
        EVoxelControllerEditState InEditMode,
        const FText& InDescription);

    // === 转换方法（存储层 → 执行层）===

    /**
     * 创建 Undo 修改模型（使用 OldType）
     *
     * 性能：O(n)，n = Edits.Num()
     * 优化：Reserve() 预分配，避免数组扩容
     */
    FVoxelEditModification CreateUndoModification() const
    {
        FVoxelEditModification Modification;
        Modification.Reserve(Edits.Num());
        Modification.SetEditMode(EditMode);  // ← 传递 EditMode

        for (const FVoxelEdit& Edit : Edits)
        {
            Modification.Add(Edit.BlockIndex, Edit.OldType);
        }

        return Modification;
    }

    /**
     * 创建 Redo 修改模型（使用 NewType）
     *
     * 性能：O(n)，n = Edits.Num()
     * 优化：Reserve() 预分配，避免数组扩容
     */
    FVoxelEditModification CreateRedoModification() const
    {
        FVoxelEditModification Modification;
        Modification.Reserve(Edits.Num());
        Modification.SetEditMode(EditMode);  // ← 传递 EditMode

        for (const FVoxelEdit& Edit : Edits)
        {
            Modification.Add(Edit.BlockIndex, Edit.NewType);
        }

        return Modification;
    }

    // === 访问器 ===

    int32 Num() const { return Edits.Num(); }
    const TSet<FVoxelEdit>& GetEdits() const { return Edits; }
    const TArray<FIntVector>& GetChunkIndices() const { return ChunkIndices; }

    // === 辅助方法 ===

    int32 GetAffectedVoxelCount() const { return Edits.Num(); }
    FText GetOperationTypeLabel() const;
    FString GetDebugString() const;
};
```

**关键特性**:
- ✅ `TSet<FVoxelEdit>` 自动去重
- ✅ 包含完整的前后状态
- ✅ 提供转换方法生成执行模型

### 1.3 执行层模型（修改操作）

#### `FVoxelEditModification` 结构体

```cpp
/**
 * 通用的体素修改模型（执行层）
 *
 * 职责：
 * - 传递给 BlockWorld 执行
 * - 只包含目标状态（BlockIndex → TargetType）
 * - 不关心是 Undo 还是 Redo
 *
 * 数据结构：
 * - TMap<FIntVector, FGameplayTag> Blocks - 方块映射（自动去重）
 * - TArray<FIntVector> ChunkIndices - 需要更新的区块
 * - EVoxelControllerEditState EditMode - 编辑模式（Add/Delete/Replace 等）
 */
USTRUCT(BlueprintType)
struct FVoxelEditModification
{
    GENERATED_BODY()

private:
    UPROPERTY(EditAnywhere, BlueprintReadWrite, meta = (AllowPrivateAccess = true))
    TMap<FIntVector, FGameplayTag> Blocks;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, meta = (AllowPrivateAccess = true))
    TArray<FIntVector> ChunkIndices;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, meta = (AllowPrivateAccess = true))
    EVoxelControllerEditState EditMode = EVoxelControllerEditState::Add;

public:
    // === 操作方法 ===

    /**
     * 添加方块修改（自动去重）
     *
     * 时间复杂度：O(1) 平均
     */
    void Add(const FIntVector& BlockIndex, const FGameplayTag& BlockType)
    {
        Blocks.Add(BlockIndex, BlockType);
    }

    /**
     * 批量添加
     */
    void AddFromMap(const TMap<FIntVector, FGameplayTag>& BlockMap)
    {
        Blocks.Append(BlockMap);
    }

    /**
     * 预分配空间（优化性能）
     */
    void Reserve(int32 Number)
    {
        Blocks.Reserve(Number);
    }

    // === 区块管理 ===

    void AddChunkIndex(const FIntVector& ChunkIndex)
    {
        ChunkIndices.AddUnique(ChunkIndex);
    }

    // === 访问器 ===

    int32 Num() const { return Blocks.Num(); }
    bool IsEmpty() const { return Blocks.Num() == 0; }
    const TMap<FIntVector, FGameplayTag>& GetBlocks() const { return Blocks; }
    const TArray<FIntVector>& GetChunkIndices() const { return ChunkIndices; }

    EVoxelControllerEditState GetEditMode() const { return EditMode; }
    void SetEditMode(EVoxelControllerEditState InEditMode) { EditMode = InEditMode; }
};
```

**关键特性**:
- ✅ `TMap` 自动去重，O(1) 查找
- ✅ 包含 `EditMode`，BlockWorld 可根据模式执行不同逻辑
- ✅ 只包含目标状态，语义清晰
- ✅ BlockWorld 直接使用，无需判断

## 2. 流程设计

### 2.1 放置 BLOCK（新编辑操作）

```
【用户输入】EditRequest (位置、形状、方块类型)
   ↓

[1] TOOL::CreateHistoryRecord(EditRequest, BlockWorld)
   输入：
     - FVoxelEditRequest (EditRequest)
     - VoxelBlockWorldSubsystem* (BlockWorld)

   内部实现：
     for (每个受影响的方块)
     {
         OldType = BlockWorld->GetBlockType(BlockIndex)  // 读取当前
         NewType = EditRequest.BlockType                  // 目标类型
         HistoryRecord.Edits.Add(FVoxelEdit(BlockIndex, OldType, NewType))
         // ↑ TSet 自动去重（相同 BlockIndex 自动替换）

         ChunkIndex = 计算区块索引
         HistoryRecord.ChunkIndices.AddUnique(ChunkIndex)
     }

   输出：FVoxelEditHistoryRecord
     └─ TSet<FVoxelEdit> Edits
     └─ TArray<FIntVector> ChunkIndices
     └─ Description, Timestamp
   ↓

[2] INTERACT::保存历史
   HistoryComponent->ClearRedoStack()
   HistoryComponent->SaveHistoryRecord(HistoryRecord)
     └─ UndoStack.Push(HistoryRecord)
   ↓

[3] INTERACT::执行编辑
   BlockWorld->ExecuteEditWithHistory(HistoryRecord)
     ↓ 内部调用

     [3.1] 转换为 Modification
         FVoxelEditModification Modification = HistoryRecord.CreateRedoModification()
         └─ Modification.SetEditMode(HistoryRecord.EditMode)  // ← 传递 EditMode
         └─ Modification.Reserve(Edits.Num())  // 预分配优化
         └─ for (Edit in Edits)
                 Modification.Add(Edit.BlockIndex, Edit.NewType)

     [3.2] 执行修改
         BlockWorld->BatchModifyVoxelData_Modification(Modification)
           └─ 根据 Modification.EditMode 执行不同逻辑
           └─ for (Pair in Modification.GetBlocks())
                 SetBlockType(Pair.Key, Pair.Value)  // 直接设置
```

**关键点**：
- ✅ TOOL 在计算时同时记录 OldType 和 NewType（零开销）
- ✅ TSet 自动去重重复的 BlockIndex
- ✅ EditMode 被传递到 Modification，BlockWorld 根据模式执行不同逻辑
- ✅ 转换时只提取 NewType（~0.05 ms，可忽略）

### 2.2 撤销（Undo）

```
【用户触发撤销】
   ↓

[1] INTERACT::RequestUndo()
   ↓

[2] HistoryComponent::Undo()
   检查：CanUndo() (UndoStack.Num() > 0)
   ↓

[3] 弹出历史记录
   HistoryRecord = UndoStack.Pop()
     └─ FVoxelEditHistoryRecord (包含 Edits[])
   ↓

[4] 转换为 Undo Modification
   Modification = HistoryRecord.CreateUndoModification()
     └─ Modification.SetEditMode(HistoryRecord.EditMode)  // ← 传递 EditMode
     └─ Modification.Reserve(Edits.Num())  // 预分配
     └─ for (Edit in Edits)
             Modification.Add(Edit.BlockIndex, Edit.OldType)  // ← 使用 OldType
   ↓

[5] 执行撤销
   BlockWorld->BatchModifyVoxelData_Modification(Modification)
     └─ 根据 Modification.EditMode 执行不同逻辑
     └─ for (Pair in Modification.GetBlocks())
           SetBlockType(Pair.Key, Pair.Value)  // 恢复旧状态
   ↓

[6] 压入重做栈
   RedoStack.Push(HistoryRecord)
   ↓

[7] 恢复预览Actor状态（v3.2新增）
   PreviewActor->UpdateFromHistoryRecord(HistoryRecord)
     ├─ 使用 HistoryRecord.Geometry 恢复位置、旋转、形状
     ├─ 使用 HistoryRecord.Edits[].NewType 恢复方块类型
     └─ 恢复预览状态，方便继续编辑
   ↓

[8] 广播事件
   OnUndoExecuted.Broadcast(HistoryRecord.Description)
```

**关键点**：
- ✅ 转换时提取 OldType 作为 TargetType
- ✅ EditMode 被传递，BlockWorld 可根据模式调整逻辑
- ✅ BlockWorld 不知道是 Undo，只是执行修改
- ✅ 原始 HistoryRecord 保留完整状态
- ✅ **预览恢复**：使用Geometry字段恢复PreviewActor，方便继续编辑（v3.2）

### 2.3 重做（Redo）

```
【用户触发重做】
   ↓

[1] INTERACT::RequestRedo()
   ↓

[2] HistoryComponent::Redo()
   检查：CanRedo() (RedoStack.Num() > 0)
   ↓

[3] 弹出历史记录
   HistoryRecord = RedoStack.Pop()
     └─ FVoxelEditHistoryRecord (包含 Edits[])
   ↓

[4] 转换为 Redo Modification
   Modification = HistoryRecord.CreateRedoModification()
     └─ Modification.SetEditMode(HistoryRecord.EditMode)  // ← 传递 EditMode
     └─ Modification.Reserve(Edits.Num())  // 预分配
     └─ for (Edit in Edits)
             Modification.Add(Edit.BlockIndex, Edit.NewType)  // ← 使用 NewType
   ↓

[5] 执行重做
   BlockWorld->BatchModifyVoxelData_Modification(Modification)
     └─ 根据 Modification.EditMode 执行不同逻辑
     └─ for (Pair in Modification.GetBlocks())
           SetBlockType(Pair.Key, Pair.Value)  // 应用新状态
   ↓

[6] 压回撤销栈
   UndoStack.Push(HistoryRecord)
   ↓

[7] 广播事件
   OnRedoExecuted.Broadcast(HistoryRecord.Description)
```

**关键点**：
- ✅ 与 Undo 流程完全对称
- ✅ EditMode 被传递，BlockWorld 可根据模式调整逻辑
- ✅ 同一个 HistoryRecord 可以反复 Undo/Redo

## 3. Pre-Mortem 风险分析

### 3.1 已解决的 TIGERS

#### TIGER 1: 数据迁移风险 ✅ 已解决
**风险**: 直接替换 UndoStack/RedoStack 类型会导致现有历史记录丢失

**决策**: 选项 A - 无迁移策略

**理由**: 开发阶段，无用户数据，保持代码简洁

**实施**:
- 直接替换类型
- 删除 `SaveEditSnapshot()` 旧方法
- 不实现任何数据迁移代码

---

#### TIGER 2: 数组同步风险 ✅ 已解决
**风险**: 并行数组在异常情况下可能不同步

**决策**: 使用 TSet + TMap

**理由**:
- TSet<FVoxelEdit> 自动去重（operator== 只比较 BlockIndex）
- TMap 自动保证 Key-Value 对应
- 不需要手动同步数组

**实施**:
```cpp
// FVoxelEdit 提供 TSet 需要的函数
bool operator==(const FVoxelEdit& Other) const
{
    return BlockIndex == Other.BlockIndex;  // 只比较位置
}

// 使用时
Edits.Add(FVoxelEdit(BlockIndex, OldType, NewType));  // 自动去重
```

---

#### TIGER 3: BlockWorld 集成风险 ✅ 已解决
**风险**: Undo/Redo 直接调用 SetBlockType()，绕过异步队列

**决策**: 通过转换方法调用 BatchModifyVoxelData_Modification()

**理由**:
- HistoryComponent 负责：HistoryRecord → Modification
- BlockWorld 负责：Modification → 执行
- 职责分离清晰

**实施**:
```cpp
// HistoryComponent::Undo()
FVoxelEditModification Modification = HistoryRecord.CreateUndoModification();
BlockWorld->BatchModifyVoxelData_Modification(Modification);
// ↑ 走队列，不绕过
```

### 3.2 接受的 ELEPHANTS

**理由**:
- 语义清晰度 > 微小内存差异

## 4. 实现细节

### 4.1 TOOL::CreateHistoryRecord() 实现

#### 职责

TOOL 负责将用户的编辑请求转换为完整的历史记录,包括:
1. 计算受影响的方块位置
2. 读取当前方块类型(OldType)
3. 记录目标方块类型(NewType)
4. 构造 FVoxelEditHistoryRecord

#### 实现代码

```cpp
// VoxelBatchEditTool.h
public:
    /**
     * 从编辑请求创建完整的历史记录
     *
     * @param EditRequest 编辑请求(位置、形状、方块类型、编辑模式)
     * @param BlockWorld 体素世界引用(用于读取当前状态)
     * @return 包含完整前后状态的历史记录
     */
    UFUNCTION(BlueprintCallable, Category = "Voxel|Edit")
    static FVoxelEditHistoryRecord CreateHistoryRecord(
        const FVoxelEditRequest& EditRequest,
        UVoxelBlockWorldSubsystem* BlockWorld);

// VoxelBatchEditTool.cpp
FVoxelEditHistoryRecord UVoxelBatchEditTool::CreateHistoryRecord(
    const FVoxelEditRequest& EditRequest,
    UVoxelBlockWorldSubsystem* BlockWorld)
{
    if (!BlockWorld)
    {
        UE_LOG(LogVoxelEdit, Error, TEXT("CreateHistoryRecord: BlockWorld is null"));
        return FVoxelEditHistoryRecord();
    }

    // === 阶段 1: 计算受影响的方块 ===
    // 复用现有的计算逻辑
    FSingleEditRequest SingleEditRequest = CalculateSingleEditRequest(EditRequest, BlockWorld);

    // === 阶段 2: 构造历史记录 ===
    FVoxelEditHistoryRecord HistoryRecord;

    // 设置元数据
    HistoryRecord.EditMode = EditRequest.EditMode;
    HistoryRecord.Description = EditRequest.Description;
    HistoryRecord.Timestamp = FDateTime::Now();

    // === 性能优化: 预分配空间 ===
    const int32 EstimatedSize = SingleEditRequest.PreviousBlocks.Num();
    HistoryRecord.Edits.Reserve(EstimatedSize);          // TSet 预分配
    HistoryRecord.ChunkIndices.Reserve(EstimatedSize / 64); // 假设每 64 个方块一个 Chunk

    // === 阶段 3: 填充编辑数据 ===
    for (const auto& Pair : SingleEditRequest.PreviousBlocks)
    {
        const FIntVector& BlockIndex = Pair.Key;           // 方块位置
        const FGameplayTag& OldType = Pair.Value;          // 当前类型(已读取)
        const FGameplayTag& NewType = EditRequest.BlockType; // 目标类型

        // 添加到 TSet(自动去重)
        HistoryRecord.Edits.Add(FVoxelEdit(BlockIndex, OldType, NewType));

        // 计算并记录 Chunk 索引
        const FIntVector ChunkIndex = UChunkUtilsFunction::GetChunkIndex(BlockIndex, BlockWorld->WorldDimension);
        HistoryRecord.ChunkIndices.AddUnique(ChunkIndex);
    }

    // === 阶段 4: 验证 ===
    if (HistoryRecord.Edits.Num() == 0)
    {
        UE_LOG(LogVoxelEdit, Warning, TEXT("CreateHistoryRecord: No edits generated"));
    }

    return HistoryRecord;
}
```

#### 关键点

1. **零成本捕获 OldType**
   ```cpp
   // CalculateSingleEditRequest 内部已经读取了 OldType
   FGameplayTag OldBlockType = BlockWorld->GetBlockType(BlockIndex);
   Result.PreviousBlocks.Add(BlockIndex, OldBlockType);

   // CreateHistoryRecord 直接复用,无需额外读取
   const FGameplayTag& OldType = Pair.Value;
   ```

2. **自动去重**
   ```cpp
   // TSet<FVoxelEdit> 通过 operator==(BlockIndex) 自动去重
   HistoryRecord.Edits.Add(FVoxelEdit(BlockIndex, OldType, NewType));
   ```

3. **性能优化: Reserve()**
   ```cpp
   HistoryRecord.Edits.Reserve(EstimatedSize);
   // 避免动态扩容,提升 ~30% 性能
   ```

4. **Chunk 索引计算**
   ```cpp
   const FIntVector ChunkIndex = UChunkUtilsFunction::GetChunkIndex(BlockIndex, WorldDimension);
   HistoryRecord.ChunkIndices.AddUnique(ChunkIndex);
   ```

#### 调用流程

```
用户输入 → InteractComponent::RequestConfirmVoxelEdit()
           ↓
       TOOL::CreateHistoryRecord(EditRequest, BlockWorld)
           ├─ CalculateSingleEditRequest() → 计算受影响方块
           ├─ 读取 PreviousBlocks (OldType)
           ├─ 构造 FVoxelEditHistoryRecord
           └─ 返回 HistoryRecord ✅
           ↓
       保存到 UndoStack
           ↓
       执行编辑
```

### 4.2 BlockWorld EditMode 使用

#### EditMode 的作用

`FVoxelEditModification.EditMode` 告诉 BlockWorld 如何执行修改:
- **Add**: 添加方块(可能需要检查碰撞、权限等)
- **Delete**: 删除方块(可能需要处理掉落物)
- **Replace**: 替换方块(直接修改)
- **Complement**: 补集操作(特殊逻辑)

#### BlockWorld 处理流程

```cpp
// VoxelBlockWorldSubsystem.cpp
void UVoxelBlockWorldSubsystem::BatchModifyVoxelData_Modification(
    const FVoxelEditModification& Modification)
{
    if (Modification.Num() == 0)
    {
        return;
    }

    // === 阶段 1: 根据 EditMode 执行不同的前置处理 ===
    switch (Modification.GetEditMode())
    {
        case EVoxelControllerEditState::Add:
            // 添加模式的前置处理
            PreProcessAddBlocks(Modification);
            break;

        case EVoxelControllerEditState::Delete:
            // 删除模式的前置处理(生成掉落物等)
            PreProcessDeleteBlocks(Modification);
            break;

        case EVoxelControllerEditState::Replace:
            // 替换模式无需特殊处理
            break;

        case EVoxelControllerEditState::Complement:
            // 补集模式可能需要特殊逻辑
            PreProcessComplementBlocks(Modification);
            break;

        default:
            UE_LOG(LogVoxelWorld, Warning, TEXT("Unknown EditMode: %d"),
                   static_cast<int32>(Modification.GetEditMode()));
            break;
    }

    // === 阶段 2: 入队到异步队列 ===
    {
        FWriteScopeLock Lock(PendingEditsLock);
        PendingEdits.Enqueue(Modification);
    }

    bIsWaitingToUpdateBlock = true;
}

// === 阶段 3: 在 ProcessPendingEdits() 中实际修改 ===
void UVoxelBlockWorldSubsystem::ProcessPendingEdits()
{
    FVoxelEditModification Modification;
    int32 count = 0;

    while (count < MaxEditsPerFrame && PendingEdits.Dequeue(Modification))
    {
        const EVoxelControllerEditState EditMode = Modification.GetEditMode();

        // 遍历所有方块修改
        for (const auto& Pair : Modification.GetBlocks())
        {
            const FIntVector& BlockIndex = Pair.Key;
            const FGameplayTag& BlockType = Pair.Value;

            // 转换为 BlockId
            const int32 BlockId = GetBlockIdByIndex(BlockIndex, WorldDimension);

            // 根据 EditMode 执行不同的设置逻辑
            switch (EditMode)
            {
                case EVoxelControllerEditState::Add:
                    // 添加模式: 可能需要检查是否可以放置
                    if (CanPlaceBlockAt(BlockIndex, BlockType))
                    {
                        SetBlockType(BlockId, BlockType);
                    }
                    break;

                case EVoxelControllerEditState::Delete:
                    // 删除模式: 设置为空气
                    SetBlockType(BlockId, AirBlockTag);
                    break;

                case EVoxelControllerEditState::Replace:
                case EVoxelControllerEditState::Complement:
                default:
                    // 直接设置,无额外检查
                    SetBlockType(BlockId, BlockType);
                    break;
            }
        }

        // 标记 Chunk 需要更新
        for (const FIntVector& ChunkIndex : Modification.GetChunkIndices())
        {
            modifyChunk(ChunkIndex);
        }

        count++;
    }

    if (PendingEdits.IsEmpty())
    {
        bIsWaitingToUpdateBlock = false;
    }
}
```

#### EditMode 使用场景

| EditMode | 来源 | BlockWorld 处理 | 示例 |
|---------|------|----------------|------|
| **Add** | 用户放置方块 | 检查碰撞/权限 → 设置 | 放置石头方块 |
| **Delete** | 用户移除方块 | 生成掉落物 → 设置为空气 | 移除木头方块 |
| **Replace** | 用户替换方块 | 直接设置 | 将泥土替换为石头 |
| **Complement** | 填充工具 | 补集逻辑 | 填充空心区域 |

#### 关键点

1. **EditMode 从 HistoryRecord 传递到 Modification**
   ```cpp
   // HistoryComponent::Undo()
   Modification.SetEditMode(HistoryRecord.EditMode);
   ```

2. **BlockWorld 根据 EditMode 执行不同逻辑**
   ```cpp
   switch (Modification.GetEditMode())
   {
       case EVoxelControllerEditState::Add:
           // 前置处理(碰撞、权限等)
           PreProcessAddBlocks(Modification);
           break;
       // ...
   }
   ```

3. **Undo/Redo 保持 EditMode**
   ```cpp
   // Undo 时仍然使用原来的 EditMode
   // 例如: Add 操作的 Undo 应该是 Delete 逻辑
   Modification.SetEditMode(HistoryRecord.EditMode);
   ```

### 4.3 性能优化实现

#### 优化策略

##### 1. Reserve() 预分配

**位置**: 所有已知大小的容器构造

```cpp
// TOOL::CreateHistoryRecord()
HistoryRecord.Edits.Reserve(EstimatedSize);           // TSet
HistoryRecord.ChunkIndices.Reserve(EstimatedSize / 64); // TArray

// CreateUndoModification()
FVoxelEditModification Modification;
Modification.Reserve(Edits.Num());  // TMap 内部预分配
```

**效果**:
- 避免动态扩容
- 减少 ~30% 内存分配次数
- 提升构造速度 ~20%

##### 2. TSet 自动去重

**优势**: 避免手动去重的 O(n²) 复杂度

```cpp
// ❌ 旧方案(手动去重)
TArray<FIntVector> BlockIndices;
for (const FIntVector& Index : NewIndices)
{
    if (!BlockIndices.Contains(Index))  // O(n) 查找
    {
        BlockIndices.Add(Index);
    }
}
// 总复杂度: O(n²)

// ✅ 新方案(TSet 自动去重)
TSet<FVoxelEdit> Edits;
for (const FVoxelEdit& Edit : NewEdits)
{
    Edits.Add(Edit);  // O(1) 插入 + 自动去重
}
// 总复杂度: O(n)
```

##### 3. TMap O(1) 查找

**优势**: 执行层快速访问方块数据

```cpp
// BlockWorld::ProcessPendingEdits()
for (const auto& Pair : Modification.GetBlocks())
{
    const FIntVector& BlockIndex = Pair.Key;      // O(1) 访问
    const FGameplayTag& BlockType = Pair.Value;   // O(1) 访问

    SetBlockType(BlockId, BlockType);
}
```

##### 4. 避免不必要的数据拷贝

**传递引用而非拷贝**:

```cpp
// ❌ 拷贝(慢)
void ProcessModification(FVoxelEditModification Modification);

// ✅ 引用(快)
void ProcessModification(const FVoxelEditModification& Modification);
```

##### 5. 批量操作

**批量 Add() 而非逐个 Add()**:

```cpp
// ❌ 逐个添加
for (const auto& Pair : BlockMap)
{
    Modification.Add(Pair.Key, Pair.Value);  // 多次调用
}

// ✅ 批量添加
Modification.AddFromMap(BlockMap);  // 一次调用
```

#### 性能对比

| 操作 | 旧方案 | 新方案 | 提升 |
|-----|-------|-------|------|
| **去重** | O(n²) Contains | O(n) TSet | ~100x (n=1000) |
| **查找** | O(n) 线性查找 | O(1) TMap | ~1000x (n=1000) |
| **内存分配** | 多次扩容 | Reserve() 预分配 | ~30% 减少 |
| **构造 HistoryRecord** | 读取 OldType | 复用 OldType | 0% 额外开销 |

#### 内存优化

##### ChunkIndices 去重

```cpp
// ❌ 可能重复
HistoryRecord.ChunkIndices.Add(ChunkIndex);

// ✅ 自动去重
HistoryRecord.ChunkIndices.AddUnique(ChunkIndex);
```

##### EditMode 共享

```cpp
// EditMode 只存一份,不在每个 FVoxelEdit 中存储
// 节省内存: 1000 方块 × 1 byte = 1 KB
struct FVoxelEditHistoryRecord
{
    TSet<FVoxelEdit> Edits;            // 无 EditMode
    EVoxelControllerEditState EditMode;  // 共享一份
};
```

## 7. 风险评估

### 7.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|-----|------|------|---------|
| **数组对应性破坏** | 高 | 中 | 完全封装 + CHECK 保护 + 单元测试 |
| **性能回退** | 中 | 低 | 性能基准测试 + 优化关键路径 |
| **多线程竞态** | 高 | 低 | 保持现有的队列机制 |
| **内存泄漏** | 中 | 低 | 智能指针 + Valgrind/Unreal Insights |
| **蓝图兼容性** | 低 | 低 | 蓝图只调用高层 API |

### 7.2 缓解策略

**数组对应性**
- ✅ 私有数组 + 访问方法
- ✅ `Add()` 方法保证同步
- ✅ `CheckValid()` 在关键路径调用
- ✅ 单元测试覆盖边界情况

**性能**
- ✅ 基准测试对比新旧方案
- ✅ 优化：预分配容量（Reserve）
- ✅ 避免不必要的数据拷贝

**多线程**
- ✅ 保持现有的 `PendingEdits` 队列
- ✅ 历史记录创建在主线程（读取世界状态）
- ✅ 执行层仍然异步
