## 0. 组合创建与状态边界

```text
同一建造侧栏：范围/模板预览 + M12a 名称/经营意图 + M12b 类型/业态 + 必要条款
 → Controller（草稿更新只改临时状态，预览/UI 订阅）
 → Confirm：CreateBusinessWithArea 概念请求
 → 业务门面
     ├─ 经营实体/关系/必要 Lease与首期 → Global.BusinessEntities
     └─ 空间草稿 → 区域 CRUD/空间注册 → AreaRef={SceneId,AreaId}
 → 有效 Lease 后租户建筑/家具真写入 → 事件 → UI
```

- 请求概念字段为 OperatorId、BusinessKind、Name、BusinessIntent、ParentBusinessEntityId、空间草稿等，具体 class 待定。OperatorId 是操作者上下文；产权人/经营人由有效授权及租约/任命确定，不允许自由输入取得权利。
- 经营实体为资产与业务唯一所有者，商圈/店铺/图外生意共用基础模型、按类型组合模块。`BusinessEntityId` 全局稳定，类型为 GUID（规则见[02 总纲 §2.7](/VoxelDesign/02-系统设计/AI决策系统-系统设计.md)）；不使用 `ShopId` 别名。
- 可选空间组件关联真实空间；区域仅范围、父子、定位、准入约束，不镜像 Owner/Manager、租约、bOpen、目录、订单或声誉。经营/空间注册编排分别执行；物品/结构产权日志保持独立来源，不因空间包含转移租户家具资产。
- StateComponent 只拥有草稿与编辑状态，不能充当经营真值或绕过合同业务。下文 SetXXX 仅为草稿内部接口，UI 目标链路经 Controller 更新；正式确认经业务门面，区域修改请求只发空间字段。
- M13a 只读/纯导航作为待迁移代码事实保留，不能限制最终创建；不要求先创建区域再跳详情补建生意或手动绑定。子区域确认只创建空间并关联现有主体。
- 创建默认 bOpen=false 不等于开业；bOperating=bOpen&&有效时段 纯派生，只 bOpen 手动且入档，无自动资格复检。初始两钱包/业务账户人物持有。
- NPC 空店/模板邀请在同一连续面板确认候选、条款与产权授权，先 Lease 再真落位。V1 只预置商圈玩家标准租杂货店，NPC 模板招商/完整客房后续；住客限时使用，不是客房 Manager，门按有效授权查询。
- 换租户沿用同一经营实体、删区域不注销实体（已定）；招图外换工待定。不新增猜测性重试、防御或修改几何/撤销算法。

### 1.1 组件层次结构

```
┌─────────────────────────────────────────────────┐
│ BuildPanelWidget (工具详情页容器)                │
├─────────────────────────────────────────────────┤

│  ┌──────────────────────────────────────────┐  │
│  │ ToolDetailPanel (模块容器)                │  │
│  │                                            │  │
│  │  ┌─────────┐ ┌─────────┐ ┌─────────┐     │  │
│  │  │ Module 1│ │ Module 2│ │ Module 3│ ... │  │

│  │                                            │  │
│  └──────────────────────────────────────────┘  │
│                                                 │
└─────────────────────────────────────────────────┘
         ↓                     ↓
    StateComponent    VisualComponent
    (状态管理)          (预览更新)
```

### 1.2 组件职责描述

#### BuildPanelWidget（工具详情页容器）
**职责**：
- 管理工具详情页的整体布局
- 注册和初始化所有模块
- 响应工具切换事件，控制模块显示/隐藏
- 协调模块与 StateComponent 的交互

**关键接口**：
```cpp
// 注册模块
void RegisterModule(UToolDetailModuleBase* Module);

// 工具切换处理
void HandleToolTagChanged(FGameplayTag NewToolTag);

// 更新所有模块显示
void UpdateModuleVisibility(FGameplayTag NewToolTag);
```

#### ToolDetailPanel（模块容器）
**职责**：
- 承载多个模块的容器 Widget
- 管理模块的布局（VerticalBox/GridPanel）
- 提供滚动和自适应布局

#### UToolDetailModuleBase（模块基类）
**职责**：
- 定义模块的统一接口
- 提供模块生命周期管理
- 处理模块与 StateComponent 的交互

**关键接口**：
```cpp
// 显示判断
virtual bool ShouldShowForTool(FGameplayTag ToolTag) const;

// 从 StateComponent 更新
virtual void UpdateFromToolState(UVoxelControllerStateComponent* StateComponent);

// 模块初始化
virtual void NativeConstruct() override;
```

#### 具体模块（Module 1-17）
**职责**：
- 实现特定的功能（素材选择、参数控制等）
- 处理用户输入
- 与 StateComponent 交互

### 1.3 组件依赖关系

```
BuildPanelWidget
    ├── 依赖 → StateComponent（读取状态）
    ├── 依赖 → VisualComponent（通过广播间接交互）
    ├── 管理 → ToolDetailPanel
    └── 管理 → UToolDetailModuleBase（所有模块）

UToolDetailModuleBase
    ├── 依赖 → StateComponent（只读草稿；写入经 Controller 业务）
    └── 派生 → 具体模块（M1-M14）

StateComponent
    ├── 广播 → OnCurrentToolTagChanged
    ├── 广播 → OnAreaFieldChanged
    ├── 广播 → OnAreaModificationChanged
    └── 广播 → OnTmpEditRequestChanged

VisualComponent
    └── 监听 → StateComponent 广播
```

## 3. 数据流

### 3.1 模块显示切换流程

```
用户点击工具按钮
    ↓
ToolIconButtonWidget.OnButtonClicked()
    ↓
InteractComponent->SwitchTool(NewToolTag)
    ↓
StateComponent->SetCurrentToolTag(NewToolTag)
    ↓
StateComponent 广播 OnCurrentToolTagChanged(NewToolTag)
    ↓
BuildPanelWidget.HandleToolTagChanged(NewToolTag)
    ↓
遍历所有已注册模块
    ↓
对每个模块调用 Module->ShouldShowForTool(NewToolTag)
    ↓
返回 true → 显示模块
          → 调用 Module->UpdateFromToolState(StateComponent)
          → 从 StateComponent 读取数据并更新 UI
返回 false → 隐藏模块
```

### 3.2 模块数据修改流程

```
用户操作模块 UI（输入框、滑块、按钮等）
    ↓
Module 处理输入事件
    ↓
调用 Controller 草稿业务方法 → 内部 StateComponent->SetXXX(NewValue)
    ↓
StateComponent 更新内部状态
    ↓
StateComponent 广播 OnXXXChanged(NewValue)
    ↓
VisualComponent 监听广播
    ↓
VisualComponent 更新 PreviewActor
    ↓
场景中预览更新
```

### 3.3 模块监听状态变化流程

```
StateComponent 状态变化
    ↓
StateComponent 广播 OnXXXChanged(NewValue)
    ↓
BuildPanelWidget.HandleXXXChanged(NewValue)
    ↓
遍历所有可见模块
    ↓
对每个模块调用 Module->UpdateFromToolState(StateComponent)
    ↓
模块从 StateComponent 读取最新数据
    ↓
模块更新 UI 显示
```

## 4. 生命周期管理

### 4.1 BuildPanelWidget 生命周期

**初始化阶段（NativeConstruct）**
1. 调用父类 NativeConstruct
2. 初始化 StateComponent 引用
3. 调用 InitializeModules() 创建所有模块
4. 绑定 StateComponent 广播事件
5. 调用 UpdateModuleVisibility() 更新初始显示

**运行阶段**
1. 响应工具切换，更新模块显示
2. 响应状态变化，更新模块数据
3. 协调模块与 StateComponent 交互

**销毁阶段（NativeDestruct）**
1. 解绑 StateComponent 广播事件
2. 清理所有模块
3. 调用父类 NativeDestruct

### 4.2 UToolDetailModuleBase 生命周期

**初始化阶段（NativeConstruct）**
1. 绑定 UI 控件（BindWidget）
2. 绑定输入事件（OnClicked、OnValueChanged 等）
3. 初始化默认值

**显示阶段**
1. 调用 UpdateFromToolState(StateComponent)
2. 从 StateComponent 读取数据
3. 更新 UI 控件显示
4. 启用交互

**隐藏阶段**
1. 停止交互
2. 可选：清理临时数据

**销毁阶段（NativeDestruct）**
1. 解绑输入事件
2. 清理资源

### 4.3 模块可见性转换

```
隐藏 → 显示
    ↓
调用 UpdateFromToolState()
    ↓
从 StateComponent 读取数据
    ↓
更新 UI 显示
    ↓
启用交互

显示 → 隐藏
    ↓
禁用交互
    ↓
可选：清理临时数据
```

## 6. 模块接口规范

### 6.1 模块命名规范

```
U<功能名>Module : public UToolDetailModuleBase

    GENERATED_BODY()

public:
    virtual void NativeConstruct() override;
    virtual bool ShouldShowForTool(FGameplayTag ToolTag) const override;
    virtual void UpdateFromToolState(UVoxelControllerStateComponent* StateComponent) override;

protected:
    // UI 控件绑定（使用 meta = (BindWidget)）
    UPROPERTY(meta = (BindWidget))
    UWidget* SomeWidget;

    // 事件处理函数（UFUNCTION）
    UFUNCTION()
    void OnSomeWidgetValueChanged();
```

### 6.2 UI 控件绑定规范

```cpp
// 必须绑定控件
UPROPERTY(meta = (BindWidget))
```

```cpp
void M4a_BoundingBoxModule::UpdateFromToolState(UVoxelControllerStateComponent* SC)
{
    if (!SC) return;

    // 读取临时区域信息
    const FTemporaryAreaInfo& AreaInfo = SC->GetTemporaryAreaInfo();

    // 更新 UI 显示
    MinXBox->SetText(FText::AsNumber(AreaInfo.AreaBox.Min.X));
    MinYBox->SetText(FText::AsNumber(AreaInfo.AreaBox.Min.Y));
    MinZBox->SetText(FText::AsNumber(AreaInfo.AreaBox.Min.Z));
    // ... 更新其他控件
```

### 7.4 模块草稿写入边界

M4a读取输入坐标后，经过注入的 Controller草稿业务更新 STATE 的相应范围字段，STATE广播，VisualComponent与 UI订阅更新。保留现有坐标解析/几何计算，不定义新的 class或方法名；StateComponent Setter仅是业务内部草稿接口。

Confirm不是该草稿更新：经营实体创建交 CreateBusinessWithArea组合门面；纯子区域/范围修改交空间业务，不能以草稿更新直接落经营合同或真写租户资产。

## 8. 性能优化

### 8.1 模块延迟创建

```cpp
// 不在初始化时创建所有模块
void BuildPanelWidget::InitializeModules()
{
    // 只创建基础模块（所有工具共用）
    CreateBasicModules();

    // 其他模块按需创建
    // 首次使用时才创建
}

UToolDetailModuleBase* BuildPanelWidget::GetOrCreateModule(TSubclassOf<UToolDetailModuleBase> ModuleClass)
{
    // 检查是否已创建
    if (CreatedModules.Contains(ModuleClass))
    {
        return CreatedModules[ModuleClass];
    }

    // 创建新模块
    UToolDetailModuleBase* Module = CreateWidget(ModuleClass, this);
    CreatedModules.Add(ModuleClass, Module);
    ToolDetailPanel->AddChild(Module);
    return Module;
}
```

### 8.2 避免不必要的更新

```cpp
void M5_SelectionInfoModule::UpdateFromToolState(UVoxelControllerStateComponent* SC)
{
    if (!SC || !IsVisible()) return;

    // 检查数据是否真正变化
    const FTemporaryAreaInfo& NewAreaInfo = SC->GetTemporaryAreaInfo();
    if (LastAreaInfo == NewAreaInfo) return;  // 未变化，跳过

    // 更新 UI
    UpdateDisplay(NewAreaInfo);

    // 缓存当前数据
    LastAreaInfo = NewAreaInfo;
}
```

### 8.3 大数据列表分页

```cpp
void M1_BuildLibraryModule::UpdateItemList()
{
    // 获取总数据量
    int32 TotalCount = AllItems.Num();

    // 计算当前页数据
    int32 StartIndex = CurrentPage * PageSize;
    int32 EndIndex = FMath::Min(StartIndex + PageSize, TotalCount);

    // 只显示当前页数据
    CurrentPageItems = AllItems.Slice(StartIndex, EndIndex);

    // 更新 UI
    RefreshItemList();
}
```
