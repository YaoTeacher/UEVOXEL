# 编辑系统-C++与蓝图职责划分-架构设计

## 1. 组件架构

### 1.1 层次结构

```
┌─────────────────────────────────────────┐
│           蓝图层 (Blueprint Layer)        │
│  职责：                                   │
│  - 输入检测和响应                         │
│  - 射线检测和数据获取                     │
│  - UI 事件绑定和协调                      │
│  - 特效、音效、提示                        │
└─────────────────────────────────────────┘
                    ↓ 调用 UFUNCTION
┌─────────────────────────────────────────┐
│         C++ 组件层 (Component Layer)       │
│  职责：                                   │
│  - 状态管理（StateComponent）             │
│  - 业务逻辑（InteractComponent）          │
│  - 渲染管理（VisualUIComponent）          │
│  - 历史记录（HistoryComponent）           │
└─────────────────────────────────────────┘
                    ↓ 访问
┌─────────────────────────────────────────┐
│       C++ 工具层 (Tool Layer)              │
│  职责：                                   │
│  - 批量编辑工具（BatchEditTool）           │
│  - 预览 Actor（PreviewActor）              │
│  - Gizmo 系统（3DUIActor）                 │
└─────────────────────────────────────────┘
                    ↓ 访问
┌─────────────────────────────────────────┐
│      子系统层 (Subsystem Layer)            │
│  职责：                                   │
│  - 世界数据管理（BlockWorldSubsystem）     │
│  - 区域管理（AreaWorldSubsystem）          │
│  - 其他核心子系统                          │
└─────────────────────────────────────────┘
```

### 1.2 组件职责描述

#### 1.2.1 蓝图层组件

**BP_VoxelPlayerController**：
- **职责**：输入协调、状态流转、UI 更新
- **输入**：Enhanced Input 事件、用户操作
- **输出**：调用 C++ 接口、更新 UI 显示
- **特点**：
  - 快速迭代和修改
  - 可视化调试
  - 设计师可调整

**WBP_EditMenu** 及其他 UI Widget：
- **职责**：用户界面显示和交互
- **输入**：C++ 状态事件
- **输出**：用户操作、UI 更新
- **特点**：
  - UMG 布局管理
  - 动画和特效
  - 用户反馈

#### 1.2.2 C++ 层组件

**VoxelPlayerController**：
- **职责**：组件容器、生命周期管理、接口暴露
- **输入**：蓝图调用
- **输出**：返回组件引用、提供工具方法
- **特点**：
  - 创建和管理子组件
  - 缓存子系统引用
  - 提供统一的外部接口

**VoxelControllerStateComponent**：
- **职责**：状态存储、状态验证、事件广播
- **输入**：组件调用
- **输出**：状态数据、变更事件
- **特点**：
  - 维护编辑状态
  - 提供状态访问接口
  - 广播细粒度状态事件

**VoxelControllerInteractComponent**：
- **职责**：业务逻辑、编辑操作、Gizmo 交互
- **输入**：蓝图调用、状态事件
- **输出**：调用工具、更新状态
- **特点**：
  - 协调各组件完成编辑
  - 处理 Gizmo 交互逻辑
  - 管理编辑请求

**VoxelControllerVisualUIComponent**：
- **职责**：预览管理、Gizmo 渲染、可视化
- **输入**：状态事件、交互事件
- **输出**：更新预览显示
- **特点**：
  - 管理 PreviewActor 生命周期
  - 创建和销毁 Gizmo
  - 更新预览网格

**VoxelControllerHistoryComponent**：
- **职责**：历史栈管理、撤销/重做
- **输入**：编辑操作完成
- **输出**：恢复之前状态
- **特点**：
  - 管理撤销/重做栈
  - 保存编辑快照
  - 提供历史统计

### 1.3 组件依赖关系

**蓝图依赖 C++**：
- 蓝图通过 BlueprintCallable 调用 C++ 方法
- 蓝图通过 BlueprintReadWrite 访问 C++ 属性
- 蓝图监听 C++ 的动态多播委托

**C++ 组件间依赖**：
- InteractComponent 依赖 StateComponent
- VisualUIComponent 依赖 StateComponent
- HistoryComponent 独立
- 所有组件可独立访问子系统

**关键原则**：
- C++ 不依赖蓝图
- 组件间通过接口通信
- 避免循环依赖

## 2. 接口定义

### 2.1 C++ 层接口

#### 2.1.1 状态管理接口

**接口功能**：
- 获取和设置玩家模式
- 获取和设置建造状态
- 获取和设置临时几何数据
- 获取临时编辑请求
- 清理临时数据

**接口限制**：
- 状态变更有验证逻辑
- 某些状态只能在特定时机修改
- 几何数据读写分离

**预期输入**：
- 新状态值
- 几何描述结构
- 编辑参数

**预期输出**：
- 状态变更成功/失败
- 当前状态值
- 几何数据副本

#### 2.1.2 编辑操作接口

**接口功能**：
- 设置第一个点（底面定义起点）
- 设置第二个点（底面定义终点）
- 更新第二个点（拖动过程中）
- 开始 Gizmo 交互
- 更新 Gizmo 交互
- 释放 Gizmo 交互
- 确认编辑
- 取消编辑

**接口限制**：
- 点的设置顺序有要求
- Gizmo 交互需要在特定状态
- 确认前需要验证编辑请求

**预期输入**：
- 体素索引
- 世界位置
- Gizmo Actor 引用

**预期输出**：
- 操作成功/失败
- 编辑请求结构
- 预览信息

#### 2.1.3 历史管理接口

**接口功能**：
- 撤销上次操作
- 重做已撤销操作
- 清空历史记录
- 检查是否可撤销/重做
- 获取统计信息

**接口限制**：
- 历史栈有大小限制
- 某些操作不可撤销
- 重做栈在新操作后清空

**预期输入**：
- 无（撤销/重做）
- 历史大小限制

**预期输出**：
- 操作成功/失败
- 撤销/重做描述
- 统计数据

#### 2.1.4 工具方法接口

**接口功能**：
- 世界位置转体素索引
- 体素索引转世界位置
- 验证体素索引有效性
- 获取组件引用
- 获取子系统引用

**接口限制**：
- 坐标转换依赖方块尺寸
- 组件引用需要有效
- 子系统需要已初始化

**预期输入**：
- 世界位置向量
- 体素索引

**预期输出**：
- 转换后的值
- 有效性判断
- 组件/子系统引用

### 2.2 蓝图层接口

#### 2.2.1 输入处理接口

**接口功能**：
- 响应 Enhanced Input 动作
- 处理点击、保持、释放事件
- 处理键盘快捷键
- 处理手势操作

**接口限制**：
- 输入动作需要预配置
- 某些输入只在特定状态有效

**预期输入**：
- Input Action Value
- 输入事件类型

**预期输出**：
- 调用 C++ 接口
- 更新内部状态

#### 2.2.2 射线检测接口

**接口功能**：
- 从鼠标位置发射射线
- 获取命中结果
- 提取世界位置
- 提取命中 Actor

**接口限制**：
- 需要有效的摄像机
- 需要碰撞通道设置

**预期输入**：
- 鼠标位置
- 碰撞通道

**预期输出**：
- 命中结果结构
- 世界位置
- Actor 引用

#### 2.2.3 UI 更新接口

**接口功能**：
- 监听 C++ 事件
- 更新 UI 显示
- 播放动画
- 显示提示

**接口限制**：
- UI 元素需要存在
- 事件绑定需要正确

**预期输入**：
- C++ 事件参数
- 状态数据

**预期输出**：
- UI 可见性变化
- 文本更新
- 动画播放

### 2.3 接口调用关系

**输入处理流程**：
```
蓝图输入事件
  → 蓝图射线检测
  → 蓝图计算体素索引（调用 C++ 工具方法）
  → 蓝图更新 C++ 状态（调用 C++ 状态接口）
  → C++ 广播事件
  → 蓝图监听事件并更新 UI
```

**编辑操作流程**：
```
蓝图检测编辑操作
  → 蓝图调用 C++ 编辑接口
  → C++ 执行业务逻辑
  → C++ 更新状态
  → C++ 广播事件
  → 蓝图更新 UI
```

**撤销重做流程**：
```
蓝图检测快捷键
  → 蓝图调用 C++ 历史接口
  → C++ 执行撤销/重做
  → C++ 广播事件
  → 蓝图更新 UI 和世界显示
```

## 3. 数据流

### 3.1 输入处理数据流

**步骤描述**：
1. 用户按下鼠标或键盘
2. Enhanced Input 系统检测输入
3. 蓝图接收输入事件
4. 蓝图执行射线检测获取世界位置
5. 蓝图调用 C++ 工具方法转换坐标
6. 蓝图调用 C++ 接口更新状态
7. C++ 验证并更新状态
8. C++ 广播状态变更事件
9. 蓝图监听事件并更新 UI

**输入来源**：
- Enhanced Input System
- 鼠标位置
- 键盘按键

**处理逻辑**：
- 蓝图：输入检测、射线检测、坐标转换
- C++：状态验证、状态更新、事件广播

**输出结果**：
- C++ 状态变更
- UI 显示更新
- 预览更新

### 3.2 编辑操作数据流

**步骤描述**：
1. 用户在底面定义阶段点击
2. 蓝图调用 C++ 设置第一个点
3. 用户拖动鼠标
4. 蓝图调用 C++ 更新第二个点
5. 用户点击 Gizmo
6. 蓝图调用 C++ 开始 Gizmo 交互
7. 用户拖动 Gizmo
8. 蓝图调用 C++ 更新 Gizmo 交互
9. 用户按下确认键
10. 蓝图调用 C++ 提交编辑
11. C++ 计算受影响的体素
12. C++ 执行编辑操作
13. C++ 保存历史记录
14. C++ 广播编辑完成事件
15. 蓝图更新 UI 和提示

**输入来源**：
- 蓝图输入处理
- 用户操作

**处理逻辑**：
- 蓝图：协调和调用
- C++：计算、执行、保存

**输出结果**：
- 世界数据修改
- 历史记录增加
- UI 更新

### 3.3 UI 更新数据流

**步骤描述**：
1. C++ 组件状态变更
2. C++ 组件广播事件
3. 蓝图监听到事件
4. 蓝图更新 UI 元素
5. 蓝图播放动画或特效
6. 蓝图显示提示信息

**输入来源**：
- C++ 状态事件

**处理逻辑**：
- 蓝图：UI 更新、动画播放

**输出结果**：
- UI 可见性变化
- 文本内容更新
- 动画播放

## 4. 生命周期管理

### 4.1 C++ 组件生命周期

#### 4.1.1 VoxelPlayerController

**初始化阶段**：
- 构造函数创建默认子组件
- BeginPlay 缓存子系统引用
- BeginPlay 初始化组件间引用

**功能阶段**：
- 接收蓝图调用
- 提供组件访问接口
- 提供工具方法

**清理阶段**：
- EndPlay 清理组件引用
- EndPlay 清除子系统引用

**转换条件**：
- 构造函数 → BeginPlay：Actor 生成
- BeginPlay → 功能阶段：初始化完成
- 功能阶段 → EndPlay：Actor 销毁

#### 4.1.2 StateComponent

**初始化阶段**：
- 构造函数初始化状态数据
- BeginPlay 绑定事件（如有需要）

**功能阶段**：
- 接收状态查询和修改
- 验证状态变更
- 广播状态事件

**清理阶段**：
- Cleanup 清理临时数据
- 清空事件绑定

**转换条件**：
- 状态变更有验证
- 某些状态只能在特定时机修改

#### 4.1.3 InteractComponent

**初始化阶段**：
- InitializeComponents 设置组件引用

**功能阶段**：
- 处理编辑请求
- 协调 Gizmo 交互
- 调用工具和子系统

**清理阶段**：
- Cleanup 取消进行中的编辑

**转换条件**：
- 需要其他组件已初始化
- 编辑操作有状态要求

#### 4.1.4 VisualUIComponent

**初始化阶段**：
- BeginPlay 绑定状态事件
- 创建 PreviewActor

**功能阶段**：
- 监听状态事件
- 更新预览显示
- 管理 Gizmo 生命周期

**清理阶段**：
- Cleanup 清理预览
- Cleanup 销毁 Gizmo

**转换条件**：
- 需要状态组件已初始化
- 预览更新依赖状态事件

#### 4.1.5 HistoryComponent

**初始化阶段**：
- 初始化历史栈

**功能阶段**：
- 保存编辑快照
- 执行撤销/重做
- 管理历史统计

**清理阶段**：
- ClearHistory 清空历史

**转换条件**：
- 编辑完成后自动保存
- 撤销/重做需要栈中有数据

### 4.2 蓝图状态生命周期

#### 4.2.1 编辑模式状态机

**Inactive（未激活）**：
- **功能**：不显示编辑 UI
- **限制**：不响应编辑输入
- **转换条件**：用户进入编辑模式 → Hidden

**Hidden（隐藏）**：
- **功能**：显示编辑 UI，无预览
- **限制**：只能进行第一个点击
- **转换条件**：用户点击 → Base

**Base（底面定义）**：
- **功能**：显示 2D 包围盒预览
- **限制**：拖动过程中不能切换工具
- **转换条件**：用户释放鼠标 → Edit

**Edit（编辑阶段）**：
- **功能**：显示 3D 包围盒和 Gizmo
- **限制**：只能操作 Gizmo 或确认/取消
- **转换条件**：用户按确认键 → Confirm

**Confirm（确认阶段）**：
- **功能**：执行编辑操作
- **限制**：短暂状态，完成后自动转换
- **转换条件**：编辑完成 → Hidden

#### 4.2.2 UI 元素生命周期

**创建阶段**：
- UMG Widget 创建
- 绑定到 C++ 事件
- 初始化显示状态

**显示阶段**：
- 监听 C++ 事件
- 更新显示内容
- 响应用户交互

**隐藏阶段**：
- 取消事件绑定
- 隐藏 Widget
- 可选销毁

## 5. 类关系图

### 5.1 C++ 类关系

**聚合关系**：
```
AVoxelPlayerController
    ├─ owns → UVoxelControllerStateComponent
    ├─ owns → UVoxelControllerInteractComponent
    ├─ owns → UVoxelControllerVisualUIComponent
    └─ owns → UVoxelControllerHistoryComponent
```

**依赖关系**：
```
UVoxelControllerInteractComponent
    ├─ uses → UVoxelControllerStateComponent
    ├─ uses → UVoxelControllerVisualUIComponent
    └─ uses → UVoxelControllerHistoryComponent

UVoxelControllerVisualUIComponent
    ├─ uses → UVoxelControllerStateComponent
    └─ creates → AVoxelPreviewActor

UVoxelBatchEditTool
    └─ uses → UVoxelBlockWorldSubsystem
```

### 5.2 蓝图与 C++ 关系

**继承关系**：
```
BP_VoxelPlayerController
    └─ inherits → AVoxelPlayerController
```

**使用关系**：
```
BP_VoxelPlayerController
    ├─ calls → AVoxelPlayerController::GetStateComponent()
    ├─ calls → AVoxelPlayerController::GetInteractComponent()
    ├─ calls → AVoxelPlayerController::GetVisualUIComponent()
    └─ calls → AVoxelPlayerController::GetHistoryComponent()

WBP_EditMenu
    ├─ listens → StateComponent.OnBuildStateChanged
    ├─ listens → StateComponent.OnFirstPointChanged
    └─ listens → StateComponent.OnSecondPointChanged
```

## 6. 实施建议

### 6.1 开发顺序

**Phase 1：C++ 层实现** ✅（已完成）
- 定义数据结构
- 实现组件系统
- 实现业务逻辑
- 暴露 BlueprintCallable 接口

**Phase 2：蓝图层实现**（当前）
- 配置 Enhanced Input
- 实现输入事件处理
- 实现射线检测
- 绑定 UI 事件

**Phase 3：集成测试**
- 完整编辑流程测试
- 撤销/重做测试
- 性能测试
- 边界情况测试

### 6.2 测试要点

**C++ 层测试**：
- 组件初始化和清理
- 接口调用正确性
- 事件广播触发
- 业务逻辑准确性

**蓝图层测试**：
- 输入检测准确性
- 射线检测准确性
- 状态流转正确性
- UI 更新及时性

**集成测试**：
- 完整编辑流程
- 异常情况处理
- 性能指标达标
- 内存无泄漏

### 6.3 性能考虑

**C++ 层优化**：
- 避免频繁的虚函数调用
- 使用 const 引用传递
- 预分配内存
- 使用对象池

**蓝图层优化**：
- 减少事件绑定数量
- 避免每帧复杂逻辑
- 使用函数库复用
- 缓存计算结果
