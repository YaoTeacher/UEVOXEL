## 1. 组件架构

### 1.1 组件层次结构

```
模板系统
├── 模板管理层（Template Management）
│   ├── 模板数据（UVoxelBuildingTemplateAsset）
│   ├── 模板库（TemplateLibrary）
│   └── 模板序列化（TemplateSerializer）
│
├── 网格生成层（Mesh Generation）
│   ├── 网格生成器（TemplateMeshGenerator）
│   └── 预览缓存（PreviewCache）
│
└── 建造执行层（Build Execution）
    ├── 建造协调器（BuildCoordinator）
    └── 历史记录器（BuildHistoryRecorder）
```

### 1.2 组件职责描述

**模板管理层**
- 管理模板数据的加载、保存、删除
- 处理模板的序列化和反序列化
- 提供模板库的组织和查询

**网格生成层**
- 从模板数据生成预览网格
- 管理预览网格的缓存
- 提供预览网格的获取和更新

**建造执行层**
- 协调模板建造的完整流程
- 计算模板放置的修改数据
- 记录建造操作的历史

### 1.3 组件依赖关系

```
模板管理层
  ↓ 依赖
网格生成层
  ↓ 依赖
建造执行层
  ↓ 依赖
外部系统（BlockWorld, HistoryComponent）
```

### 1.4 文件格式规范（.vxbp）

**设计目标**：
- 官方模板和玩家模板统一格式
- 支持运行时创建（解决打包后无法创建 uasset 问题）
- 支持缩略图预览
- 支持快速扫描（不解压完整数据）

**文件二进制布局**：

| 偏移 (Offset) | 数据段 | 类型 | 大小 | 说明 |
|--------------|--------|------|------|------|
| 0x00 | **Magic** | `uint32` | 4 | 固定为 `0x56584250` (ASCII: "VXBP") |
| 0x04 | **Version** | `int32` | 4 | 文件版本号 |
| 0x08 | **ThumbnailSize** | `int32` | 4 | 缩略图数据块大小（0表示无缩略图） |
| 0x0C | **PayloadSize** | `int32` | 4 | 核心数据块大小 |
| 0x10 | **ThumbnailBlob** | `Binary` | 可变 | PNG/JPG 格式的缩略图数据 |
| ... | **PayloadBlob** | `Binary` | 可变 | **核心数据** (Zlib压缩后的序列化数据) |

**核心数据结构（Payload 内容）**：

```cpp
struct FBlueprintCoreData
{
    int32 Version = 1;
    FIntVector Size;
    FIntVector AnchorOffset;
    TArray<FGameplayTag> Palette;
    TMap<FIntVector, int32> VoxelData;
    FString TemplateName;
    FString Description;
    FString AuthorName;
    FDateTime CreationDate;
    int32 BlockCount;
    TArray<FGameplayTag> Tags;
    TArray<FString> RequiredMods;
    TArray<FString> RequiredDLCs;

    friend FArchive& operator<<(FArchive& Ar, FBlueprintCoreData& Data)
    {
        Ar << Data.Version << Data.Size << Data.AnchorOffset;
        Ar << Data.Palette << Data.VoxelData;
        Ar << Data.TemplateName << Data.Description;
        Ar << Data.AuthorName << Data.CreationDate;
        Ar << Data.BlockCount << Data.Tags;
        Ar << Data.RequiredMods << Data.RequiredDLCs;
        return Ar;
    }
};
```

### 1.5 目录结构

**官方模板目录**：
- 路径：`Content/VoxelTemplates/`
- 用途：存放游戏内置的官方模板
- 权限：只读（打包后）
- 扫描：ConfigDataSubsystem 启动时扫描

**玩家模板目录**：
- 路径：`Saved/VoxelTemplates/`
- 用途：存放玩家创建的模板
- 权限：可读写（运行时可创建）
- 扫描：ConfigDataSubsystem 启动时扫描

**ConfigDataSubsystem 统一管理**：
```cpp
// 扫描两个目录
TArray<FString> TemplateDirectories = {
    FPaths::ProjectContentDir() / TEXT("VoxelTemplates"),  // 官方
    FPaths::ProjectSavedDir() / TEXT("VoxelTemplates")    // 玩家
};

// 扫描并注册所有 .vxbp 文件
ConfigDataSubsystem->ScanAndRegisterTemplates(TemplateDirectories);
```

## 3. 数据流

### 3.1 模板采集流程（选区→模板）

```
选区系统提供 FVoxelSelection
  ↓
TMap<FIntVector, FGameplayTag> SelectedVoxels（位置→原始类型）
  ↓
UVoxelTemplateManager::CreateFromSelection()
  ↓
步骤1：计算包围盒
  - MinCorner = SelectedVoxels.GetMin()
  - MaxCorner = SelectedVoxels.GetMax()
  - Size = MaxCorner - MinCorner + FIntVector(1,1,1)
  ↓
步骤2：计算锚点偏移（底面中心）
  - AnchorOffset.X = (Size.X - 1) / 2
  - AnchorOffset.Y = (Size.Y - 1) / 2
  - AnchorOffset.Z = 0
  ↓
步骤3：构建调色板（去重 + 排除脚手架）
  - 遍历 SelectedVoxels.Values
  - 过滤掉 `Voxel.Block.Scaffolding.*` 层级的Tag
  - 添加唯一Tag到 Palette
  - 返回Tag对应的索引
  ↓
步骤4：转换体素数据（底面中心为原点）
  - 遍历 SelectedVoxels
  - 计算相对坐标：RelativePos = WorldPos - (MinCorner + AnchorOffset)
  - 查找调色板索引：PaletteIndex = Palette.Find(BlockType)
  - 存储到VoxelData：VoxelData.Add(RelativePos, PaletteIndex)
  ↓
步骤5：生成元数据
  - TemplateName = "未命名模板"
  - AuthorName = PlayerName
  - CreationDate = FDateTime::Now()
  - 统计信息：BlockCount = VoxelData.Num()
  ↓
步骤6：检测依赖（TODO）
  - 遍历Palette中的Tag
  - 查找Tag所属MOD/DLC
  - 添加到RequiredMods/RequiredDLCs
  ↓
步骤7：保存为 .vxbp 文件
  - 生成缩略图（可选）
  - 调用 UVoxelTemplateFileIO::SaveToVXBPFile()
  - 保存到 Saved/VoxelTemplates/ 目录
  - 返回文件路径
  ↓
输出：UVoxelBuildingTemplateAsset（包含 FilePath）
```

### 3.2 预览生成流程

```
玩家选择模板
  ↓ 检查缓存
UVoxelTemplatePreviewCache::GetOrCreatePreviewMesh()
  ↓ 缓存未命中
UVoxelTemplateMeshGenerator::GenerateMeshDataForTemplate()
  - 构建虚拟 ChunkGenContext
  - 调用 BlockWorld->GenerateMeshData()
  ↓ 缓存网格
Cache.Add(TemplateID, MeshData)
  ↓
输出：FChunkMeshData
```

### 3.3 建造执行流程

```
玩家确认建造
  ↓ 计算定位点
UVoxelBuildCoordinator::CalculateBuildModification()
  - 遍历模板方块
  - 应用相对坐标偏移
  - 应用6向旋转变换
  - 计算世界坐标
  - 动态计算 ChunkIndex
  ↓ 构建修改请求
FVoxelEditModification
  - Blocks.Add(WorldPos, BlockType)
  - ChunkIndices.Add(ChunkIndex)
  ↓ 执行修改
BlockWorld->BatchModifyVoxelData_Modification()
  ↓ 记录历史
HistoryComponent->SaveHistoryRecord()
```

#### 3.3.1 6向旋转变换规范

**设计理念**: 分离旋转中心和定位锚点

```
旋转操作: 以包围盒几何中心为旋转中心
放置操作: 以底面中心为定位锚点（世界坐标固定）
```

**坐标系统定义**:
```cpp
FIntVector Size;              // 模板尺寸
FIntVector GeometricCenter;   // 几何中心: (Size-1) / 2
FIntVector BottomCenter;      // 底面中心: ((Size.X-1)/2, (Size.Y-1)/2, 0)
```

**6向旋转矩阵定义**:

| 方向 | 变换规则 | 说明 |
|------|---------|------|
| Forward | `(x, y, z) → (x, y, z)` | 不变 |
| Backward | `(x, y, z) → (-x, -y, z)` | 绕Z轴180° |
| Left | `(x, y, z) → (y, -x, z)` | 绕Z轴-90° |
| Right | `(x, y, z) → (-y, x, z)` | 绕Z轴+90° |
| Up | `(x, y, z) → (x, -z, y)` | 绕X轴+90° |
| Down | `(x, y, z) → (x, z, -y)` | 绕X轴-90° |

**旋转操作流程**:
```
输入: 原始体素数据(相对坐标) + 目标方向
  ↓
步骤1: 计算几何中心
  - GeoCenter = (Size-1) / 2
  ↓
步骤2: 将体素坐标转换到几何中心坐标系
  - RelativeToGeoCenter = LocalPos - GeoCenter
  ↓
步骤3: 应用旋转变换
  - RotatedPos = RotationMatrix.Transform(RelativeToGeoCenter)
  ↓
步骤4: 转换回以底面中心为原点的坐标系
  - 计算旋转后的底面中心位置
  - NewLocalPos = RotatedPos + (GeoCenter - NewBottomCenter)
  ↓
输出: 旋转后的体素数据
```

**放置到世界坐标**:
```
输入: 旋转后的模板 + 锚点世界坐标(底面中心)
  ↓
步骤1: 应用旋转变换
  - RotatedVoxelData = ApplyRotation(Template.VoxelData, Rotation)
  ↓
步骤2: 计算旋转后的底面中心
  - RotatedBottomCenter = GetRotatedBottomCenter(Size, Rotation)
  ↓
步骤3: 转换到世界坐标
  - WorldPos = AnchorPosition + (LocalPos - RotatedBottomCenter)
  ↓
输出: FVoxelEditRequest数组
```

**关键设计决策**:
- ✅ 分离关注点: 旋转中心与定位锚点职责清晰
- ✅ 符合直觉: 玩家定位点不变,旋转改变模板朝向
- ✅ 数学明确: 每个方向的变换矩阵都有明确定义
- ✅ 易于实现: 离散旋转,无需浮点运算

## 3.5 错误处理规范

### 3.5.1 设计原则

**统一的错误处理策略**: 使用错误码+结果结构体,所有模板系统接口返回结构化的错误信息。

**API设计模式**:
- **模式1**: 返回`FVoxelTemplateResult`结构体（推荐用于复杂操作）
- **模式2**: 输出参数+返回错误码（推荐用于简单操作）

### 3.5.3 结果结构体定义

```cpp
USTRUCT(BlueprintType)
struct FVoxelTemplateResult
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Error")
    EVoxelTemplateError ErrorCode = EVoxelTemplateError::None;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Error")
    FString ErrorMessage;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Error")
    FString Context;  // 额外的上下文信息

    // 便捷方法
    bool IsSuccess() const { return ErrorCode == EVoxelTemplateError::None; }
    bool IsError() const { return ErrorCode != EVoxelTemplateError::None; }

    static FVoxelTemplateResult Success()
    {
        return FVoxelTemplateResult{EVoxelTemplateError::None, TEXT(""), TEXT("")};
    }

    static FVoxelTemplateResult Failure(EVoxelTemplateError Code, const FString& Message = TEXT(""), const FString& InContext = TEXT(""))
    {
        return FVoxelTemplateResult{Code, Message, InContext};
    }
};
```

**示例1: 复杂操作（返回结果结构体）**

### 3.5.5 错误处理迁移策略

**阶段1**: 新代码使用新系统

**阶段2**: 渐进式重构现有代码

- 保留旧API作为wrapper

**阶段3**: 统一错误处理

## 5. 历史记录与撤销

### 5.1 撤销粒度定义

**单体放置**
- 每个模板实例 = 1 次历史记录
- 支持撤销单个模板放置

**阵列放置**
- 整个阵列 = 1 次历史记录
- 不论阵列包含多少实例（1-1000个）
- 阵列参数调整时记录新历史

**预览阶段参数调整**
- 旋转改变 → 记录历史
- 位置移动 → 记录历史
- 阵列配置改变 → 记录历史
- 所有有影响的参数变化都要记录

**参考标准**
- Photoshop: 所有参数调整都有历史记录
- Blender: 操作级别历史，重要参数变化单独记录

### 5.2 历史记录流程

```
模板放置流程：
玩家确认放置
  ↓ 计算修改数据
UVoxelBuildCoordinator::CalculateBuildModification()
  ↓ 构建历史记录
FVoxelEditHistoryRecord
  - Modification: FVoxelEditModification
  - EditType: EVoxelControllerEditState::TemplateBuild
  - bIsArray: true/false
  - ArrayConfig: FArrayPlacementConfig（如果是阵列）
  ↓ 提交到历史系统
UVoxelControllerHistoryComponent::SaveHistoryRecord()
  ↓
输出：可撤销的历史记录

撤销流程：
玩家触发撤销
  ↓ 查找历史记录
HistoryComponent->GetLastRecord()
  ↓ 判断是否为阵列
if (Record.bIsArray)
  - 撤销整个阵列
else
  - 撤销单体放置
  ↓ 反向修改
BlockWorld->BatchModifyVoxelData_Modification(InverseModification)
```
