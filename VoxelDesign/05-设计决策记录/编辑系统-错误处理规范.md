# 编辑系统-错误处理规范

**适用范围**: 编辑系统所有子系统（选区、模板、阵列等）

---

## 1. 概述

### 1.1 背景

编辑系统现有代码使用简单的`bool`返回值表示成功/失败,但无法区分失败原因。Council辩论(2026-01-24)识别出**所有系统边界都缺少错误处理契约**,这导致:
- 调用者无法知道为什么失败
- 错误日志难以定位问题
- 无法向用户展示有意义的错误信息

### 1.2 设计目标

**统一错误处理策略**: 使用错误码+结果结构体,所有编辑系统接口返回结构化的错误信息。

**核心原则**:
- ✅ 明确的错误分类
- ✅ 丰富的上下文信息
- ✅ 蓝图友好
- ✅ 渐进式迁移路径

### 2.2 结果结构体

```cpp
USTRUCT(BlueprintType)
struct FVoxelTemplateResult
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Error")
    EVoxelTemplateError ErrorCode = EVoxelTemplateError::None;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Error")
    FString ErrorMessage;

    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Error")
    FString Context;  // 额外的上下文信息

    // 便捷方法
    bool IsSuccess() const { return ErrorCode == EVoxelTemplateError::None; }
    bool IsError() const { return ErrorCode != EVoxelTemplateError::None; }

    static FVoxelTemplateResult Success()
    {
        return FVoxelTemplateResult{EVoxelTemplateError::None, TEXT(""), TEXT("")};
    }

    static FVoxelTemplateResult Failure(EVoxelTemplateError Code, const FString& Message = TEXT(""), const FString& InContext = TEXT(""))
    {
        return FVoxelTemplateResult{Code, Message, InContext};
    }
};
```

## 3. API设计模式

### 3.1 模式1: 返回结果结构体

**适用场景**: 复杂操作,需要返回数据和错误信息

```cpp
FVoxelTemplateResult CreateTemplateFromSelection(
    const FVoxelSelection& Selection,
    FString TemplateName,
    UVoxelBuildingTemplateAsset*& OutTemplate
);
```

**调用示例**:
```cpp
UVoxelBuildingTemplateAsset* NewTemplate = nullptr;
auto Result = CreateTemplateFromSelection(Selection, Name, NewTemplate);

if (Result.IsError())
{
    UE_LOG(LogTemplate, Error, TEXT("Failed: %s - %s"),
           *Result.ErrorMessage, *Result.Context);

    // 显示给用户
    FMessageDialog::Open(EAppMsgType::Ok,
        FText::Format(TEXT("模板创建失败: {0}"),
        FText::FromString(Result.ErrorMessage)));

    return;
}

// 成功,使用NewTemplate
```

### 3.2 模式2: 输出参数+错误码

**适用场景**: 简单操作,只需要知道成功/失败

```cpp
EVoxelTemplateError ValidateTemplate(
    UVoxelBuildingTemplateAsset* Template,
    FString& OutErrorMessage
);
```

**调用示例**:
```cpp
FString ErrorMsg;
EVoxelTemplateError Error = ValidateTemplate(Template, ErrorMsg);

if (Error != EVoxelTemplateError::None)
{
    UE_LOG(LogTemplate, Error, TEXT("Validation failed: %s"), *ErrorMsg);
    return;
}
```

## 4. 错误消息映射

```cpp
FString GetErrorMessage(EVoxelTemplateError ErrorCode)
{
    switch (ErrorCode)
    {
        case EVoxelTemplateError::None:
            return TEXT("操作成功");

        case EVoxelTemplateError::NullPointer:
            return TEXT("检测到空指针");

        case EVoxelTemplateError::EmptySelection:
            return TEXT("选区为空,请先选择体素");

        case EVoxelTemplateError::ChunkNotLoaded:
            return TEXT("所需的区块未加载");

        case EVoxelTemplateError::InvalidFileFormat:
            return TEXT("无效的模板文件格式");

        case EVoxelTemplateError::VersionMismatch:
            return TEXT("模板版本不兼容");

        case EVoxelTemplateError::DiskFull:
            return TEXT("磁盘空间不足");

        // ... 其他错误码

        default:
            return TEXT("未知错误");
    }
}
```

## 5. 迁移策略

### 5.1 阶段1: 新代码使用新系统

**范围**: 模板系统所有新接口

**示例**:
```cpp
// 新接口
FVoxelTemplateResult CreateTemplateFromSelection(...);

// 不要使用旧风格
bool CreateTemplateFromSelection(...);  // ❌ 不推荐
```

### 5.2 阶段2: 渐进式重构现有代码

**优先级**:
1. **P0**: 模板系统核心接口
2. **P1**: 选区系统接口
3. **P2**: 阵列系统接口
4. **P3**: 其他编辑工具

**迁移示例**:
```cpp
// 旧代码
bool UVoxelBlockWorldSubsystem::modifyChunk(FIntVector ChunkIndex)
{
    if (LoadedChunks.Contains(ChunkIndex))
    {
        return true;
    }
    return false;
}

// 新代码（迁移后）
FVoxelTemplateResult UVoxelBlockWorldSubsystem::modifyChunk(FIntVector ChunkIndex)
{
    if (!LoadedChunks.Contains(ChunkIndex))
    {
        return FVoxelTemplateResult::Failure(
            EVoxelTemplateError::ChunkNotLoaded,
            TEXT("区块未加载"),
            FString::Printf(TEXT("ChunkIndex: %s"), *ChunkIndex.ToString())
        );
    }

    // ... 操作逻辑
    return FVoxelTemplateResult::Success();
}
```

### 5.3 阶段3: 统一错误处理

**目标**: 所有编辑系统使用统一的错误码

**统一错误码**: `EVoxelEditorError`（扩展自`EVoxelTemplateError`）

## 6. 最佳实践

### 6.1 错误处理检查清单

**✅ 应该做**:
- 所有公共接口返回结构化错误信息
- 错误消息包含足够的上下文
- 记录错误日志到指定的Log类别
- 向用户显示有意义的错误信息

**❌ 不应该做**:
- 吞掉错误(静默失败)
- 只返回bool而不管原因
- 使用通用的"Unknown Error"
- 硬编码错误消息(使用映射表)

### 6.2 日志记录

```cpp
if (Result.IsError())
{
    // 记录详细错误日志
    UE_LOG(LogTemplate, Error, TEXT("[%s] %s: %s - %s"),
           *TEXT(__FUNCTION__),
           *GetErrorName(Result.ErrorCode),
           *Result.ErrorMessage,
           *Result.Context);

    // 显示给用户(简化版)
    ShowErrorMessage(Result.ErrorMessage);
}
```
