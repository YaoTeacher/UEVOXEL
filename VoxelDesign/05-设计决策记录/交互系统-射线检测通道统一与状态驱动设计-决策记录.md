## 二、架构现状 —— 深入调查结论

### 2.1 StateComponent 已有集中式数据

当前 `UVoxelControllerStateComponent` 已持有建造流程的全部数据：

| 数据 | 说明 |
|------|------|
| `CurrentToolTag` | 当前工具（单体素/家具/模板/几何体/区域创建/区域修改） |
| `TmpGeometry` | 编辑中的临时几何体（Box + Rotation + ShapeType 等） |
| `FirstEditPoint` / `SecondEditPoint` | 两点框选的起止世界坐标 |
| `TmpAreaInfo` | 临时区域信息（不含 Coverage，Coverage 来自 TmpGeometry.Box） |
| `CurArea` | 当前选中的区域 Actor |
| `PlayerMode` | 控制器模式（非建造/建造） |

### 2.2 Gizmo 操作已经数据集中

**关键发现**：TranslateGizmo / RotateGizmo / FaceGizmo 三个 Handler 全部只修改 `StateComponent.TmpGeometry`，从不直接改 PreviewActor 的 Transform。

PreviewActor 是被动刷新——监听 `OnBuildModeParamsUpdated` 广播事件，然后从 `StateComponent.TmpGeometry` 读取最新数据重建 mesh 和 transform。

### 2.3 Area 工具共享同一套 Gizmo

当前 `Tool_AreaEdit_Create` 和 `Tool_AreaEdit_Modify` 走的是和 SimpleGeometry 完全相同的 Gizmo 交互管线——修改的都是 `TmpGeometry.Box`。提交时 `TmpAreaInfo.Coverage` 从 `TmpGeometry.Box` 读取。

### 2.4 PreviewState 现状分布

`EPreviewInteractionState`（HIDDEN / BASE / EDIT / CONFIRM）**当前存放在 PreviewActor**，但被 3 个组件跨层使用：

| 组件 | 干什么 | 访问方式 |
|------|--------|---------|
| `InteractComponent` | 获取当前阶段决定输入分发 | `VC→PreviewActor→GetPreviewState()` |
| `VisualUIComponent` | 切换阶段时控制 Gizmo 显隐 | `SetPreviewState()` + `CancelEdit()` |
| `PreviewActor` | 控制自身显隐 | 内部 `SetPreviewState()` |

**问题：输入组件要穿透两层拿到状态决策值，耦合深。**

## 三、核心重构：BuildPhase 上移到 StateComponent

### 决策：EPreviewInteractionState → BuildPhase，从 PreviewActor 移到 StateComponent

**理由**：HIDDEN → BASE → EDIT → CONFIRM 描述的是**建造流程的阶段**（第一阶段选点 → 第二阶段框选 → 第三阶段 Gizmo 精修 → 确认提交），不是 Actor 的视觉周期。它是输入分发的核心判断依据，应该和 `CurrentToolTag` 放在同一位置。

### 改后的架构

```
StateComponent（建造流程的单一事实来源）
├── CurrentToolTag          ← 什么工具
├── BuildPhase              ← 什么阶段 【NEW：从 PreviewActor 上移】
├── TmpGeometry             ← 编辑中的几何数据
├── FirstEditPoint / SecondEditPoint
├── CurArea                 ← 当编辑已有区域时
└── ...

PreviewActor（纯视觉反应器）
├── 监听 OnBuildModeParamsUpdated → 重建 Mesh
├── 监听 BuildPhase 变化 → 显示/隐藏自身
├── 监听 BuildPhase 变化 → 通知 VisualUIComponent 调整 Gizmo
└── 不持有 BuildPhase，改为从 StateComponent 读取

VisualUIComponent（Gizmo 管理 + 视觉协调）
├── 监听 OnBuildModeParamsUpdated → 更新 PreviewActor 渲染
├── 监听 BuildPhase 变化 → 显示/隐藏 Gizmo + HeightCollision
├── 持有 12 个 Gizmo Actor 实例，统一管理生命周期
└── Gizmo 定位位置来自 TmpGeometry（从 StateComponent 读取）
```

### 改动的具体文件

#### 文件 1：`VoxelControllerStateComponent.h` — 新增 BuildPhase

在 `CurrentToolTag` 附近新增：
```cpp

EPreviewInteractionState BuildPhase = EPreviewInteractionState::HIDDEN;

// 新增访问器：
UFUNCTION(BlueprintPure, Category = "Voxel|State|Build")
EPreviewInteractionState GetBuildPhase() const { return BuildPhase; }

// 新增设置器（会广播 OnBuildModeParamsUpdated）：
UFUNCTION(BlueprintCallable, Category = "Voxel|State|Build")
void SetBuildPhase(EPreviewInteractionState NewPhase);
```

#### 文件 2：`VoxelControllerStateComponent.cpp` — 实现 SetBuildPhase

```cpp
void UVoxelControllerStateComponent::SetBuildPhase(EPreviewInteractionState NewPhase)
{
    if (BuildPhase == NewPhase) return;
    BuildPhase = NewPhase;
    OnBuildModeParamsUpdated.Broadcast();
}
```

#### 文件 3：`VoxelPreviewActor.h` — 移除 PreviewState 所有权

移除成员变量：
- `EPreviewInteractionState PreviewState = EPreviewInteractionState::HIDDEN;` ← 删除

#### 文件 4：`VoxelControllerVisualUIComponent.cpp` — SetPreviewState 改为监听 BuildPhase

影响点：

## 四、统一检测策略

### 4.1 策略表

**InputComponent 的检测决策仅读取 StateComponent，不穿透任何其他对象。**

```
检测决策 = f(SC->GetControllerMode(), SC->GetBuildPhase(), SC->GetCurrentToolTag())
```

| ControllerMode | Tool | BuildPhase | 检测内容 | 通道 |
|---------------|------|-----------|---------|------|
| **非 SceneBuildMode** | 任意 | 任意 | **不检测** | — |
| SceneBuildMode | 单体素 | (不用 Phase) | 地面 | BuildGround |
| SceneBuildMode | 家具 | (不用 Phase) | 地面 | BuildGround |
| SceneBuildMode | **模板** | HIDDEN | 地面（放置） | BuildGround |
| SceneBuildMode | **模板** | EDIT | **Gizmo + 地面参考** | **3DUI + BuildGround** |
| SceneBuildMode | 简单几何体 | HIDDEN | 地面（选第一点） | BuildGround |
| SceneBuildMode | 简单几何体 | BASE | 地面（框选范围） | BuildGround |
| SceneBuildMode | 简单几何体 | EDIT | **Gizmo + 地面参考** | **3DUI + BuildGround** |
| SceneBuildMode | 区域创建 | HIDDEN | 地面（选第一点） | BuildGround |
| SceneBuildMode | 区域创建 | BASE | 地面（框选范围） | BuildGround |
| SceneBuildMode | 区域创建 | EDIT | **Gizmo + 地面参考** | **3DUI + BuildGround** |
| SceneBuildMode | 区域修改 | HIDDEN | 地面（选第一点） | BuildGround |
| SceneBuildMode | 区域修改 | BASE | 地面（框选范围） | BuildGround |
| SceneBuildMode | 区域修改 | EDIT | **Gizmo + 地面参考** | **3DUI + BuildGround** |

> 规律：EDIT 状态 = 检测 Gizmo（3DUI）。非 EDIT = 检测地面（BuildGround）。两者互斥。

### 4.2 交互事件分发

| 输入事件 | BuildPhase | 做什么 |
|---------|-----------|--------|
| **Click（按下）** | HIDDEN | 查地面 → 设置 FirstPoint → SetBuildPhase(BASE) |
| **Click（按下）** | BASE | (不处理，由 Ongoing 持续更新) |
| **Click（按下）** | EDIT + 命中 Gizmo | 激活 ActiveDragGizmo，记录拖拽零点 |
| **Click（按下）** | EDIT + 未命中 Gizmo | 查地面 → 确认编辑 / 无操作 |
| **Click（按下）** | EDIT + 单体素/家具 | 查地面 → 直接放置 |
| **Hold（每帧 Tick）** | BASE + bIsModyfing | 查地面 → 更新 SecondPoint → 范围预览 |
| **Hold（每帧 Tick）** | EDIT + ActiveDragGizmo | 查地面 → 更新 SecondPoint → Gizmo 拖拽 |
| **Release（松开）** | BASE | 松手确认范围 → SetBuildPhase(EDIT) |
| **Release（松开）** | EDIT | 释放 ActiveDragGizmo，结束拖拽 |

### 4.3 状态转移图

```
非建造模式 → 不运行检测

场景建造模式：
                        
   [切换工具/取消]          [切换工具/取消]
        ↓                       ↓
     HIDDEN ───[Click 地面]──▶ BASE ───[Release]──▶ EDIT ───[StepBack/Cancel]──▶ HIDDEN
        ↑                       │                     │
        └───────[StepBack]──────┘                     │
         (完全取消)                                    │
        ┌─────────────────────────────────────────────┘
        │    [单次 Gizmo 操作完成? → 保留 EDIT 继续调整]

        [Click] → 放置 → 完（不进入 Phase 状态机）
        
  模板（特殊）：
        HIDDEN ───[Click 地面]──▶ EDIT ───[Gizmo 拖动]─── 调整位置/旋转
                                       └──[StepBack]──▶ HIDDEN
```

## 七、TickComponent 补充 Gizmo 拖拽持续更新

### 问题

当前 `HandleMouseInput` 只在按下时触发一次。Gizmo 拖拽需要**按住不放时每帧更新**，否则 Gizmo Translate/Rotate/Face 只能更新一次位置。

### 方案

在 `TickComponent` 中加入 Gizmo 拖拽循环：

```
TickComponent 流程：

1. if (非SceneBuildMode) → return
2. 读取 SC->BuildPhase, SC->CurrentToolTag
3. if (BuildPhase == EDIT && ActiveDragGizmo != nullptr)
       → DeprojectMousePositionToWorld
       → LineTraceSingleByChannel(BuildGround) 打地面获取世界坐标
       → HandleGizmoInteraction(ActiveDragGizmo, GroundHit.Location)
       → return（跳过 Hover）
4. 非拖拽状态：委托 HandleMouseHover 处理（单体素/家具预览）
```

### 代码位置：`VoxelControllerInteractComponent.cpp` L1575-1580

当前 TickComponent 为空。补充后：

```cpp
void UVoxelControllerInteractComponent::TickComponent(float DeltaTime,
    ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction)
{
    Super::TickComponent(DeltaTime, TickType, ThisTickFunction);

    UVoxelControllerStateComponent* SC = GetControllerState();
    if (!SC) return;
    if (SC->GetControllerMode() != EVoxelControllerMode::SceneBuildMode) return;

    // Gizmo 拖拽持续更新
    if (ActiveDragGizmo)
    {
        APlayerController* PC = Cast<APlayerController>(GetOwner());
        if (!PC) return;

        FVector WorldLocation, WorldDirection;
        if (!PC->DeprojectMousePositionToWorld(WorldLocation, WorldDirection)) return;

        const FVector TraceEnd = WorldLocation + WorldDirection * TraceDistance;
        FHitResult GroundHit;
        FCollisionQueryParams Params;
        Params.bTraceComplex = false;

        if (GetWorld()->LineTraceSingleByChannel(
            GroundHit, WorldLocation, TraceEnd, ECC_GameTraceChannel1, Params))
        {
            HandleGizmoInteraction(ActiveDragGizmo, GroundHit.Location);
        }
        return;
    }

    // 非拖拽：Hover 由蓝图 Tick 调用的 HandleMouseHover 处理
}
```

## 八、HandleMouseInput 重构

### 当前问题

1. 检测通道用错（Visibility → 3DUI）
2. 工具分支混乱：模板走家具放置逻辑，但模板需要 EDIT 的 Gizmo
3. 分支树深度 4 层（模式→工具→阶段→Gizmo 类型），难以维护

### 重构后的 HandleMouseInput 流程

```
void HandleMouseInput()
{
    SC = GetControllerState()
    非SceneBuildMode → return
    
    ToolTag = SC->GetCurrentToolTag()
    BuildPhase = SC->GetBuildPhase()

    // ===== 步骤1：决定该发射哪些射线 =====
    bool bNeedGizmoRay = (BuildPhase == EDIT);            // EDIT 状态下才检测 Gizmo
    bool bNeedGroundRay = (BuildPhase != EDIT)            // 非 EDIT 都检测地面
                          || (BuildPhase == EDIT);         // EDIT 也需要（作为世界坐标参考）

    // ===== 步骤2：发射射线 =====
    FHitResult GroundHit;
    if (bNeedGroundRay)
        LineTraceSingleByChannel(GroundHit, ..., ECC_GameTraceChannel1, ...)

    AVoxel3DUIActor* GizmoActor = nullptr;
    if (bNeedGizmoRay)
    {
        LineTraceSingleByChannel(GizmoHit, ..., ECC_GameTraceChannel6, ...)
        GizmoActor = Cast<AVoxel3DUIActor>(GizmoHit.GetActor())
    }

    // ===== 步骤3：按工具分发 =====
    if (ToolTag matches 单体素/家具)
        → 使用 GroundHit.Location 放置
    else if (ToolTag matches 模板)
        → SetBuildPhase(EDIT) + Gizmo 交互
    else
        → HandleGizmoInteraction(GizmoActor, GroundHit.Location)
}
```

## 十、AreaEdit_Modify 的 Gizmo 定位到目标 Area Actor

### 当前问题

当前所有工具的 Gizmo 位置都从 `TmpGeometry.GetCenter(BlockLength)` 计算。对于 AreaEdit_Modify 的 EDIT 阶段，Gizmo 应该浮在**目标 Area Actor** 周围，而非 PreviewActor。

### 方案

在 VisualUIComponent 的 `HandleBuildModeParamsUpdated()` 中增加判断：

```
若 BuildPhase == EDIT 且 CurrentToolTag == Tool_AreaEdit_Modify 且 CurArea != nullptr：
    GizmoCenter = CurArea->GetActorLocation()
    GizmoBounds = CurArea->GetAreaWorldBounds()
否则：
    GizmoCenter = Geometry.GetCenter(BlockLength)
    GizmoBounds = Geometry.GetBound(BlockLength)
```

### 前提

- `CurArea` 已在 `SelectArea()` 中设置到 StateComponent
- `GetAreaWorldBounds()` 需确认 VoxelAreaBaseInstance 是否有该方法或等效计算（由 `AreaCoverage.Min/Max × BlockLength` 算出）

**此部分为后续独立实现**，当前先打通数据流：`SC->CurArea` → `HandleBuildModeParamsUpdated` 读取。

| **模板 EDIT** | 模板工具点击 → Gizmo 出现 → 拖动 | 模板预览可移动/旋转 |
| **几何体框选** | 几何体工具拖框 → 松手进 EDIT → Gizmo 出现 | 流程正常 |
| **区域创建** | 区域创建工具拖框 → 松手进 EDIT | Gizmo 出现 |
| **非建造模式零开销** | 切到漫游模式 | HandleMouseInput/TickComponent 提前 return |
| **日志确认** | 看 `[DEBUG] HandleMouseInput` | BuildPhase 和 GizmoActor 日志正确 |
