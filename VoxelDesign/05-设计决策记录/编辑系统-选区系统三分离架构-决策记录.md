## 决策1: 引入三分离选区系统架构

**日期**: 2026-01-23

**决策背景**：
- 原有的选择系统将"选择"和"选区"概念混淆
- 选区工具和操作工具职责不清
- 工具切换逻辑混乱,用户不知道选区何时会被清空
- 简单几何体的预览阶段与选区工具功能重合

**考虑的选项**：
- **A. 保持现有架构**
  - 优点: 无需修改,现有代码继续工作
  - 缺点: 概念混淆继续存在,扩展困难

- **B. 扩展现有枚举,添加更多状态**
  - 优点: 最小化代码修改
  - 缺点: 枚举爆炸,难以理解和维护

- **C. 三分离架构** ✅
  - 优点: 概念清晰,职责明确,易于扩展
  - 缺点: 需要重构现有代码

**选择的方案**: C - 三分离架构

**选择理由**：
1. **概念清晰**: 选区是数据,选区工具是修改手段,操作工具是消费者
2. **职责明确**: 每层有明确的职责,互不干扰
3. **易于扩展**: 新增选区工具或操作工具不影响其他层
4. **用户友好**: 工具切换规则简单,选区生命周期清晰

**权衡和风险**：
- **权衡**: 需要重构现有代码,但长期收益大于短期成本
- **风险**: 现有33+文件引用选区相关枚举,需要渐进式迁移

## 决策2: 选区工具分类为四种类型

**日期**: 2026-01-23

**决策背景**：
- 需要统一不同选区定义方式的接口
- 用户需要灵活的选区构建能力
- 必须支持复杂选区的组合构建

**考虑的选项**：
- **A. 框选、魔棒、多边形** (原方案)
  - 优点: 基础功能完整
  - 缺点: 缺少参数化形状选区,缺少自由绘制能力

- **B. 框选、魔棒、多边形、几何体** (中间方案)
  - 优点: 增加参数化形状
  - 缺点: 几何体与选区概念混淆

- **C. 单点、几何、笔刷、魔棒** ✅
  - 优点: 覆盖所有使用场景,概念清晰
  - 缺点: 工具数量增加,需要统一抽象

**选择的方案**: C - 四种选区工具类型

**选择理由**：
1. **单点选择**: 最基础的选择单位,精确编辑
2. **几何选区**: 参数化定义规则形状,适合建筑
3. **笔刷选区**: 自由绘制,适合有机形状和细节雕刻
4. **魔棒选区**: 智能扩展,基于连通性和类型匹配

**权衡和风险**：
- **权衡**: 工具数量增加,但通过统一抽象降低复杂度
- **风险**: 需要清晰的用户引导和文档说明

**工具特性对比**：

| 工具 | 可调整性 | 切换保留 | 布尔运算 | 典型场景 |
|------|---------|---------|---------|---------|
| 单点 | ❌ | ❌ | ✅ | 精确编辑 |
| 几何 | ✅ 整体调整 | ✅ | ✅ | 规则建筑 |
| 笔刷 | ✅ 增删修改 | ✅ | ✅ | 有机形状 |
| 魔棒 | ✅ 重新选择 | ✅ | ✅ | 连通区域 |

## 决策3: 操作工具分为两类

**日期**: 2026-01-23

**决策背景**：
- 部分编辑操作需要预选区(移动、复制、删除)
- 部分编辑操作不需要预选区(新增体素、几何体建造、蓝图放置)
- 需要明确区分这两类工具的交互逻辑

**考虑的选项**：
- **A. 所有工具统一处理**
  - 优点: 简化架构
  - 缺点: 直接操作工具强制要求预选区,不符合直觉

- **B. 分为直接操作和选区操作** ✅
  - 优点: 交互逻辑清晰,符合用户直觉
  - 缺点: 增加一层分类

**选择的方案**: B - 两类操作工具

**选择理由**：
1. **直接操作工具**: 不需要预选区,操作后自动生成选区,便于后续编辑
2. **选区操作工具**: 需要预选区,对现有选区执行操作
3. **自动选区生成**: 几何体建造后自动选中,可立即移动或复制

**工具分类**：

| 类型 | 工具 | 选区要求 | 后续行为 |
|------|------|---------|---------|
| 直接操作 | 新增体素 | 无需预选区 | 自动生成选区 |
| 直接操作 | 几何体建造 | 无需预选区 | 自动生成选区 |
| 直接操作 | 蓝图放置 | 无需预选区 | 自动生成选区 |
| 选区操作 | 移动 | 必须有选区 | 保留选区 |
| 选区操作 | 复制/粘贴 | 复制需要选区 | 保留选区 |
| 选区操作 | 删除 | 必须有选区 | 清空选区 |
| 选区操作 | 替换 | 必须有选区 | 保留选区 |
| 选区操作 | 选区内填充 | 必须有选区 | 保留选区 |
| 选区操作 | 保存为模板 | 必须有选区 | 保留选区 |

## 决策4: 选区生命周期为手动清空前持久保存

**日期**: 2026-01-23

**决策背景**：
- 用户需要在不同工具间切换并保持选区
- 需要支持复杂的选区构建流程(多个工具组合使用)
- 用户期望明确的选区生命周期管理

**考虑的选项**：
- **A. 每次操作后自动清空**
  - 优点: 简化实现
  - 缺点: 无法组合工具使用,不符合用户期望

- **B. 单点选择切换模式清空,其他保留** ✅
  - 优点: 平衡灵活性和简单性
  - 缺点: 需要清晰的用户引导

**选择的方案**: B - 混合策略

**选择理由**：
1. **单点选择**: 立即清空(因为最简单,用户通常不需要保留)
2. **几何/笔刷/魔棒**: 切换模式保留(因为构建复杂选区需要多次操作)
3. **手动清空**: Esc/Delete/清空按钮/Ctrl+D

**清空策略**：

| 选区类型 | 清空时机 |
|---------|---------|
| 单点选择 | 切换模式自动清空 |
| 几何选区 | 手动清空 |
| 笔刷选区 | 手动清空 |
| 魔棒选区 | 手动清空 |
| 直接操作生成的选区 | 下一次直接操作替换 |

## 决策5: 选区内填充工具的四种模式

**日期**: 2026-01-23

**决策背景**：
- 用户需要在选区内执行不同类型的编辑
- 简单的"删除"或"替换"无法覆盖所有场景
- 需要明确区分填充、替换、删除、完全修改的语义

**考虑的选项**：
- **A. 只提供删除和替换**
  - 优点: 简化UI
  - 缺点: 无法满足"只填补空缺"等常见场景

- **B. 提供四种模式** ✅
  - 优点: 覆盖所有使用场景,语义清晰
  - 缺点: UI稍复杂

**选择的方案**: B - 四种模式

**选择理由**：
1. **填充(Complement)**: 只在空位放置,保留现有体素
2. **替换(Replace)**: 只替换现有体素,保留空位
3. **删除(Destruct)**: 删除所有体素为空
4. **完全修改(Normal)**: 覆盖所有位置,不管现状

**场景对比**：

| 模式 | 操作前 | 操作后 | 使用场景 |
|------|--------|--------|---------|
| 填充 | `██░░` | `████` | 填补空缺,保留现有 |
| 替换 | `██░░` | `██░░` | 材质更换,保留空位 |
| 删除 | `████` | `░░░░` | 清空区域 |
| 完全修改 | `██░░` | `████` | 强制覆盖 |

**与三维度枚举的映射**：
- 填充: `Build` + `Complement`
- 替换: `Paint` + `Replace`
- 删除: `Destruct`
- 完全修改: `Build` + `Normal`

## 决策6: 几何体预览作为参数化选区定义器

**日期**: 2026-01-23

**决策背景**：
- 简单几何体(盒/球/圆柱)在场景中通过Gizmo交互调整
- 原有架构将几何体作为独立编辑工具
- 与选区工具功能重合

**考虑的选项**：
- **A. 保持独立编辑工具**
  - 优点: 现有代码无需修改
  - 缺点: 与选区系统割裂,功能重复

- **B. 几何体作为参数化选区定义器** ✅
  - 优点: 统一架构,复用代码,功能一致
  - 缺点: 需要重构

**选择的方案**: B - 参数化选区定义器

**选择理由**：
1. 几何体预览阶段本质上是在定义选区
2. 可以复用BatchEditTool的形状计算代码
3. 几何选区与框选/魔棒/笔刷并列,都是选区定义方式
4. 几何选区确认后,可以像其他选区一样执行移动/复制等操作

**架构对比**：

| 方面 | 独立编辑工具 | 参数化选区定义器 |
|------|-------------|-----------------|
| 数据流 | 几何参数 → 编辑 | 几何参数 → 选区 → 编辑 |
| 后续操作 | 只能建造 | 移动/复制/删除/填充/模板 |
| 代码复用 | 形状计算重复 | 复用BatchEditTool |
| 用户体验 | 功能割裂 | 统一体验 |

**复用关系**：
```
几何选区工具 → 复用BatchEditTool的形状计算
  ├─ CalculateBoxVoxels()
  ├─ CalculateSphereVoxels()
  └─ CalculateCylinderVoxels()
```

## 总结

### 关键决策

1. ✅ 引入三分离架构(选区数据、选区工具、操作工具)
2. ✅ 选区工具分类为四种(单点、几何、笔刷、魔棒)
3. ✅ 操作工具分为两类(直接操作、选区操作)
4. ✅ 选区生命周期为手动清空前持久保存
5. ✅ 选区内填充提供四种模式
6. ✅ 几何体预览作为参数化选区定义器

### 架构演进

```
v2.x: 混合架构
选择工具 + 批量编辑工具 (职责混淆)
    ↓
v3.0: 三分离架构
选区数据 + 选区工具 + 操作工具 (职责清晰)
```

### 迁移策略

**阶段1: 桥接层** (1-2天)
- 添加新接口和抽象
- 保留旧接口,标记废弃
- 零破坏性变更

**阶段2: 双API共存** (1-2周)
- 新功能使用新架构
- 旧功能逐步迁移
- 编译时警告引导

**阶段3: 清理** (1周)
- 移除废弃代码
- 完整测试
- 文档更新
