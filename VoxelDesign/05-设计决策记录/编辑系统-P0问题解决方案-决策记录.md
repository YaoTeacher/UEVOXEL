## P0-1: 工具Tag替代BuildState枚举

### 决策内容

废弃`EVoxelControllerBuildState`枚举，使用GameplayTag工具层级来区分操作对象类型。

### 工具Tag层级设计

```ini
; 第一层：工具功能分类
+GameplayTagList=(Tag="Voxel.Tool.Selection",DevComment="选区工具-用于定义选区")
+GameplayTagList=(Tag="Voxel.Tool.Edit",DevComment="编辑工具-用于修改世界")
+GameplayTagList=(Tag="Voxel.Tool.AreaEdit",DevComment="区域编辑工具")

; 第二层：选区工具子类型
+GameplayTagList=(Tag="Voxel.Tool.Selection.SingleVoxel",DevComment="单体素选择")
+GameplayTagList=(Tag="Voxel.Tool.Selection.SimpleGeometry",DevComment="简单几何体选择")
+GameplayTagList=(Tag="Voxel.Tool.Selection.Brush",DevComment="笔刷选择")

; 第二层：编辑工具子类型
+GameplayTagList=(Tag="Voxel.Tool.Edit.SingleVoxel",DevComment="单体素编辑-放置体素/家具")
+GameplayTagList=(Tag="Voxel.Tool.Edit.SimpleGeometry",DevComment="简单几何编辑")
+GameplayTagList=(Tag="Voxel.Tool.Edit.Selection",DevComment="选区操作工具-移动/复制/删除选区内容")
+GameplayTagList=(Tag="Voxel.Tool.Edit.Template",DevComment="模板放置工具")

; 第二层：区域编辑工具子类型
+GameplayTagList=(Tag="Voxel.Tool.AreaEdit.Create",DevComment="创建区域")
+GameplayTagList=(Tag="Voxel.Tool.AreaEdit.Modify",DevComment="修改区域")
```

### StateComponent调整

**旧版**:
```cpp
class UVoxelControllerStateComponent
{
    UPROPERTY(BlueprintReadOnly)
    EVoxelControllerBuildState BuildState;  // ❌ 废弃
    
    UPROPERTY(BlueprintReadOnly)
    EVoxelControllerEditState EditState;    // ✅ 保留
};
```

**新版**:
```cpp
class UVoxelControllerStateComponent
{
    UPROPERTY(BlueprintReadOnly)
    FGameplayTag CurrentToolTag;  // ✅ 替代BuildState
    
    UPROPERTY(BlueprintReadOnly)
    EVoxelControllerEditState EditState;  // ✅ 保留
    
    UPROPERTY(BlueprintReadOnly)
    TMap<FName, FString> ToolParameters;  // ✅ 工具参数
};
```

### 理由

**优势**:
- 可扩展性：新增操作对象类型无需修改枚举，只需添加新Tag
- 层级化管理：工具Tag自然支持层级结构
- 数据驱动：工具配置可通过数据表管理

**劣势**:
- 类型安全性降低：Tag是字符串，不如枚举类型安全
- 缓解措施：使用`FGameplayTag::RequestGameplayTag()`确保有效性

## P0-2: 旋转矩阵关键测试点

### 决策内容

无需编写自动化单元测试，提供手动测试的关键测试点清单。

### 关键测试点

1. **基础功能测试**: 6个方向变换正确性
2. **边界条件测试**:
   - 奇数尺寸: 3x3x3, 5x7x3（几何中心在整数坐标）
   - 偶数尺寸: 4x4x4, 6x8x4（几何中心在.5坐标）
   - 不对称尺寸: 3x5x7
   - 单个体素: 1x1x1

3. **逆运算测试**:
   - Forward→Backward→Forward
   - Left→Right→Left
   - 任意方向→反向→原方向

4. **锚点一致性测试**:
   - 底面中心计算: `(Size.X-1)/2, (Size.Y-1)/2, 0`

5. **实际场景测试**:
   - 模板数据完整性（旋转前后体素数量不变）
   - 坐标不丢失（所有体素旋转后在合理范围内）
   - 无重复坐标（旋转后不会有两个体素映射到同一位置）

## P0-3: Palette跨平台排序一致性

### 决策内容

使用显式索引映射替代按TagName排序，确保跨平台一致性。

### 当前实现（存在风险）

```cpp
// 按TagName排序（跨平台风险）
Palette.Sort([](const FGameplayTag& A, const FGameplayTag& B) {
    return A.GetTagName().Compare(B.GetTagName()) < 0;
});
```

### 解决方案：显式索引映射

```cpp
// 创建Palette时维护索引映射
TArray<FGameplayTag> Palette;  // 有序数组
TMap<FGameplayTag, int32> TagToIndex;  // Tag→索引映射

// 添加新Tag时
int32 NewIndex = Palette.Num();  // 使用当前大小作为索引
TagToIndex.Add(Tag, NewIndex);
Palette.Add(Tag);  // 按添加顺序，天然有序
```

### 优势

- 创建时已有序，无需排序操作
- 索引稳定，不受Tag内部表示变化影响
- 性能更好：O(1)插入

## P0-4: 历史记录预览恢复

### 决策内容

在`FVoxelEditHistoryRecord`中添加`Geometry`字段，支持撤销时恢复PreviewActor状态。

### 当前问题

撤销后：
- ✅ 世界数据已恢复（`FVoxelEdit.Edits`）
- ✅ EditMode已恢复
- ❌ PreviewActor状态丢失（无法恢复预览参数）

### 解决方案

```cpp
struct FVoxelEditHistoryRecord
{
    // ... 现有字段 ...
    
    // === 新增：预览恢复所需 ===
    UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Voxel|History|Record")
    FVoxelGeometryDesc Geometry;  // ← 只缺这一个！
};
```

### 撤销恢复流程

```cpp
// 撤销时恢复PreviewActor
1. 历史系统提供 FVoxelEditHistoryRecord
2. 使用 Record.Geometry.FirstP/SecondP 计算预览位置
3. 使用 Record.Geometry.Rotation 恢复旋转参数
4. 使用 Record.Geometry.ShapeType 恢复形状选择器
5. 从 Record.Edits 中取 NewType 恢复BlockType
6. 调用 PreviewActor->UpdateFromEditRequest(Request)
```

### 关键说明

- **BlockType**: 使用`FVoxelEdit.NewType`（已有）
- **TargetPosition**: 可通过`Geometry.FirstP/SecondP`计算
- **仅添加Geometry字段**
