## 决策1：确认/取消入口统一为场景锚定 2D 弹窗（UVoxelEditConfirmWidget）

**日期**：2026-08-21

**决策背景**：
M16 操作按钮模块在 v6 原型中已不在面板实例化（`ToolDetailPanel.cpp` 注释"确认/取消改为世界内浮标"），但实际只有 AreaEdit 工具拥有 3D 世界内确认/取消浮标（PreviewComponent 的 ConfirmButtonActor/CancelButtonActor），其余工具（简单几何、选区内编辑、家具、模板、选区形状、Cutout）没有任何世界附近的确认入口，确认语义分裂（v4 审查报告 C4 已点名）。

**考虑的选项**：
- A. 把 3D 浮标（Voxel3DUIActor + TextRender）推广到全部工具
- B. 新建 2D 屏幕空间弹窗，每帧投影跟随编辑锚点，统一替换 3D 浮标
- C. 恢复 M16 面板模块，不做场景弹窗

**选择的方案**：B

**选择理由**：
- 2D UMG 控件的交互可靠性（点击命中、样式、可读性）远优于 3D Mesh + TextRender 浮标
- 项目已有全部基础设施：InfoTooltip 的投影+视口钳制算法（`VoxelInfoTooltip.cpp`）、Layout 常驻控件挂载模式（DragProgressWidget）、模块自绑 StateComponent 广播模式（M1）
- 消除确认语义分裂：所有工具共用同一确认形态，符合 v4 审查"同类动作统一主按钮形态"的要求
- DESIGN_UMG.md §7 已明确"确认/取消在世界内浮标、底带无执行按钮"，弹窗是该决策的落地形态

**权衡和风险**：
- 弹窗每帧投影有少量开销（仅 EDITING 态、单个控件，可忽略）
- 弹窗可能短暂遮挡 Gizmo，通过 TargetOffset 偏移缓解

## 决策2：弹窗显隐唯一条件 = BuildPhase == EDITING，不维护工具白名单

**日期**：2026-08-21

**决策背景**：
需要确认的工具（有 OnConfirmEdit 的工具）恰好都是会进入 EDITING 阶段的工具；即时操作工具（单体素、选区笔刷）不进 EDITING。

**考虑的选项**：
- A. 弹窗内维护 GameplayTag 白名单
- B. 以 `BuildPhase == EPreviewInteractionState::EDITING` 为唯一显示条件

**选择的方案**：B

**选择理由**：
- EDITING 即"有待确认编辑"的唯一权威状态，白名单会随工具增减漂移
- 新工具只要遵循既有阶段流转就自动获得弹窗，零接入成本

**权衡和风险**：
- 若未来某工具进入 EDITING 但确认语义特殊，需要再评估（当前无此工具）

## 决策3：取消语义统一为完整取消（CancelCurrentEdit），废弃轻量取消入口

**日期**：2026-08-21

**决策背景**：
取消曾有两个层级且行为不等价：`RequestCancelVoxelEdit`（只清 TmpEditRequest + 预览，不重置 BuildPhase、不广播，UI 刷新有缺口）与 `CancelCurrentEdit`（清输入态 + ResetEditSession 广播 + PreviewComp 回退，右键取消链路所用）。M16 的 ResetButton 和 AreaEdit 3D 浮标取消键走的是前者。

**选择的方案**：弹窗取消按钮与右键取消统一调 `ToolComp->CancelCurrentEdit()`。

**选择理由**：
- 同一语义两个入口是 bug 温床；用户预期"取消"= 放弃编辑回到 IDLE
- 完整取消带广播，弹窗与面板能靠订阅正确刷新（轻量取消不广播是已知缺陷）
- `RequestCancelVoxelEdit` 保留在 ToolComp 上（可能有其他调用方），但 UI 层不再使用

**权衡和风险**：
- AreaEdit 点取消的行为从"轻量清理"变为"完整重置"，属于有意的行为统一

## 决策4：废弃 AreaEdit 3D 浮标及其 PreviewComponent 配套代码

**日期**：2026-08-21

**决策内容**：
随弹窗上线，移除：
- `VoxelAreaEditTool`：OnMouseInput 的 3D 按钮点击拦截、UpdatePreview/ConfigureGizmos 的 Show/HideAreaConfirmButtons 调用
- `VoxelPreviewComponent`：ConfirmButtonActor/CancelButtonActor、AreaConfirmButtonMesh/AreaCancelButtonMesh/AreaButtonMaterial、Ensure/Update/Face/Show/Hide 五个函数及构造/销毁/Tick 中的配套调用

AreaEdit 的确认/取消改由场景弹窗承担（确认仍经 `RequestConfirmVoxelEdit → AreaEditTool::OnConfirmEdit` 内部分支 CommitArea/ModifyArea，无需 UI 侧 Tag 分发——DR-AREA编辑链路修复.md 时代的 UI 分发已被 ToolRegistry 路由取代）。

## 附：链路与定位约定

- **显示链路**：工具流转 → `SC->SetBuildPhase(EDITING)` → 广播 `OnBuildPhaseChanged` → 弹窗自绑回调刷新（UI 只订阅不直改，符合数据流铁律）
- **锚点**：`SC->GetTmpGeometry().GetBound(BlockLength)` 包围盒顶部中心；选区类工具的范围由 SC 的 HandleSelectionChanged 同步进 TmpGeometry.Box，无特例
- **定位**：弹窗 NativeTick 每帧 `ProjectWorldLocationToScreen` + 偏移 + 视口钳制（复刻 InfoTooltip 钳制策略）；投影失败（锚点在相机后方）时隐藏，恢复后自动出现
- **定位落点（2026-08-21 修正）**：UE5.8 的 `SetPositionInViewport` 只作用于直接 `AddToViewport` 的控件（走 `UGameViewportSubsystem` 槽位），对 RootCanvas 子控件**不会移动 CanvasPanelSlot**。弹窗改为直接写 `CanvasPanelSlot->SetPosition(目标像素 / ViewportScale)` + 左上锚点 + AutoSize。**注意**：`VoxelInfoTooltip::UpdatePositionNearWorldLocation` 仍在用 `SetPositionInViewport`，同样受此坑影响，后续需同样改造
- **层级**：RootCanvas 常驻子控件，位于 HUD/建造面板之上、Modal/Toast 之下（v4 审查 z 层级表：HUD < 浮标 < 模态 < Toast）
- **双通道**：M15 的 PlaceButton（家具/模板）与弹窗构成确认双通道，互为冗余（v4 审查推荐模式）
- **生命周期**：由 `UVoxelPrimaryGameLayout::NativeOnInitialized` 常驻创建（`EditConfirmWidgetClass` 配置蓝图 `WBP_EditConfirmWidget`），默认 Collapsed，不做反复 Create/Destroy
