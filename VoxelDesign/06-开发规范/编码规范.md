## 📋 概述

本文档定义了 Voxel 项目的编码规范，包括命名规范、体素位置坐标的传输和使用规范，确保代码的一致性和正确性，避免位置转换错误和性能问题。

**核心原则**：
- 统一的命名规范，提高代码可读性
- 在业务逻辑层使用索引坐标（INDEX），只在显示和几何计算时转换为世界坐标（POSITION）

---

## 🏷️ 命名规范

### 组件命名规范

**规则**: 所有 Component 类型后缀使用完整单词 `Component`

#### ✅ 正确示例

```cpp
// 类名：使用完整 Component 后缀
class UVoxelControllerStateComponent : public UActorComponent
class UVoxelControllerInteractComponent : public UActorComponent
class UVoxelControllerVisualUIComponent : public UActorComponent
class UVoxelControllerHistoryComponent : public UActorComponent

// 变量名：使用完整 Component 后缀
TObjectPtr<UVoxelControllerStateComponent> StateComponent;
TObjectPtr<UVoxelControllerInteractComponent> InteractComponent;
TObjectPtr<UVoxelControllerVisualUIComponent> VisualUIComponent;
```

#### ❌ 错误示例

```cpp
// 类名：不要使用缩写
class UVoxelControllerStateComp : public UActorComponent;  // 错误！

// 变量名：不要使用缩写
TObjectPtr<UVoxelControllerStateComponent> StateComp;  // 错误！
```

#### 理由

1. **完整单词更清晰**: `Component` 比 `Comp` 更明确，避免歧义
2. **符合 UE 命名惯例**: Unreal Engine 官方推荐使用完整单词
3. **提高可读性**: 缩写降低代码可读性，增加理解成本
4. **便于搜索**: 搜索 `Component` 比搜索 `Comp` 更精确

#### 特殊情况

以下情况可以不遵循此规范：
- 第三方库或引擎提供的组件，保持原有命名
- 历史遗留代码，标记为 TODO 逐步重构

### 类命名规范

**规则**: 使用 PascalCase，前缀反映类型

#### 类前缀

| 前缀 | 用途 | 示例 |
|------|------|------|
| `A` | Actor 类 | `AVoxelPlayerController`, `AVoxelPreviewActor` |
| `U` | UObject 类 | `UVoxelControllerStateComponent`, `UVoxelAreaWorldSubsystem` |
| `F` | 结构体 | `FVoxelEditRequest`, `FVoxelGeometryDesc` |
| `E` | 枚举 | `EVoxelControllerEditState`, `EPreviewMode` |
| `I` | 接口 | `IVoxelInteractiveInterface` |

#### ✅ 正确示例

```cpp
// Actor 类
class AVoxelPlayerController : public APlayerController
class AVoxelPreviewActor : public AActor
class AVoxel3DUIActor : public AActor

// Component 类
class UVoxelControllerStateComponent : public UActorComponent
class UVoxelBlockWorldSubsystem : : public UWorldSubsystem

// 结构体
struct FVoxelEditRequest
struct FVoxelGeometryDesc

// 枚举
enum class EVoxelControllerEditState : uint8
enum class EPreviewMode : uint8
```

### 函数命名规范

**规则**: 使用 PascalCase，动词开头，明确表达意图

#### ✅ 正确示例

```cpp
// 动词开头，明确表达意图
void UpdateSingleVoxelPreview(...);
void SetControllerMode(EVoxelControllerMode NewMode);
bool CheckModificationPermission(...);
FIntVector GetBlockIndexByPosition(...);

// 布尔返回值使用 Is/Has/Can 前缀
bool IsValid() const;
bool HasValidBounds() const;
bool CanTransitionTo(EPreviewInteractionState NewState) const;
```

#### ❌ 错误示例

```cpp
// 不明确
void SingleVoxel(...);  // 缺少动词
bool Valid();           // 应该用 IsValid
void Data();            // 不明确
```

### 变量命名规范

**规则**: 使用 CamelCase，名词为主，明确表达内容

#### ✅ 正确示例

```cpp
// 成员变量
TObjectPtr<UVoxelControllerStateComponent> StateComponent;
FIntVector CurrentBlockIndex;
float CachedBlockLength;
bool bHasValidBounds;

// 布尔变量使用 b 前缀
bool bIsDragging;
bool bShowActorGizmos;
bool bCenterInitialized;

// 参数
void UpdatePreview(const FIntVector& BlockIndex, float BlockLength);
```

#### ❌ 错误示例

```cpp
// 不明确的缩写
TObjectPtr<UVoxelControllerStateComponent> SC;  // 应该用 StateComponent
FIntVector idx;                                  // 应该用 Index
float len;                                       // 应该用 Length

// 布尔变量缺少 b 前缀
bool IsDragging;    // 应该用 bIsDragging
bool IsValid;       // 成员变量应该用 bIsValid
```

## 📐 坐标空间定义

### INDEX（索引空间）

**类型**: `FIntVector`
**单位**: 体素索引（整数，如 0, 1, 2...）
**用途**: 业务逻辑层的所有数据传输和计算

**使用场景**：
- ✅ 子系统间数据传输
- ✅ StateComponent 状态存储
- ✅ BlockWorldSubsystem 方块管理
- ✅ AreaWorldSubsystem 区域管理
- ✅ HistoryComponent 历史记录
- ✅ 所有工具类计算
- ✅ 玩家交互逻辑
- ✅ 碰撞检测逻辑

**示例**：
```cpp
FIntVector BlockIndex = FIntVector(10, 20, 30);  // 第 10, 20, 30 个体素
```

### POSITION（世界坐标空间）

**类型**: `FVector`
**单位**: 米（浮点数，如 1000.0f, 2000.0f...）
**用途**: 显示层和几何计算

**使用场景**：
- ✅ VisualComponent UI 显示
- ✅ PreviewActor 预览渲染
- ✅ Actor 生成位置
- ✅ 网格顶点计算
- ✅ 导航网格生成
- ✅ 物理碰撞设置
- ✅ 粒子效果位置

**示例**：
```cpp
FVector WorldPosition = FVector(1000.0f, 2000.0f, 3000.0f);  // 世界坐标（米）
```

## 🏗️ 架构分层

### 三层架构模型

```
┌─────────────────────────────────────────────────────────┐
│                     业务逻辑层 (INDEX)                    │
│  - InteractComponent                                     │
│  - StateComponent                                        │
│  - BlockWorldSubsystem                                   │
│  - AreaWorldSubsystem                                    │
│  - HistoryComponent                                      │
│  - 所有工具类                                             │
└────────────────────┬────────────────────────────────────┘
                     │ 转换层
                     ↓
┌─────────────────────────────────────────────────────────┐
│                   显示和几何层 (POSITION)                 │
│  - VisualComponent                                       │
│  - PreviewActor                                          │
│  - Mesh Generation                                       │
│  - Actor Spawning                                        │
└─────────────────────────────────────────────────────────┘
```

### 层级职责

**业务逻辑层**（INDEX）：
- 处理游戏逻辑
- 管理体素状态
- 计算编辑操作
- 存储历史记录

**转换层**（INDEX ↔ POSITION）：
- 只在必要时进行转换
- 使用统一的转换函数
- 明确标注转换点

**显示和几何层**（POSITION）：
- 渲染 UI 预览
- 生成网格
- 放置 Actor
- 物理模拟

## 🔄 转换工具函数

### 标准转换函数

**位置**: `Source/Voxel/Private/Utils/ChunkUtilsFunction.cpp`

```cpp
/**
 * @brief 将体素索引转换为世界坐标
 * @param BlockIndex 体素索引
 * @param BlockLength 体素边长（米）
 * @return 世界坐标（米）
 */
FVector UChunkUtilsFunction::GetPositionByBlockIndex(
    const FIntVector BlockIndex,
    const float BlockLength)
{
    return FVector(
        BlockIndex.X * BlockLength,
        BlockIndex.Y * BlockLength,
        BlockIndex.Z * BlockLength
    );
}

/**
 * @brief 将世界坐标转换为体素索引
 * @param Position 世界坐标（米）
 * @param BlockLength 体素边长（米）
 * @return 体素索引
 */
FIntVector UChunkUtilsFunction::GetBlockIndexByPosition(
    const FVector Position,
    const float BlockLength)
{
    return FIntVector(
        FMath::FloorToInt(Position.X / BlockLength),
        FMath::FloorToInt(Position.Y / BlockLength),
        FMath::FloorToInt(Position.Z / BlockLength)
    );
}
```

### 使用示例

```cpp
// INDEX → POSITION
FIntVector BlockIndex = FIntVector(10, 20, 30);
FVector WorldPos = UChunkUtilsFunction::GetPositionByBlockIndex(
    BlockIndex,
    100.0f  // BlockLength = 100cm
);
// 结果: WorldPos = (1000.0f, 2000.0f, 3000.0f)

// POSITION → INDEX
FVector WorldPos = FVector(1050.0f, 2050.0f, 3050.0f);
FIntVector BlockIndex = UChunkUtilsFunction::GetBlockIndexByPosition(
    WorldPos,
    100.0f
);
// 结果: BlockIndex = (10, 20, 30)  // 向下取整
```

## ❌ 常见错误和修正

### 错误 1: 重复转换导致位置放大

```cpp
// ❌ 错误代码
FVector Position = FVector(Index) * BlockLength;  // 第一次转换
Position = Position * BlockLength;                 // 第二次转换！
// 结果: 位置被放大了 BlockLength 倍

// ✅ 正确代码
FVector Position = FVector(Index) * BlockLength;  // 只转换一次
```

**影响**: 严重错误，会导致位置完全错误

### 错误 2: 在循环中重复转换

```cpp
// ❌ 错误代码
for (const FIntVector& Index : Indexes)
{
    FVector Pos = UChunkUtilsFunction::GetPositionByBlockIndex(Index, BlockLength);
    FIntVector NewIndex = UChunkUtilsFunction::GetBlockIndexByPosition(Pos, BlockLength);
    // 不必要的来回转换
}

// ✅ 正确代码
for (const FIntVector& Index : Indexes)
{
    // 直接使用 Index，无需转换
    ProcessBlock(Index);
}
```

**影响**: 性能损失，虽然不会出错但效率低下

### 错误 3: 函数命名不明确

```cpp
// ❌ 不明确
struct FAreaCoverageFragment
{
    FBox GetBoundingBox() const;  // 返回什么空间？
    FVector GetCenter() const;    // 返回什么空间？
};

// ✅ 明确
struct FAreaCoverageFragment
{
    // 明确标注返回索引空间
    FBox GetBoundingBoxIndex() const
    {
        return FBox(FVector(MinIndex), FVector(MaxIndex));
    }

    FVector GetCenterIndex() const
    {
        return FVector((MinIndex + MaxIndex) * 0.5f);
    }

    // 明确标注需要 BlockLength 参数
    FBox GetBoundingBoxWorld(float BlockLength) const
    {
        const FVector Min = FVector(MinIndex) * BlockLength;
        const FVector Max = FVector(MaxIndex) * BlockLength;
        return FBox(Min, Max);
    }

    FVector GetCenterWorld(float BlockLength) const
    {
        return GetCenterIndex() * BlockLength;
    }
};
```

**影响**: 代码可读性差，容易误用

### 错误 4: 在业务逻辑层使用 POSITION

```cpp
// ❌ 错误：业务逻辑函数使用 POSITION
bool UVoxelAreaWorldSubsystem::IsAreaConflicting(
    const FVector AreaCenter,  // 错误！
    const float AreaRadius)
{
    // 需要转换为 INDEX 才能比较
    // 容易出错，性能差
}

// ✅ 正确：业务逻辑函数使用 INDEX
bool UVoxelAreaWorldSubsystem::IsAreaConflicting(
    const FAreaCoverageFragment& AreaCoverage)
{
    // 直接使用 INDEX 比较
    // 清晰、高效、正确
}
```

**影响**: 代码复杂、性能差、容易出错

## 🔍 审查检查清单

在编写或审查代码时，使用以下检查清单：

### 函数签名检查

- [ ] 业务逻辑函数参数使用 `FIntVector`
- [ ] 显示/渲染函数参数使用 `FVector`
- [ ] 转换函数明确标注需要 `BlockLength` 参数
- [ ] 函数命名明确指出坐标空间

### 转换检查

- [ ] 每个 INDEX 只转换一次为 POSITION
- [ ] 避免在循环中重复转换
- [ ] 避免来回转换（INDEX → POSITION → INDEX）
- [ ] 转换只在边界层（VisualComponent、Actor 生成）

### 数据结构检查

- [ ] 结构体存储使用 `FIntVector`
- [ ] 提供转换方法时明确命名
- [ ] 转换方法需要 `BlockLength` 参数
- [ ] 注释清楚说明坐标空间

### 组件通信检查

- [ ] 组件间传递使用 INDEX
- [ ] 只在 VisualComponent 转换为 POSITION
- [ ] Actor 生成时转换为 POSITION
- [ ] 避免在业务逻辑层转换

## 🚀 性能优化建议

### 1. 避免频繁转换

```cpp
// ❌ 不好：每次都转换
void ProcessManyBlocks(const TArray<FIntVector>& Indexes)
{
    for (const FIntVector& Index : Indexes)
    {
        FVector Pos = ConvertIndexToPosition(Index);
        DoSomething(Pos);
    }
}

// ✅ 好：只在需要时转换
void ProcessManyBlocks(const TArray<FIntVector>& Indexes)
{
    // 在索引空间处理
    for (const FIntVector& Index : Indexes)
    {
        DoSomethingWithIndex(Index);
    }

    // 批量转换用于显示
    TArray<FVector> Positions = ConvertIndexesToPositions(Indexes);
    UpdateDisplay(Positions);
}
```

### 2. 使用整数运算

```cpp
// ❌ 不好：使用浮点运算
float Distance = FMath::Sqrt(
    FMath::Square(Pos1.X - Pos2.X) +
    FMath::Square(Pos1.Y - Pos2.Y) +
    FMath::Square(Pos1.Z - Pos2.Z)
);

// ✅ 好：使用整数运算（如果不需要精确距离）
int32 ManhattanDistance = FMath::Abs(Index1.X - Index2.X) +
                         FMath::Abs(Index1.Y - Index2.Y) +
                         FMath::Abs(Index1.Z - Index2.Z);
```

### 3. 缓存转换结果

```cpp
// ✅ 好：缓存常用的转换
class UVoxelControllerVisualUIComponent
{
private:
    float CachedBlockLength = 0.0f;

    FVector GetCachedPosition(const FIntVector& Index)
    {
        if (CachedBlockLength == 0.0f)
        {
            CachedBlockLength = GetBlockLength();
        }
        return FVector(Index) * CachedBlockLength;
    }
};
```

## 🎨 UI 统一控件规范

> 详见 [UI-统一控件与主题层-决策记录](../05-设计决策记录/UI-统一控件与主题层-决策记录.md) 与 [DESIGN_UMG.md §9](../DESIGN_UMG.md)

1. **新 UI 一律使用统一控件**：文本用 `UVoxelTextBlock`（选 TextRole），滑条用 `UVoxelSlider`，输入框用 `UVoxelEditableTextBox`，下拉用 `UVoxelComboBoxString`；**禁止裸摆引擎原生控件**。
2. **样式只改主题资产**：颜色/素材图片/字体型号集中在 `DA_VoxelUITheme`（`/Game/Resource/UI/CoreUI/Theme/`），禁止在 WBP 里手工逐控件调样式。
3. **特例逃生口**：单个控件确需脱离主题时，将其 `bUseThemeStyle` 置 false（`UVoxelTextBlock` 另有 `SizeOverride`）。
4. **存量 WBP 换装**：把控件替换为 UVoxel* 子类时**保持控件名不变**，C++ BindWidget 无需改动。
5. **统一控件不含业务**：只做样式自应用与事件转发；业务调用仍走 Controller 组件/业务逻辑层（单向数据流铁律不变）。
