# 建造交互链路-数据流审核报告

- 日期：2026-05-07
- 审核范围：`Source/Voxel/Private/Core/UI/Build/`、`Core/UI/HUD/`、`Core/UI/Interaction/`、`Core/UI/ItemLibrary/`、`Core/UI/Tool/` 全部建造相关交互入口
- 基准原则：见 `AGENTS.md → 关键技术模式 → 前端-后端交互数据链路（单向数据流，铁律）`（通用原则：UI 层 → 业务逻辑层 → 数据层 → 广播 → 渲染层；建造域的业务逻辑层 = Controller 组件 + 工具类）

---

## 1. 规范链路（目标形态）

```
UI 控件交互（按钮/滑块/输入框/列表点击）
  → 业务逻辑层：Controller 组件（UVoxelToolComponent / UVoxelSelectionComponent）
       ├─ 参数类业务：直接写 StateComponent（广播）
       └─ 复杂编辑业务：按 CurrentToolTag / 固定域 / ItemTag 路由到工具类
            （Voxel/Editor/Tools/*：UVoxelToolBase 策略子类，经 FVoxelToolContext 访问下游）
  → 修改后端数据（UVoxelBuildStateComponent 状态数据 / World 子系统世界数据）
  → StateComponent 广播（细粒度事件，14 种；Setter 内做「变化才广播」守卫）
  → 订阅方刷新渲染：
      ├─ 3D UI：UVoxelPreviewComponent（PreviewActor/Gizmo/选区框/切面/透明框，绑定 14 个事件）
      └─ 2D UI：BuildPanelWidget 模块 + HUD（BindAllBuildEvents 聚合 8 事件 → HandleBuildModeParamsUpdated）
```

**广播侧核查结论（全部合规）**：

- `UVoxelBuildStateComponent` 所有 Setter 均有「值未变早退」守卫（如 `SetTmpGeometry` L411-416、`SetTemplateRemapEntry` L418-437、`SetEditSliceLayer` L654-665），变化才广播，无广播风暴风险。
- `UVoxelPreviewComponent::BindDelegates`（cpp L155-181）订阅 14 个事件：OnToolChanged / OnGeometryChanged / OnBuildPhaseChanged / OnBrushChanged / OnSelectedFurnitureChanged / OnItemInHandChanged / OnTmpAreaChanged / OnPlacementModeChanged / OnSelectionChanged / OnPreDragChanged / OnSliceChanged / OnCutoutChanged / OnControllerModeChanged / OnCurrentAreaChanged —— 3D UI 侧链路健全。
- `BindAllBuildEvents`（cpp L1018-1036）聚合 8 个事件，2D UI 模块统一订阅后全量刷新（注释明确是 P1 过渡行为，P3 细化——合规）。

### 2.4 严重违规（✗✗ UI 层直接执行世界写操作）

**VoxelTemplateSaveDialog::OnConfirmClicked**（cpp L139-199）：

UI 弹窗内直接完成整套后端业务：
1. 直接取 `VoxelBlockWorldSubsystem` / `VoxelItemWorldSubsystem` / `ConfigDataSubsystem`；
2. 调用 `UVoxelTemplateUtils::CaptureFromSelection` 捕获选区；
3. 调用 `UVoxelTemplateUtils::SaveToTmplFile` 落盘。

这违反了「UI → Controller 组件 → 后端」链路中最核心的一条：UI 层不得操作 World 子系统。应收敛为 `ToolComp->SaveSelectionAsTemplate(const FTemplateMeta& Meta)`（内部委托工具类完成捕获+落盘+历史记录），弹窗只负责收集元信息并调用。

### 2.5 疑似死代码（已修正结论）

**UBoxCoverageModifyWidget**（`Private/Core/UI/Interaction/BoxCoverageModifyWidget.*`）：

- 原结论"全工程零引用可删除"**不成立**：MCP `search_subclasses` 发现存在蓝图子类 `/Game/Resource/UI/BuildModeUI/WBP_BuildCoverageWidget`（父类即 UBoxCoverageModifyWidget），不能删除 C++ 类。
- 处置改为：修复其 `ChangeCurCoreByClick` 的直改 SC（改经 `ToolComp->SetTmpGeometry`）；若后续确认 WBP_BuildCoverageWidget 自身无引用，再连同蓝图一起废弃。

### 2.6 蓝图委托核查（MCP 已核实）

四组 `BlueprintAssignable` 委托的绑定情况（MCP 读取 EventGraph + C++ 全量 grep）：

| 委托 | C++ 绑定 | 蓝图绑定（MCP 读 EventGraph） | 结论 |
|------|---------|------------------------------|------|
| M10 `OnSampleModeChanged` | 无 | WBP_M10 EventGraph 为空 | 悬空广播。`Tool.Sample` 为占位工具，后端无消费者 |
| M11 `OnSelectionModeChanged/OnMaxVoxelCountChanged/OnMaxDepthChanged` | 无 | WBP_M11 EventGraph 为空 | 悬空广播。`Tool.Selection.Magic` 为占位工具 |

## 5. 结论

1. **广播与订阅侧（后端数据 → 3D UI / 2D UI 刷新）架构健全**：SC 所有 Setter 带守卫、PreviewComponent 绑定 14 个事件、BindAllBuildEvents 聚合机制完整，无需改动。
2. **前端写入口约 70% 合规**：18 个 M 系列模块中 13 个完全合规；核心物品/区域/工具链（SetItemInHand、SetAreaType、SwitchTool、SelectArea）全部走 ToolComp。
3. **违规集中在「读-改-写整块几何数据」路径与 HUD 辅助面板**：M4a/M4b/M15 同模块双路径并存，以及高度/切面/图层/透明框/家具选中/模式切换等 HUD 组件的直改 SC。
4. **最严重的是 VoxelTemplateSaveDialog 把整个模板捕获业务做在 UI 层**，必须下沉到 ToolComp。
5. 修复顺序建议：P0 补 `SaveSelectionAsTemplate` → P1 批量补包装方法并替换调用点 → P2 清死代码与访问方式 → P3 蓝图核查。
