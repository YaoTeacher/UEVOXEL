## 1. 原型现状架构

### 1.1 状态模型

原型用**两个变量**表达三个模式：

```
SCENE = 'main' | 'explore'        // 场景
MODE  = 'manage' | 'build'        // main 场景内的子状态
```

- 经营模式 = `SCENE:main + MODE:manage`
- 建造模式 = `SCENE:main + MODE:build`（main 场景内的子状态，**不是平级模式**）
- 探索模式 = `SCENE:explore`（独立场景，时间暂停，常驻回合条）

### 1.2 屏幕分区（1280×700）

| 区域 | 经营 | 建造 | 探索 |
|------|------|------|------|
| 左上 | 520px 经营 Grid（店铺/商圈双 TAB + 主数据 + 功能图标 + 建造入口） | **保留**（按钮变"退出建造"） | 探索功能图标组（技能/道具/队伍/任务/地图） |
| 左中 | — | — | 队伍竖条（top:110px） |
| 左下 | 选中对象卡（区域/角色，bottom:12px） | **保留** | 角色卡（bottom:**156px**） |
| 顶部中央 | — | — | 回合顺序条（常驻） |
| 右上 | 面包屑 + 时间/倍速 + 切面/镜高滑杆 + 圆形小地图 + 图层弹出 | 同左 | 同左（无倍速） |
| 底部 | — | 工具条（480px 居中）+ 资源库（600px，按需）+ 参数面板（260×180 右下）+ 3D 确认浮标 | BG3 式行动条（150px 全宽） |
| 弹层 | 全屏功能页（80%×84%）/ NPC 对话框 / 区域业务弹窗（复用对话框） | 同左 | 同左 |

## 2. 跨模式核心问题（按严重度分级）

### P0-1 模式模型与 C++ 不对齐，且对用户不可见

**现状三方矛盾**：

| 层面 | 模型 | 问题 |
|------|------|------|
| 原型 | SCENE×MODE 两变量，建造是 main 子状态 | 三模式切换入口是**三种不同交互**：进建造靠左上面板按钮、进探索靠点小地图开全屏地图选择器、退出建造靠另一个按钮。模式之间是什么关系，UI 没有任何表达 |
| C++ | `EVoxelControllerMode` 四值平级（Adventure/Manage/Film/SceneBuild，`GameStateEnum.h:57`） | **ManageMode/FilmMode 零实现**；切换只有 `VoxelGameMainPanel::OnModeToggleClicked` 一个 UI 按钮，只做 SceneBuild↔Adventure 二选一，无快捷键 |
| 设计文档 | VoxelEditorModeSubsystem（全局编辑器模式布尔） | 与玩家态 ControllerMode 是两个概念，且**该类在 C++ 中尚不存在**（AGENTS.md 描述已过时） |

**参考**：CK3 的地图模式是顶部一组平级按钮，任何模式一键直达；BG3 的探索↔回合制是无缝自动+手动按钮双向；RimWorld 单场景，"架构师"底栏只是面板开关，从不切场景。三款参考游戏没有一个用"场景×子状态"的隐式模型。

**建议**：
1. 三模式平级化：经营 / 建造 / 探索互为平级，统一切换器（建议右下模式组或顶部 Tab，绑定快捷键如 `Tab` 循环、`B` 建造、`M` 地图/探索）。
2. 建造与经营同场景是正确决策（RimWorld 式），但切换应是对等的模式迁移而非"进入/退出页面"。
3. C++ 对齐：补 ManageMode 实现或重新定义枚举语义；`OnControllerModeChanged` 已有广播，UI 架构文档已有 `UI.Mode.Changed` 频道，链路只差实现。

### P0-2 输入无模式隔离，无快捷键层

- C++ 只有一个 `IMC_VoxelDefault`（13 个 IA），**无按模式切换的输入上下文**；建造点击与探索点击共用 `IA_Select/IA_Release`，靠 `ToolComp` 按 `CurrentToolTag` 内部分发。
- 后果：经营模式下点击世界对象（应开 Inspector）与建造模式下点击体素（应建选区/放置）走同一管道，模式边界靠工具内部 if 维持，随功能增加必然破损。
- 原型中模式切换没有任何快捷键；建造内撤销/重做有 `IA_Edit_Undo/Redo` 但 UI 按钮上不标快捷键（BG3/双点均在按钮角标快捷键）。

**建议**：
1. 输入路由按模式分层：Adventure=交互（拾取/对话）、Build=工具（放置/选区）、Manage=对象选择（点区域/NPC 开卡）。可用 CommonUI 的输入配置或 IMC 优先级实现。
2. 建立全局快捷键表并在 UI 上标注（见 §7.4）。

### P1-1 ESC/关闭层级未定义

原型中可关闭对象有 **6 层**：选中卡 ✕、区域卡 ✕、图层弹出、全屏功能页 ESC、NPC 对话框、建造放置取消、退出建造 ✕——没有任何优先级定义，全部平铺在事件代理里。C++ 侧 ESC 路由只有两级（当前 Screen `HandleEscape()` → 否则暂停菜单，`VoxelPlayerController::OnEscapePressed`）。

BG3 与 RimWorld 的铁律：ESC 逐层关闭，从最上层弹层到最底层 HUD 依次消化。原型的"退出建造"按钮用 ✕ 图标，与"关闭卡片"✕、"重置"✕ 三处同形不同义。

**建议**：定义关闭栈并与 CommonUI 层级对齐（Modal > GameMenu > Game HUD），ESC 逐层消化；退出建造改用「门/箭头」图标（⏏/🚪），重置用 ⟲。

### P1-2 右侧 HUD 跨模式复用，语义冲突

1. **"切面"三名冲突**：工具条"切面"工具组（= C++ `Tool.Cutout` 透明框）、右侧"切面"滑杆（渲染切片高度）、图层弹出里的"切面"开关——三个入口两个功能一个名字。C++ 里 `UVoxelCutoutEditTool`（透明框）与 TopLeftBar 的 Slice 渲染开关确实是两个功能，命名必须解耦（建议：透明框=「剖切框」，渲染切面=「切片」）。
2. **切面/镜高滑杆全模式常驻**：探索战棋遭遇时是纯干扰。BG3 战斗时 HUD 会整体重构。
3. **时间行语义三分**：经营=流动+倍速；探索=暂停（⏸）；建造=注释声明"强制暂停"但 UI 无标识（`.v4-build-paused` 样式定义了却从未启用）。三个模式的"暂停"是三种语义：探索=回合制外时间冻结、建造=经营模拟暂停、经营=可变速流动——需要在 UI 上区分表达。

### P1-3 "选中"语义二元冲突

原型存在**两套选中**：
- `window._sel`：对象选中（角色/区域 → 左下 Inspector 卡）
- 体素选区：建造模式的 Selection（M5 选区信息模块）

建造模式下点击场景区域**仍会弹出区域卡**（`sceneBuild` 里调用 `renderChar`），与体素选区操作在同一屏幕竞争注意力。C++ 侧 `UVoxelSelectionComponent` 只管体素选区，对象选中没有任何 API——两个系统各自为政。

RimWorld 的解法：任意时刻只有一种选中——点建筑=建筑信息卡，框选=底部中央出现选区操作条，二者互斥且视觉容器明确分开。

**建议**：统一为右栏单 Inspector 槽位，两种选中互斥共槽（体素选区 → M5 选区信息 + 选区操作；对象 → 角色/区域卡），视觉用不同边框色区分。

## 3. 建造模式专项（用户核心痛点）

> 现状：底部工具条（480px）+ 库（600px，按需出现）+ 参数面板（260×180px）+ 3D 确认浮标 + 左上经营面板保留 + 左下 Inspector 保留。世界有效视口被四边夹击至约 55%。

### B1【严重】面板优先级倒置：参数 260×180 vs 库 600×160

- 参数面板是**高频操作区**（"几何选择"工具有 3 组模块 + 选区信息，180px 必须滚动），库是**低频浏览区**却占据底部视觉中心 600×160px。
- C++ `UToolDetailPanel` 有 16 个参数模块（M2b1~M16），设计文档的模块布局图按全高侧栏设计，原型压缩进 180px 必然失控。
- 参考：天际线的工具子面板是**向上弹出的窄条**（不遮中央视野）；双点博物馆的物品库是**左侧抽屉**（选完即走）；RimWorld 的 Architect 是底栏菜单，选中工具后参数在左侧栏。

**建议**：
1. 参数面板升为**右栏全高 dock**（约 300px 宽 × 全高），与 Inspector 共槽（见 P1-3）。
2. 库改为底部工具条上方的**可收起抽屉**：默认收起为当前材料一行（当前方块+最近使用），点击/滚动展开为网格；无库工具不占位。
3. 工具条保持底部居中但瘦身：历史组 + 工具图标格 + 当前材料槽。

### B2【严重】工具分组交互不一致

- 5 个组 Tab 中 3 个（采样/区域/切面）**没有子工具**——点"编辑"是展开子工具行，点"采样"是直接选工具。用户要并行维持"Tab=容器"与"Tab=工具"两种心智。
- C++ 实际注册 11 个平铺 ToolTag（`VoxelToolComponent::RegisterTools`），`EVoxelToolCategory` 只是元数据。
- RimWorld Architect 菜单：**分类永远是容器，工具永远是图标格**，无子菜单的分类点开就是一格工具——行为完全一致。

**建议**：组=容器（图标格弹出），工具=图标格 + 快捷键角标 + 名称（当前文字 span 可发现性差）；无兄弟工具的工具直接提升为一级格子，消灭"空容器 Tab"。

### B3【严重】工具→材料路由方向与 C++ 相反

- 原型：`syncLib()` 硬编码"选工具 → 定库 → 库内选材料"，库点击**不切换工具**。
- C++：`UVoxelToolBase::UseItemInHand` 按手持物品 ItemTag **自动路由工具**（Block→单格、BuildItem→家具、Template→模板）——物品驱动，与原型方向相反。
- 两套心智模型并存会导致实现期返工。Minecraft/RimWorld 均为"选材料即定行为"：RimWorld 选墙材料时工具已由菜单项决定，材料是工具的子选项。

**建议**：采用 C++ 方向——**库内点击材料 = 拿在手里**，自动路由到匹配工具并高亮工具条；手动切工具仍然保留（清空手持）。这消除了"先选工具还是先选材料"的死锁。

### B4【严重】区域创建流打断建造

```
区域工具确认 → showAreaBizDialog（复用紫色 NPC 对话容器 v4Dlg，风格与建造 HUD 完全割裂）
            → onok 回调 setMap('main') → SCENE 不变但 MODE 被重置为 'manage'
            → 建造流被打断退出
```

连续创建/调整多个区域时，玩家要反复"进入建造 → 画区域 → 被踢出 → 再进入"。C++ 的 `FAreaModificationData` 两步流程本身支持停留在建造态。

**建议**：
1. 业务弹窗改用独立 Modal 样式（对齐 C++ `ModalStack` 层），不要复用 NPC 对话容器。
2. 确认后**停留建造模式**，弹 Toast「区域已创建」即可。
3. 创建（范围刚画完，弹窗带范围数据）与编辑（从区域卡进入，弹窗带现有数据）统一为一个"区域业务数据" Modal，上下文字段差异化显隐。

### B5【中等】确认/取消体系不完整

- 3D 跟随浮标方向正确（BG3 的确认按钮在游标旁、双点放置确认同），但：
  - 原型无快捷键标注；C++ 两点编辑状态机 `IDLE→PLACING→EDITING` 与 UI 阶段未对齐（注释说 EDIT 阶段显示，但无状态读取）。
  - 历史组"重置 ✕"与浮标"取消 ✕"同形歧义。
- **建议**：浮标标注 `LMB 确认 / RMB 取消`（Enter/Esc 兜底）；EDITING 阶段常显、PLACING 阶段隐藏；重置参数改 ⟲ 图标。LMB 确认/RMB 取消需要 C++ 输入路由支持（见 P0-2）。

### B6【中等】建造模式下经营面板 + Inspector 不收起

- 左上 520px 经营 Grid 在建造模式仅把按钮换成"退出建造"，其余原样保留——建造时玩家的视线焦点在体素与选区，经营数据是纯遮挡。
- 天际线进入工具时无关面板自动让位；BG3 进战斗时探索 HUD 重构。
- **建议**：进建造自动把经营面板折叠为**迷你条**（资金 + 租约警示 + 退出建造），点击可临时展开；左下 Inspector 并入右栏（见 B1/P1-3）。

### B7【中等】历史系统入口不足

- C++ 有 50 条撤销栈 + 1000 条操作日志 + `OperationHistoryItemWidget`，原型只有 ↺↻✕ 三个图标，无历史列表入口。
- 建议：↺↻ 保留单击步进，**长按/右键展开历史下拉**（Photoshop 式）；或右栏加可折叠"历史"组。

### B8【轻度】库与工具硬编码绑定

`syncLib()` switch 硬编码工具→库映射；C++ `UItemLibraryDataSource` 已有统一数据源抽象（`FItemLibraryEntry`，方块/模板/家具/区域类型四个子类源）。

**建议**：库面板统一为一个组件 + 4 个 Tab（方块/模板/家具/区域类型），按当前工具默认选中对应 Tab，而非按工具硬切整个面板的显隐。这直接对齐 C++ 数据源结构。

## 4. 经营模式专项

### M1【严重】左上 520px Grid 信息层级错配

店铺/商圈双 TAB 的身份设计本身好（对应区域树"我的酒店"vs"商业街"两级实体），但**全部信息**（双 TAB + 主数据 + 次数据 + 5~6 功能图标 + 建造入口 + 营业开关）压在左上 520×约 200px，与右上小地图列形成左右夹击。

- CK3：全局数值在**顶部细资源条**，详情全部进窗口化面板；天际线：底部服务条 + 点击后局部信息面板。
- **建议**：
  1. 顶部设常驻资源条（资金/满意度/客流/时间/租约警示），全模式共享。
  2. 左上收缩为**区域身份卡**（招牌图 + 名称 + 营业开关 + 进入建造），店铺/商圈切换保留为卡内 Tab。
  3. 主数据（带 delta 的一行三数值）上移到资源条或保留在身份卡内，只留一份。

### M2【中等】经营数据双源

选中"我的酒店"时，左下区域卡重复显示资金/满意度/人流/收益（左上已有同一组数据），且营业/打烊开关也出现两次（左上 openstat + 左下 area-toggle），状态一致性靠两套 DOM 手工同步。

**建议**：单一数据源原则——左上=当前聚焦区域的经营概览，左下（或右栏）=选中实体的**补充信息**（管理关系/权限/范围/子区域），不重复经营数值。选中当前聚焦区域时两张卡合并。

### M3【中等】功能页一刀切全屏

营业时间/员工/库存等中频操作点开就是 80%×84% 全屏页，打断世界观察。图标无文字（24px 🕐👥📦），可发现性差（CK3/双点均为图标+文字标签）。

**建议** 功能页三级化：
| 级别 | 内容 | 形式 |
|------|------|------|
| 高频 | 营业开关、员工在岗概览 | 内联在身份卡 |
| 中频 | 营业时间、员工排班、库存 | **右侧抽屉半屏**（世界仍可观察） |
| 低频 | 技能树、势力关系图、营业执照 | 全屏页 |

### M4【阻断级】经营数据在 C++ 无模型

原型区域卡字段：资金/满意度/人流量/收益/营业状态/营业时间/员工/库存/租约——`FAreaInstance`（`VoxelAreaBase.h`）**全部没有**，现有字段只有 AreaTypeTag/Coverage/Authority/Owner/ManagerCreatureId/GameplayTags。

这是经营模式能否落地的前提：**需要先设计经营数据模型**（建议独立 `AreaBusinessComponent` 或 `FAreaBusinessData`，挂在区域实例上），UI 原型否则在驱动无源之水。已有的可复用脚手架：物品 `CirculateData`（价值/堆叠）、家具功能 Tag（BarCounter/Bed 等）、NPC 社交属性（TipRate/WorkEfficiency）、`EAcceptabilityEnum`（权限四档，与原型 AUTH_ACCEPT 完全对齐 ✓）。

## 5. 探索模式专项

### E1【严重】自由探索与回合遭遇没有子状态区分

原型一进 `explore` 就常驻回合条（第3回合）+ AP 行动条 + 小地图敌人点——等于**永远处于战斗中**。战棋游戏的常态应是：

| 子状态 | HUD | 参考 |
|--------|-----|------|
| 自由探索 | 即时移动、队伍跟随、无回合条；底部功能条（道具/队伍/地图/任务） | BG3 探索态 |
| 回合遭遇 | 回合条 + AP 行动条 + 掩体/命中预报 | BG3 战斗态 / FE3H |

建议：两子状态自动切换（发现敌人→回合制入场动画+HUD 重构），FE3H 的整章回合制也是一种选项，但需要在原型中明确二选一。

### E2【中等】角色相关 UI 三处分散

左中队伍条（top:110）+ 左下角色卡（bottom:156）+ 底部行动条内当前单位头像——视线呈三角形。BG3 的解法：队伍头像**横排并入底部行动条左侧**，点击切换控制对象；回合顺序顶部横排（DOS2 同款）。另外角色卡底距三模式三个值（156/12/12），同一组件位置跳变。

**建议**：队伍条并入底部行动条（左段），角色卡固定右栏槽位（与其他模式的 Inspector 共槽），回合条保留顶部中央。

### E3【轻度】探索功能入口左上孤岛

技能/道具/队伍/任务/地图五个图标孤立在左上，与底部行动条分离。BG3 这些入口在行动条右端常驻。

**建议**：并入底部行动条右段（结束回合按钮左侧），左上完全释放。

### E4 补充：回合制数据无 C++ 支撑

AP/回合顺序/技能/命中预报在 C++ 均无实现，仅有 `Creature.Body` 部位 Tag 的注释级铺垫（"用于战棋部位打击"）。探索模式的 UI 设计可以先行，但数据模型（回合状态机、AP、技能表）需要列入设计计划。

## 7. 重构方案汇总（v5 原型建议）

### 7.1 全局框架：顶条 + 右槽 + 底带 + 场景中心

```
┌──────────────────────────────────────────────────┐
│ 顶部资源条：资金/满意度/客流/时间·倍速/警示（全模式）   │
├──┬───────────────────────────────────────┬───────┤
│左│                                       │右上小地图│
│上│                                       ├───────┤
│身│          世界视野（最大化）              │右栏槽位 │
│份│                                       │=Inspector│
│卡│                                       │/参数/单位│
│  │                                       │/对象卡  │
├──┴───────────────────────────────────────┴───────┤
│ 底部上下文带：建造=工具带 / 探索=行动条 / 经营=折叠      │
└──────────────────────────────────────────────────┘
```

**三条不变量**（各模式共享，解决"布局跳变"）：
1. 右栏槽位永远在同一位置，内容随模式/选中切换（Inspector 单槽制）。
2. 底部带永远在同一高度，内容随模式切换。
3. 顶部资源条常驻，只换内容不换位置。

### 7.2 模式切换器

- 右下或顶部资源条右端：**经营 | 建造 | 探索** 三按钮组（平级、图标+文字、标注快捷键）。
- 探索涉及场景切换 → 切出前确认未保存状态（CK3 式）；建造↔经营无缝。
- C++ 落地：扩展 `OnModeToggleClicked` 为三态，`UI.Mode.Changed` 消息驱动各 HUD 模块显隐。

### 7.3 选中模型统一

| 模式 | 可选中对象 | 容器 |
|------|-----------|------|
| 经营 | 区域、NPC | 右栏 Inspector |
| 建造 | 体素选区（M5+操作）、NPC（只读卡） | 右栏 Inspector（互斥） |
| 探索 | 单位（友/敌/中立）、掩体/物件 | 右栏 Inspector |

任意时刻全局只有一个选中；ESC 清除选中；点空白清除选中。

### 7.4 快捷键层（原型应标注）

| 键 | 功能 | 参考 |
|----|------|------|
| Tab | 模式循环 | 通用 |
| B | 建造开关 | 双点 |
| Esc | 逐层关闭/取消 | BG3/RimWorld |
| LMB/RMB | 确认/取消放置 | 天际线/双点 |
| Ctrl+Z/Y | 撤销/重做（C++ 已有 IA） | 通用 |
| Space / 1-3 | 时间暂停/倍速 | RimWorld/天际线 |
| Q/E | 工具组循环 | BG3 动作组 |

### 7.5 命名解耦

| 现名 | 改为 | 说明 |
|------|------|------|
| 切面（工具） | 剖切框 | = C++ `Tool.Cutout` 透明框 |
| 切面（右滑杆） | 切片高度 | 渲染切片 |
| 重置 ✕（历史组） | 重置参数 ⟲ | 与取消 ✕ 区分 |
| 退出建造 ✕ | 退出建造 ⏏ | 与关闭卡片 ✕ 区分 |

### 7.6 保留并发扬的现有好设计

- 区域面包屑 + 下属展开 + 双击定位（CK3 式，方向正确；补 hover affordance）
- 3D 确认/取消浮标跟随实体（BG3 游标确认，补快捷键标注）
- 认识度信息模糊化（差异化卖点，FE3H 支援等级式渐进揭示；建议排班页员工同步显示认识度图标）
- 工具模块化 `ShouldShowForTool` 思路（与 C++ 16 模块一一对应，继续沿用）
- 营业/打烊内联在主数据行（高频内联的正确示范）
