## 第一部分：Geometry 操作问题

### G1: 🔴 高 - 缺少 Center 字段

**文件**: `/Source/Voxel/Public/Voxel/Editor/VoxelEditorData.h:27-133`
**架构文档**: `/VoxelDesign/03-架构设计/编辑系统-FVoxelGeometryDesc数据结构-架构设计.md` 第2.2节

**问题描述**:
- 架构设计要求 `Center` 字段为 **Private**，只能通过四种操作方法更新
- 实际代码中**完全缺失** `Center` 字段
- 当前的 `GetCenter()` 方法是计算得出的，不是存储的固定旋转中心

**设计要求**:
```cpp
USTRUCT(BlueprintType)
struct FVoxelGeometryDesc
{
    GENERATED_BODY()

public:
    FAreaCoverageFragment Box;
    FRotator Rotation;
    EBatchShapeType ShapeType;
    int32 Thickness;
    bool bIsRegular;

private:
    FVector Center;  // ❌ 实际代码中缺失

public:
    // 四种操作方法
    void MoveGEO(FIntVector Delta);
    void ModifyCoverage(EAxis::Type Axis, bool bMaxSide, int32 Delta);
    void Recenter();
    void RotateGEO(FRotator DeltaRotation);
};
```

**影响范围**:
- 无法支持固定旋转中心功能
- `ModifyCoverage` 操作时无法保持 Center 不变
- 无法实现 `Recenter` 功能（重置 Center 到旋转后的实际几何中心）
- 违反架构设计的数据一致性规则

**改造建议**:
1. 添加 `FVector Center` 字段（设为 Private）
2. 实现四种操作方法（`MoveGEO`, `ModifyCoverage`, `Recenter`, `RotateGEO`）
3. 更新 `GetCenter()` 返回存储的 Center，而非计算得出
4. 添加 `GetGeometricCenter()` 方法返回基于 Box 计算的几何中心
5. 实现操作影响矩阵的约束检查

### G3: 🔴 高 - 缺少 Geometry 操作回调数据流

**问题描述**:
- 缺少完整的回调数据流：用户拖动 Gizmo → PreviewActor 回调 → VisualUIComponent → InteractComponent → Geometry 更新 → 重新渲染
- Gizmo 拖动无法触发 Geometry 更新

**架构要求的数据流**:
```
用户拖动 Gizmo
    ↓
PreviewActor 内部检测拖动
    ↓
调用对应的 OnXxxGizmoDragged()
    ↓
触发 GeometryOperationCallback
    ↓
VisualUIComponent 接收回调
    ↓
调用 InteractComponent 执行操作
    ↓
调用 Geometry 方法（MoveGEO/RotateGEO/ModifyCoverage/Recenter）
    ↓
StateComponent.Geometry 更新
    ↓
VisualUIComponent 读取新 Geometry
    ↓
调用 PreviewActor 更新渲染
```

**改造建议**:
实现完整的回调数据流

### C3: 🔴 高 - VoxelPlayerController 违反职责分离

**文件**: `/Source/Voxel/VoxelPlayerController.cpp`
**架构文档**: `/VoxelDesign/03-架构设计/编辑系统-Controller-架构设计.md` 第5.1节

**问题描述**:
- Controller 直接包含业务逻辑（权限检查、区域生成等）
- Controller 直接调用 WorldSubsystem（绕过 InteractComponent）
- 缺少 InputHandlerComponent，输入处理逻辑分散

**违规代码示例**:
```cpp
// ❌ Controller 直接处理业务逻辑
void AVoxelPlayerController::GenerateArea()
{
    if(!CheckModificationCost()) return ;  // 权限检查应在 InteractComponent

    // ... 区域状态检查

    // ❌ Controller 直接调用 WorldSubsystem
    AreaWorldSubsystem->GenerateAreaInstance(
        StateComp->GetTmpAreaInfo(),
        StateComp->GetCurrentParentArea(),
        this
    );
}

// ❌ Controller 直接操作 StateComponent
void AVoxelPlayerController::UpdateTmpArea(const FAreaModificationData NewInfo)
{
    StateComp->SetTmpAreaInfo(NewInfo);  // 应该通过 InteractComponent
}
```

**设计要求**:
```cpp
/**
 * Voxel玩家控制器
 *
 * 职责：
 * - 协调各Component
 * - 管理组件生命周期
 * - 提供统一的外部接口
 *
 * 不做：
 * - 不直接处理业务逻辑
 * - 不直接检测输入
 * - 不直接渲染
 */
```

**影响范围**:
- 代码耦合度高
- 违反单一职责原则
- 难以测试和维护
- 组件间边界模糊

**改造建议**:
1. 将权限检查逻辑移至 `InteractComponent`
2. 将 `GenerateArea()` 改为委托给 `InteractComponent` 的方法
3. 移除 Controller 对 WorldSubsystem 的直接调用
4. 实现 `InputHandlerComponent` 统一输入处理
5. Controller 只保留组件协调和高层接口
